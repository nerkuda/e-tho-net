# installer/ — установщик ETN для Windows

`etn.iss` (Inno Setup 6): сервер ETN службой Windows и/или клиент.

## Сборка и payload

```powershell
nvm use 22; npm install
pwsh -File installer/fetch-payload.ps1   # Node, WinSW, сервер, клиент
pwsh -File installer/build.ps1            # release/ETN-Setup-<версия>.exe
```

`fetch-payload.ps1` идемпотентен (кэш `installer/.cache`, SHA-256); dev-клиент
закрыт — иначе EBUSY на `better_sqlite3.node` (грабли `9239db37`); нужны права
на симлинки (грабли `e978947a`).
`build.ps1` не собирает exe из устаревшей поставки; флаги `-RefreshPayload`,
`-CheckPayloadOnly`, `-TestMode`.

Payload: `node\` → `{app}\node\`, `service\` → `{app}\service\` (WinSW 2.12.0 и
шаблон), `server\` → `{app}\server\` (`dist`, `migrations`, `node_modules`),
`client\` → `{app}\` или `{app}\client\`.

## Служба Windows

`service/etn-service.xml` — шаблон WinSW (ADR `db60302a`): подставляет
`{{DATA_DIR}}`, `{{PORT}}`, `{{HOST}}` (остались `{{` — код 10), задаёт
`ETN_DEPLOYMENT=windows-service` (иначе — standalone и отказ обновления из
клиента, ошибка `e375123f`).

Запуск — `node.exe server\dist\index.js`, не `etn` (тот печатает справку и
возвращает 1). Журнал — `{{DATA_DIR}}\logs\service`
(`etn-service.out.log`/`.err.log`); каталог создаёт установщик. Остановка и
запуск — WinSW `stop|status|start`, не `sc`; после `stop` ждём `Stopped`
(60 с).

Регистрация — `ssPostInstall`; готовность подтверждает health-check. Личность
службы до замены файлов: чужой `ImagePath`, `Start=4`, `DeleteFlag=1`,
`NonExistent` при живом ключе — код 20; сбой после копирования — код 10.
`usUninstall`: `stop`, `uninstall`, проверка `status`; отказ отменяет удаление
(`%ProgramData%\ETN\logs\uninstall-*.log`). Чужую службу не трогаем.

## Каталог данных, порт, брандмауэр

- Данные — `%ProgramData%\ETN` (ADR `144bcdb0`): `logs`, `logs\service`,
  `backups`.
- Порт 4321 по умолчанию, задаётся на экране параметров, хранится в
  `install.json` и `ETN_PORT`; при обновлении показывается.
- «Разрешить подключения с других компьютеров» — источник `ETN_HOST`: `0.0.0.0`
  или `127.0.0.1`. Правило `ETN Server` (TCP, `domain,private`) создаётся и
  снимается с флагом и при удалении; ошибка `netsh` установку не отменяет.
- Предпроверки: порт корректен и свободен (IPv4-слушатели; своя служба не
  ошибка, dual-stack ловится bind), путь данных не занят файлом, запись в
  каталоги, ≥300 МБ. Причина — в журнал и `reason_file`, в GUI — сообщением с
  фокусом на поле порта; изменения не выполняются.

## Обновление сервера

Фазы в `ssInstall` до копирования файлов (задача `bb063ac3`):

1. Личность службы — код 20.
2. Остановка до `Stopped` (1061 повторяется, 1062 — не ошибка).
3. Бэкап БД при смене версии; неудача — проверка прежней версии и подсказка,
   сообщение с причиной, объёмом и журналом; код 10.
4. Снимок `…\.install\rollback\<метка>\` (`server`, `service`); только текущего
   запуска.
5. Замена файлов, настройка, регистрация, запуск; сбой — код 10.
6. Health-check: 60 с фактического времени, повтор через 2 с, один
   `GET /api/v1/health` → 200, `status=ok`, `db=ok`, `version` из того же тела;
   `/api/v1/version` не вызывается (требование `0a79d9de`, задача `a1ea1d40`).
   Режим `app` пропускается.
7. Успех — `install.json`, затем удаление снимка.
8. Неудача — откат: служба стоп, `server`/`service` из снимка целиком, БД —
   только из архива этого запуска (`LatestBackupDir` не используется), прежняя
   версия проверяется без версии; не остановилась — файлы и БД не трогаются.
   Итог — в причине, reason-файле и журнале (с указанием потери записей).

Silent-коды: 0 — успех, 20 — предусловие до замены файлов, 10 — сбой.
`MsgBox` нет; журнал `%ProgramData%\ETN\logs\install-*.log`.

## Бэкап и восстановление БД

SQLite-операции — CLI сервера (задача `3acd9c3c`). `db-backup.js` (`etn-db-tool.mjs`) извлекается в `{tmp}`; запуск —
`node.exe`: `backup --to <данные>\backups
--report-out <tmp>\report.txt --data-dir <данные>`, `restore --from <архив>
--force …`.

Архив — `backups\etn-backup-<версия>-<метка>.zip` (сущность `2975c553`):
`_system.db` и `networks\<uuid>\data.db`, без вложений, три последних; Online
Backup API + `integrity_check`, битая — отказ до замены файлов. Откат — только
архив этого запуска; ремонт той же версии, первая установка, adopt
(`686c5d76`) — без бэкапа.

## Клиент

| область | каталог | установка |
|---|---|---|
| «только для меня» (`client_scope=user`) | `%LOCALAPPDATA%\Programs\ETN` | без UAC |
| «для всех» (`client_scope=machine`) | `%ProgramFiles%\ETN` | администратор или `/ALLUSERS` |

Каталог — `ClientInstallPath`; область задают права процесса.
При обновлении `ClientScopeText`: своя копия останется в профиле,
рядом появится машинная. Ярлыки — рабочий стол и «Пуск», их удаляет
деинсталлятор.

Старый клиент 0.14.x (NSIS) удаляется своим деинсталлятором, если
клиент выбран: `/S` и `_?=<каталог>` последним параметром (NSIS 3.2.2),
ожидание исчезновения `Uninstall` до 10 с; иначе установка не начинается.

Запущенный `ETN.exe` в двух каталогах (`ClientCloseRoots`) закрывается мягко
(`taskkill /PID`), ожидание 30 с, затем `/F /PID … /T` и ещё 15 с; не закрылся —
код 20, причина в журнале и reason-файле. В GUI — подтверждение; отказ
возвращает на экран компонентов.

«Запустить клиент» — при успехе и выбранном клиенте, от исходного пользователя
(`ShellExecAsOriginalUser`); `/SERVERONLY` и silent (`/VERYSILENT /SERVERONLY`)
клиент не ставят, коды 0/10/20.

## Экраны установщика

Первый экран — компоненты с приветствием (стандартные приветствие и страница
лицензии отключены): `TNewCheckListBox` с собственной прокруткой и неподвижный нижний
блок. В списке два флажка и серые описания: состояние и действие установщика.
Нижний блок снизу вверх: причина неактивности «Далее» («Далее недоступна: …»,
видна всегда); при первой установке — чекбокс лицензии MIT и ссылка на
`LICENSE`; каталог данных и ссылка на другие варианты сервера. Длинные подписи
переносятся; при маленьком окне прокручивается только список.

Подписи зависят от состояния машины; при обновлении лицензия не запрашивается.
Без компонента или лицензии «Далее» неактивна с причиной. Радиокнопок режима
нет: режим задают права процесса (`PrivilegesRequired=lowest`, без respawn —
ошибка `aa5af30c`). Обычный запуск — клиент «только для меня»; сервер и клиент
«для всех» — от администратора; `/ALLUSERS` — для тихого автообновления службы.

Далее — администратор (логин и отображаемое имя), параметры сервера, первичный
ключ (показывается один раз, копируется). Этапы подписываются в `StatusLabel`
(список — карточка `e3ec6938`); установка идёт одним процессом.

При сбое — экран ошибки: причина, журнал, последняя резервная копия, следующий
шаг, кнопки «Открыть журнал», «Открыть папку данных», «Повторить установку».
Успех — сводка: `http://127.0.0.1:<порт>`, адрес в локальной сети (виртуальные
адаптеры и VPN исключены, помечен «может отличаться»), каталог данных, журнал,
бэкап, напоминание сохранить ключ, кнопки действий; ошибка `netsh` —
предупреждением. Отмена UAC (`/ALLUSERS` без прав) — молчаливый код 2;
install-лог ещё не создан (ограничение `2dd215f7`).

## Тексты интерфейса

UI-строки — только в `[CustomMessages]`: `Etn<Область><Смысл>`, `[A-Za-z0-9_]`,
без точек (точка — языковой префикс Inno), `%n` — перенос, `%1..%9` — `FmtMessage`,
без краевых пробелов, один отрендеренный вариант — одно сообщение. Журнальные
строки (`LogLine`/`LogDefer`/`Log`) остаются литералами в `[Code]`. Сторожа:
ключи определены, дубликатов нет, UI-литералов в `[Code]` нет.

## Тесты

```powershell
pwsh -File installer/tests/silent-codes.ps1   # поведение и коды 0/10/20
pwsh -File installer/tests/init-key.ps1       # etn init и экран ключа
pwsh -File installer/tests/staged-app.ps1     # установка и запуск на payload
```

`silent-codes.ps1` собирает установщик (`build.ps1 -TestMode`) на фикстуре
`tests/fixtures/payload`: обновление, откат, служба, брандмауэр, клиент,
удаление, статические сторожа `etn.iss`. `init-key.ps1` — инициализация,
повторный запуск, сохранение ключа, silent-код 10. `staged-app.ps1` ставит
сборку с настоящим payload в песочницу: раскладка, шаблон,
`GET /api/v1/health`. Тесты — PowerShell 7 (5.1 не поддерживается).
