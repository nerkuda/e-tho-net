# Публикация поставки ETN на GitHub

Полная процедура перенесена в базу знаний и актуализируется там. Возьми её и
выполни шаги:

```
etn.thoughts.search { network_id: "253431e2-780d-466b-879e-6373f73fbad5",
                       query: "Публикация релиза на GitHub", scope: "names" }
```

Затем `etn.comments.get` по найденной мысли (или `subgraph` с комментариями) —
и следуй процедуре. Если база недоступна, опирайся на аварийный минимум из
скилла `etn-kb` и остановись, если не можешь гарантировать корректность шагов.

Ключевые подводные камни (подробно — в базе):

- два remote: `origin` (рабочий) и `github` (публичный); push на github — только явный;
- Node 22 — не менять;
- версию бампить во всех пяти `package.json` + `docs/install-server.md`;
- релиз собирает workflow по тегу `v*`, вручную `gh release create` не вызывать.
