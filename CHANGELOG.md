# Changelog

Все заметные изменения проекта фиксируются здесь. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [0.5.4] — 2026-08-30

Под-версия группы 0.5.0, закрывающая фазу S: слои изменений доступны агенту
(MCP) и пользователю (клиент) с полным паритетом возможностей (S10, S11) и
закреплены сквозным набором тестов (S12).

### Добавлено

- **Слои в MCP — полный доступ агента (S10, 9e0965a, 895588c, 06387c1).**
  Восемь инструментов: `etn.layers.list` / `create` / `update` / `delete`
  (каскад с подтверждением) / `select` / `merge` (полное или частичное, с
  отчётом и отказом по конфликту) / `diff` (структурный) / `diff_doc`
  (текстовый). Сквозная слоистость всех существующих инструментов чтения и
  записи: сессионный слой резолвится пер-ключевым идентификатором
  `mcp:<api_keys.id>` — у каждого ключа своя независимая слой-сессия.
  Эхо слоя `layer: {id, title}` в ответе каждого пишущего инструмента;
  `etn.changes.list` фильтрует события видимостью слоя. Спецификация:
  05-mcp-server §5.2c. Тест полного цикла «создать → писать → изолироваться
  → слить → удалить» только через MCP.
- **Слои в клиенте (S11, e586282, 7975390, 5b4dac8, 814b601).** Меню
  «Основа» в тулбаре (заголовок меню — имя текущего слоя, постоянный
  индикатор); слой — свойство таба (`tabs.layer_id`, миграция клиента 006),
  серверная сессия переключается при активации таба до чтения фокуса.
  Диалоги: создание (с объяснением механики, комментарием и веткой git),
  свойства слоя (переименование/комментарий), удаление (с числом потомков и
  «основа не пострадает»), слияние (отчёт или список конфликтов). Два
  диффа: структурный по связям (added/removed/смена типа/перецепка/порядок,
  REST §5a.7) и текстовый (построчный дифф детерминированных документов,
  плоская сборка до T2). Индикация на холсте: перекрытые мысли — пунктирная
  рамка с бейджем, связи — штриховая линия. Realtime: control-фреймы
  `layer.switched`/`layer.deleted` и событие `layer.merged` дают полный
  ресинк. Спецификация: 03-server-api §5a.7, 07-client-electron §3.6,
  08-ui-spec §1.3/§2.2/§2.4, 09-scenarios L1–L3.
- **Сквозные тесты слоёв (S12, 5f08996).** Изоляция по всем инструментам
  чтения списком (get/query/search/subgraph/neighbors/path); прозрачность
  неперекрытых строк (и «замороженность» перекрытых); переиспользуемый
  тест-инвариант целостности `checkLayerIntegrity` (висячие ссылки по всем
  слоям — гоняется и по боевой базе); перф-смоук на 3000 мыслей при полной
  глубине 4 слоя.

### Исправлено

- **Значения свойств по умолчанию при создании мысли (0d114d2).** Создание
  мысли с типом, чьи свойства объявляют `default_value`, раньше не
  подставляло дефолты ни на карте (Ctrl+Enter), ни через REST, ни через
  MCP. Теперь `createThought` записывает эффективные значения по умолчанию
  (свои + унаследованные по L21) для всех путей создания; нетипизированные
  мысли не затрагиваются.

## [0.5.3] — 2026-08-30

Под-версия группы 0.5.0: слияние слоя с основой (S8 — детекция конфликтов,
резервный слой, замыкание; S14 — семантика связей при слиянии).

### Добавлено

- **Слияние слоя — REST API (S8, 97c359e, 452ddc8, a58b8ed).**
  `POST /networks/{nid}/layers/{id}/merge`: полное или частичное слияние слоя
  в родителя одной транзакцией. Детекция конфликтов — сверка `base_version`
  теневых строк с текущими версиями победителей (любое расхождение → 422 со
  списком `conflicts[]`, без частичного применения); замыкание сливаемого
  множества по ссылкам (концы связей, типы, владельцы комментариев) с
  остаточным случаем: связь на физически отсутствующий конец не создаётся,
  факт в отчёт; резервный служебный слой с прежним состоянием затронутых
  строк — точка отката слияния; реплей в порядке «надгробия → обновления →
  вставки»; логические дубли связей схлопываются по тройке
  (source, target, type); массовое переупорядочивание сворачивается в одну
  позицию `reorder_collapsed`; автоочистка корзины снимает удерживающие
  ссылки; событие `layer.merged`. Спецификация: 03-server-api §5a.6,
  13-layers §8, 04-realtime §4.9.
- **Семантика связей в слоях (S14, f4345f6, 23f91bc).** Смена концов связи в
  рабочем слое — пометка старой на удаление (надгробие) плюс создание новой
  связи с новым `id`, а не обновление тени; при смене `id` эмитятся
  `link.deleted` + `link.created`. UNIQUE-тройка связей стала частичным
  индексом среди живых строк (миграция 029) — надгробие больше не занимает
  тройку (закрыт дефект миграции 025); смена типа/стиля/порядка — обновление
  тени с замороженным `base_version`. Спецификация: 13-layers §6.1, §6.5.

### Исправлено

- **MCP `etn.properties.set`: строковые скаляры в одиночной форме (330b8c5).**
  MCP-хосты (например, ZCode) приводят скалярный union-параметр `value` к
  строке — `value: true` доходит как `"true"` и отвергался доменной
  валидацией. На границе MCP добавлен коэрс по `value_type` определения:
  `bool` — строки `"true"`/`"false"` (без учёта регистра), `number` — строки,
  разбираемые `Number()` в конечное число; текстовые свойства не коэрсятся,
  доменная валидация не менялась. Bulk-форма `values` не затронута.
- **Повторное подключение к серверу восстанавливает сессию (8d7bf3e).**
  Подключение к серверу с сохранёнными настройками восстанавливает табы и
  активную мыслесеть, как при перезапуске клиента, вместо экрана выбора
  мыслесети и лишнего таба; первое подключение без настроек — прежнее
  поведение.
- **Таб недоступной мыслесети блекнеет после восстановления сессии
  (97ab90e).** Разметка доступности табов выполняется после заполнения store
  (гонка с пустым списком исчезла); клик по блеклому табу показывает заглушку
  «Нет доступа к сети» с кнопкой закрытия вместо молчаливого бездействия.

## [0.5.2] — 2026-08-29

Под-версия группы 0.5.0: серверная основа слоёв изменений (S2–S7, S9) — без
клиентского интерфейса и MCP. Слой — «песочница» поверх основы сети: его можно
создать, поработать в нём и удалить; кто не выбирает слой, работает в основе,
поведение не меняется.

### Добавлено

- **Слои изменений — схема БД (S2–S3).** Таблица `layers` и `layer_id` в
  ветвимых таблицах сети (миграции 025–028); разрешение строк по цепочке
  слоёв: временная таблица `layer_chain`, представления `*_v`, пул соединений
  «сеть + слой».
- **Слои изменений — домен (S4–S5).** Слой-осознанная запись; материализация
  теневых строк и надгробий — связь с невидимым концом невидима целиком;
  прикладной каскад удаления надгробиями. Типы и определения свойств в слоях:
  owner-проверки по контексту слоя, теневые upsert-ы значений и оверрайдов,
  детектор «тип существует только в слое».
- **Слои изменений — поиск (S6).** Полнотекстовый поиск и FTS-индекс имён с
  учётом слоёв: rowid-джойн индекса имён, синхронизация синонимов слоя,
  корректный `total_in_group` после дедупликации.
- **Слои изменений — REST API (S7).** Ресурс слоёв: CRUD, выбор активного
  слоя, эхо `meta.layer` / заголовка `X-Etn-Layer`, каскадное удаление с
  cascade-подтверждением; слой клиентской сессии (`session_layers`)
  участвует во всех операциях сети.
- **Слои изменений — realtime (S9).** События WebSocket видны подписчику
  только в его слое; смена слоя — принудительный ресинк клиента.

### Исправлено

- **Миграция БД 025 (bfc268c):** детерминированный `gen_uuid` выдавал один
  UUID на все строки — миграция выполнялась с одинаковыми идентификаторами.
- **Выделение в редакторе комментария (d3c5038):** CodeMirror-редактор
  показывает видимое выделение с акцентным фоном `--selection-bg` вместо
  светло-серых дефолтов baseTheme.

## [0.5.1] — 2026-08-28

Номер 0.5.0 в плане версий зарезервирован за отложенными пост-MVP задачами
(слои изменений и др.) и выходит позже; 0.5.1 — самодостаточная поставка
«корзина до слоёв».

### Добавлено

- **Корзина: двухфазное удаление (S13).** Мысль или связь можно пометить на
  удаление (`marked_for_deletion`) и вернуть из корзины; физическое удаление
  — отдельным действием с блокировками (использование в свойствах
  `thought_ref`, дочерние мысли). Диалоги одиночного и группового удаления с
  построчным выбором «удалить / в корзину», панель «Корзина» с очисткой
  («удалить всё, что возможно»). Пометка видна значком корзины и бледностью
  на холсте, в редакторе (зачёркнутое название), панелях выделения, истории
  и закреплений. Поиск и отбор «Структур» по умолчанию скрывают помеченные
  (опция «показывать удалённые»). REST-эндпоинты корзины
  (`/trash`, `deletion-check`, пакетные операции `trash`/`purge`,
  восстановление) и MCP-инструменты `etn.trash_list`, `etn.trash_purge`,
  `etn.thoughts_deletion_check`, `etn.links_deletion_check`,
  `etn.thoughts_usage_clear`; миграция БД 024.
- **Свойства «ссылка на мысль»: несколько значений (617442f5).** Свойство с
  флагом «несколько значений» хранит список мыслей; в редакторе — чипы, в
  API и MCP значения принимаются массивом.
- **Значения «ссылка на мысль» — мини-облачка.** Заданное значение
  отображается миниатюрой облачка мысли (значок, цвета, начертание),
  крестик убирает мысль из значения, клик по облачку открывает мысль.
- **Диалог «О программе» (4cba7d74):** версия, автор, лицензия, ссылки —
  пункт в меню пользователя.

### Исправлено

- **Вставка текста из другой программы (290a50c0).** Копирование мысли
  зеркалит wiki-ссылки в системный буфер; внутренний снапшот считается
  устаревшим, как только системный буфер перезаписан (в другой программе
  или копией текста внутри ETN) — Ctrl+V вставляет фактическое содержимое
  системного буфера, а не давно скопированные мысли.
- **Ctrl+C при открытой панели выделения (627a0822).** Горячая клавиша
  всегда копирует одну мысль под курсорной рамкой (или в фокусе); панель
  выделения на Ctrl+C не влияет, её копирование — только командой
  «Скопировать мысли».
- **Enter в инлайн-подборе `thought_ref`:** выбирает подсвеченную стрелками
  строку (раньше работал только Ctrl+Enter/клик).
- **Дубли по части слова (1882573e):** фрагменты матчатся по подряд идущим
  словам заголовка/синонима в порядке ввода.
- **«Назначить иконкой мысли» (ac15c84a):** иконка обновляется мгновенно во
  всех представлениях.
- **MCP `direction` (6ad4bbbe):** «parent» подвешивает новую мысль под
  target — семантика как в документации, без инверсии.

## [0.4.4] — 2026-08-27

### Исправлено

- **Вложения при удалённом сервере:** превью, картинки в комментариях,
  «Назначить иконкой» и «Открыть в программе по умолчанию» работают, когда
  сервер удалённый — клиент скачивает серверскую копию файла через новый
  эндпоинт `GET /networks/{nid}/attachments/raw` (раньше файл искался только
  по локальному пути сервера, которого нет на машине клиента). POSIX-пути
  вложений (Linux-сервер) корректно восстанавливаются в etnimg-URL.
- **Буфер обмена:** текстовое копирование (Ctrl+C/Ctrl+X при текстовом
  выделении в редакторе, полях ввода и просмотре) вытесняет ранее
  скопированную мысль из внутреннего буфера — как в системном буфере обмена;
  вставка текста в комментарий больше не дублирует содержимое.

## [0.4.3] — 2026-08-26

### Исправлено

- **Поиск дублей:** частичное совпадение `find_duplicates` считается только по
  целым словам («Диана» больше не совпадает с «обсидиан»); wildcard-синоним
  (`*`) матчится со всем вводом, а не со словом внутри фразы; Enter в диалоге
  добавления создаёт новую мысль, а не подставляет невыбранное точное
  совпадение.
- **Сервер и MCP:** `comment_template_md` типа применяется при создании мысли
  через MCP/REST; `POST /thoughts/query` отвечает `422 VALIDATION_ERROR` на
  неизвестные поля тела; `etn.types.list` получил параметр `scope` для
  раздельного получения каталога связей.
- **Редактор:** высоты списков и свёрнутость групп запоминаются глобально по
  id и переживают перезапуск (`ui_state`); сплиттеры вида «Хроника» тоже
  запоминают максимумы высот панели отбора и таблицы.
- **Текстовое выделение:** видимое выделение в markdown-полях получает
  акцентный фон `--selection-bg`, единый в просмотре и редакторе; Ctrl+C при
  текстовом выделении в просмотре комментария копирует текст, а не мысль.
- **Realtime:** watchdog клиента на простой приёма и форс-реконнект по
  пробуждению ПК/возврату сети — соединение восстанавливается без
  перезапуска приложения.

## [0.4.2] — 2026-08-25

### Исправлено

- **Редактор мысли:** устранено дёрганье при повторном клике на ту же мысль

  падает при `active=any` без других фильтров; инструменты больше не отдают
  агенту `data:`-иконки картинок.

## [0.4.0] — 2026-08-24

### Добавлено

- **Табы в одном окне (фаза Q):** несколько мыслесетей одновременно —
  лента табов с переполнением и drag-n-drop, snapshot состояния таба с
  dirty-маркером, realtime-пул соединений, заглушка для недоступных сетей.
- **Экспорт/импорт `.etnx` (фаза P):** формат переносимости ETNX v1.0,
  zip-экспорт мыслесети через диалог, импорт с флажками «что импортировать»,
  слайсы импорта с realtime-событиями, идемпотентность повторных вставок.
- **Wiki-id ссылки `[[#<id>]]` / `[[n:<сеть>#<id>]]` (фаза R):**
  ID-форма вики-ссылок с резолюцией в имена, атомарный блок имени и
  навигация стрелками в редакторе, кросс-сетевая резолюция, протокол
  `etn://open?…` в Electron, контекстное меню «Обновить формат» для
  legacy-ссылок, две подгруппы в «Упоминаниях» таба «Связи»;
  инструмент `etn.thoughts.backlinks` (REST + MCP).
- **MCP-сервер — пакет для AI-агентов (фаза O):** составная запись
  «единицы знания» `etn.thoughts.upsert_bundle` одной транзакцией;
  мульти-привязки в `etn.comments.upsert` (`targets[]`); карта значений в
  `etn.properties.set`; `etn.types.list` с резолвом типа по имени;
  самоописание сети и контекстная типизация (markdown-поля, узловой тип,
  `structure`); предупреждения о незаполненных required-свойствах;
  аннотации инструментов; per-key переопределение rate-limit записи;
  дельта-фид изменений `etn.changes.list`; метрики чтений

## [0.1.0] — MVP (в разработке)

### Добавлено

- **Сервер (Node.js + Fastify + SQLite):**
  - хранение: одна `_system.db` (пользователи, ключи, реестр сетей, аудит,
    event_log) + отдельный `data.db` на каждую мыслесеть;
  - аутентификация по статическим API-key (`etn_<32hex>`, только SHA-256 хеш);
  - роли: администратор системы / владелец сети / участник (равноправный);
  - REST API `/api/v1`: пользователи и ключи, сети и членство, мысли, связи,
    типы мыслей/связей и свойства, комментарии (постоянные/хронологические),
    вложения, полнотекстовый поиск (FTS5), экспорт markdown/html;
  - real-time через WebSocket: каталог событий, `audience: network|user`,
    resume по `last_seq`, подавление эха, идемпотентность по `Client-Request-Id`;
  - MCP-сервер (stdio + StreamableHTTP): 10 ресурсов `etn://`, 19 инструментов,
    4 prompt-шаблона, лимиты и аудит действий агентов;
  - защита от зацикливания обхода графа (visited-set + path-CTE, лимиты).
- **Десктоп-клиент (Electron):**
  - холст с виртуальной сеткой и фиксированными облачками, фокус-облачко,
    эллипсы-индикаторы, SVG-линии связей;
  - редактор мысли/связи (свойства, markdown-комментарии, вложения, упоминания);
  - поиск с четырьмя группами и фильтрами, диалог добавления с дедупликацией,
    история фокуса в статус-баре (50 мыслей), выделение и групповые операции;
  - админ-панель (пользователи, ключи, сети, аудит);
  - локальное хранилище: профили серверов (safeStorage), UI-state, черновики,
    история фокуса, `client_id`, `last_seq`;
  - применение real-time событий к UI без перезагрузки.
- **Инфраструктура:** npm workspaces (server/client/shared), ESLint + Prettier,
  CI (GitHub Actions), Dockerfile + docker-compose, документация
  (install-server, install-client, admin-guide, user-guide, mcp-clients).

### Известные ограничения MVP

- Онлайн-only клиент (офлайна нет; черновики защищают от потери при обрыве).
- Вложения — ссылки/пути; загрузка файлов на сервер не реализована.
- Экспорт в PDF не реализован (HTML + печать).
- Присутствие пользователей (`presence.*`) не отображается в UI.
- Один серверный процесс; WAL-лок SQLite (2–5 одновременных редакторов на сеть).
