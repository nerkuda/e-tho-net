# ETN — The Endless Thought Network

Бесплатный self-hosted «цифровой мозг»: заметки, идеи, задачи и файлы живут не
в папках, а в виде направленного графа связанных мыслей, который можно
листать, как разум — от общего к частному и обратно. Вдохновлён TheBrain, но
не копирует его, а развивает собственные методики работы с информацией — свой
сервер, свои данные, никаких подписок и облаков.

> ⚠️ **Перед обновлением до 0.8.x — обязательно сделайте резервную копию базы!**
>
> В версии 0.8.1 **связи между мыслями становятся свойствами** — это большое внутреннее изменение, которое затрагивает базу данных. Программа сама перестроит данные при первом запуске, но **отката назад нет**: если что-то пойдёт не так, восстановить базу можно будет только из резервной копии.
>
> **Что нужно сделать перед обновлением:**
>
> 1. Остановите сервер.
> 2. **Скопируйте папку с базами данных целиком** (в каждой сети это файл `data.db`) в безопасное место. Это ваша страховка — без неё обновляться не рекомендуется.
> 3. Обновите сервер и клиент **вместе** — старая версия клиента не совместима с новым сервером, по отдельности они работать не будут.
> 4. Запустите сервер. Он сам применит все изменения к базе. При больших базах это может занять время — следите за логами.
> 5. Откройте свою сеть и убедитесь, что мысли и связи на месте. Если что-то потерялось, проверьте свойства мыслей, отборы и фильтры — возможно, они не учитывают новые настройки по умолчанию. При необходимости восстановите базу из копии и сообщите разработчикам.
>
> **После обновления.** Если вы подключаете к сети AI-агентов через MCP,
> проверьте их инструкции, скиллы и промпты: порядок работы со связями
> изменился. Связь теперь создаётся заполнением свойства (направление задано
> в самом свойстве), отдельного вызова создания связи больше нет, а
> `thought_ref`-свойства переведены в свойства-связи. Устаревшие рецепты
> агентов нужно поправить — иначе они будут обращаться к снятым операциям.
>
> Подробности — в [`docs/install-server.md`](docs/install-server.md) §8 и в `CHANGELOG.md` (раздел 0.8.1).

## Ключевые возможности

- 🧠 **Связи мыслей важней их мест хранения.** Мысль может быть связана с
  любым числом других — вверх и вниз, — поэтому одна и та же идея спокойно
  живёт сразу в нескольких контекстах. Карта фокусирует внимание нв выбранной
  мысли и показывает её окружение: исходящие и входящие связи и родсвтенные 
  мысли.
- 📝 **Внутри мысли — заметка, файлы и история.** К каждой мысли — описание,
  вложения, картинки, свойства и лента датированных записей, которую можно
  использовать как хронику размышлений или отчетов. 
  Все тексты — Markdown, со ссылками на другие мысли и живым предпросмотром. 
  Локальный граф отображает все связи мысли.
- 👁️ **Припоминание без потери контекста.** Зажми Ctrl и наведи курсор: 
  текст, вложения, связи, датированные записи, предки, потомки — показываются
  во всплывающих окошках. Изучай связанные мысли по ссылкам вглубь не меняя 
  фокус.
- 🔍 **Удобный поиск по всему содержимому.** Ищет по названиям, заметкам, 
  датированным записям и связям и наглядно показывает местонахождение каждой 
  найденной фразы. 
  Поиск можно ограничить фильтрами, в том числе иерархией мыслей.
- 🏷️ **Типы для порядка и понимания.** С помощью типов мыслей и свойств для них
  можно описать онтологию — человек, книга, проект, идея. С помощью типов связей
  можно описать семантику: от чего зависит, из чего состоит, где реализуется, 
  чем управляет. 
  Мысли-заметки перестают быть свалкой: в такой базе можно не только получать 
  точные выборки, но и выстраивать логику.
- 🎯 **Живые подборки содержимого.** В типах мыслей можно настраивать отборы
  для просмотра контекстных мыслей независимо от их связей. Например, для типа
  «проект» — «Актуальные задачи», «Завершенные задачи», «Результаты исследований».
  Для типа «книга» — «Места», «Персонажи», «Сцены». И т.д. Кнопки таких подборок 
  появятся на карте при фокусировке на любую мысль настроенного типа. 
- 📖 **Публикации — живые документы из мыслесети.** Разрозненные мысли по любой
  теме легко собрать в связный документ, чтобы поделиться с другими: отбор 
  задаёт, какие мысли станут разделами, из каких связей брать тексты. Читай, 
  изучай, редактируй, добавляй новые мысли прямо в тексте публикации. Экспортируй
  в Markdown/HTML/PDF. 
- 🗂️ **Слои для контролируемых изменений.** Когда требуется изменить множество 
  мыслей и связей с предварительной проверкой, без нанесения вреда текущему 
  состоянию базы, используются слои изменений. Каждый слой перекрывает только 
  измененные элементы, не влияя на основу, из которой он создан. Убедился, что 
  все изменения сделаны правильно — сливай слой в основу. Не понравились изменения
  — удаляй слой бесследно.
- 🗑️ **Ничего случайно не потеряется.** Мысль или связь не удалится, если на ней
  что-то держится. Ненужное можно поместить в корзину и разобраться с ним позже
  — ETN покажет, где используется каждая помеченная на удаление мысль. Вернуть 
  из корзины обратно можно одним движением.
- 👥 **Совместная работа в реальном времени.** Несколько человек и ИИ-агентов 
  правят одну базу одновременно — изменения появляются у всех сразу, в том числе
  и по слоям изменений. Без перезагрузок и принудительных обновлений. И никаких 
  «а у меня старая версия».
- 🔒 **Твои данные — твоя собственность.** ETN живёт там, где решишь: на твоём
  компьютере в домашней сети или на твоём сервере в облаке. Никаких подписок за 
  доступ к своим знаниям. Приложение — под Windows, macOS и Linux, бесплатное, 
  с открытым исходным кодом. Каждая мыслесеть — отдельный файл базы данных 
  плюс файлы вложений.
- 🤖 **ИИ-помощник, который знает твои мысли.** Подключи ассистентов (Claude,
  Opencode, ZCode и другие) через встроенный MCP-сервер — они получат твои 
  знания, смогут искать и ориентироваться в них, дописывать и связывать мысли, 
  понимать и сохранять контекст.

## Статус

Активная разработка функциональности. Планирование работ и контроль за выполнением
перенесены в мыслесеть мейнтейнера; закрытые фазы `docs/workplan/` оставлены для 
истории.

## Спецификации

> **Спецификации в каталоге [`docs/`](docs/) устарели** начиная с версий 
> 0.6 и будут обновлены из мыслесетей мейнтейнера после реализации фичи 
> «Генератор документации».

Начиная с версии 0.6 вся технологическая документация ведется в мыслесети 
мейнтейнера.


## Стек

- **Сервер:** Node.js 20+ (**рекомендуется 22 LTS** — для него у better-sqlite3 есть готовая prebuilt-binary; на Node 24 потребуется Python в PATH для компиляции), TypeScript, Fastify, better-sqlite3, WebSocket.
- **Клиент:** Electron, TypeScript.
- **Хранилище:** SQLite — одна `_system.db` + `networks/<id>/data.db` на сеть.
- **MCP:** `@modelcontextprotocol/sdk`.

## Структура монорепо

```
etn/
├── docs/      # спецификации и план работ
├── server/    # серверное приложение + CLI (etn init)
├── client/    # десктоп-клиент на Electron
├── shared/    # общие типы (DTO, константы, протоколы real-time)
└── package.json
```

## Разработка

```bash
npm install              # установить зависимости всех workspaces
npm run dev:server       # запуск сервера в режиме разработки
npm run dev:client       # запуск клиента
npm run typecheck        # проверка типов во всех workspaces
npm test                 # все тесты
```

## Установка

- **Сервер** — Docker (`docker compose up -d`) или Node.js 22 из исходников;
  подробно — [`docs/install-server.md`](docs/install-server.md).
- **Клиент** — готовые установщики (Windows/macOS/Linux) в
  [релизах](https://github.com/nerkuda/e-tho-net/releases); из исходников —
  [`docs/install-client.md`](docs/install-client.md).
