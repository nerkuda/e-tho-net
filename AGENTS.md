# AGENTS.md — инструкции для агентов проекта ETN

> **TL;DR.** ETN — self-hosted граф мыслей (аналог TheBrain). Спецификации в
> [`docs/`](docs/) — **источник истины** (авторитетнее кода). MVP собран, проект
> в режиме **тестовой эксплуатации и баг-фиксов**. **База знаний** (мыслесеть
> «ETN» на MCP-сервере `etn-remote`) — основной источник инструкций, стандартов,
> граблей и каталога задач. Этот файл — тонкий роутер: минимум, чтобы войти в
> базу и не нарушить критичное, пока база недоступна.

## 0. Режим работы

- **MVP сдан.** Фазы A–K, N, O, Q — `done`; L/M/P/R — `in_progress`. Workplan —
  историческая справка и индекс, а не очередь работ.
- **Входной поток — от пользователя-тестировщика** (сообщает дефекты). Новую
  функциональность «с нуля» не начинать без явной задачи с ID.
- **Node 22 LTS** (`.nvmrc`) — осознанный выбор, менять нельзя. Установка и
  запуск не требуют Python: только Node 22 и `npm install`.

### `etn-remote` vs `etn-dev`

- **`etn-remote`** — боевая база знаний (RAG). Сюда агент читает и пишет в
  рабочем порядке.
- **`etn-dev`** — локальный полигон для отладки самого MCP-сервера. На нём
  тестовые сети «Тест 1» (архивный каталог задач/ошибок) и «ETN» (промо).
  Сюда — только когда чинишь/проверяешь поведение MCP.

## 2. Главные правила

1. **Спецификации в `docs/` — источник истины.** Конфликт кода и спецификации →
   баг кода. Код следует спецификации, но пользователю удобнее иначе → запрос на
   изменение спецификации (`docs:`-коммит). Неоднозначно — подними вопрос.
2. **Не начинай новую функциональность «мимо плана».** Всё крупное получает ID
   (файл фазы + индекс).
3. **Не ломай `done`-области** — читай связанную спецификацию перед правками.
4. **Не коммить runtime/build-артефакты:** `*.db`, `*.db-wal`, `*.db-shm`,
   `etn_data/`, `data/`, `var/`, `.env`, `node_modules/`, `dist/`, `out/`,
   `build/`, `release/`.
5. **Читай документацию «лениво»:** `docs/workplan.md` — индекс; детали задач —
   в `docs/workplan/phase-*.md`. Открывай только файлы нужных фаз.

## 3. Структура репозитория

```
etn/
├── docs/        # спецификации (01..12) + workplan (индекс) + workplan/ (фазы) + руководства
├── server/      # @etn/server  — Fastify + better-sqlite3 + WebSocket + MCP
│   ├── src/  migrations/{system,network}/
│   └── dist/    # сборка — НЕ коммитить
├── client/      # @etn/client  — Electron + electron-vite (vanilla TS, без React)
│   ├── src/{main,preload,renderer}/  scripts/rebuild-native.mjs
│   └── out/     # сборка — НЕ коммитить
├── shared/      # @etn/shared  — общие типы, DTO, константы, коды ошибок
├── markdown/    # @etn/markdown — ЕДИНЫЙ markdown→HTML рендерер (менять только здесь)
├── .nvmrc       # Node 22 LTS
└── package.json # npm workspaces: shared, markdown, server, client
```

Карта «где что искать» по темам баг-фиксов — в базе, раздел «Кодовая база».

## 4. Команды (обязательны перед коммитом)

```bash
nvm use 22                              # Node 22 (nvm-windows)
npm install                             # после checkout / смены ветки
npm -w @etn/client run rebuild:native   # один раз после install

npm run dev:server                      # сервер (tsx watch)
npm run dev:client                      # Electron-клиент (electron-vite)

npm run typecheck                       # типы всех workspace
npm -w @etn/server test                 # серверные тесты
npm -w @etn/client test                 # клиентские тесты
npm run build                           # сборка всех workspace
```

Если `typecheck` или затронутые тесты красные — чинить до коммита. Сервер и
клиент можно запускать одновременно.

## 5. Коммиты

- **Баг-фикс:** `fix(<scope>): <summary>`.
- **Задача workplan:** `[<TASK_ID>] <type>(<scope>): <summary>`.
- **Правка спецификации:** отдельный `docs(<area>): ...`, не смешивать с кодом.
- Один коммит = одна правка. Деструктивные операции (удаление, `git push
  --force`) — только после подтверждения пользователя.

## 6. Чек-лист перед коммитом

- [ ] TS strict, без `any` без причины.
- [ ] `npm run typecheck` зелёный; затронутые тесты зелёные.
- [ ] Спецификация соблюдена (или правка — отдельным коммитом).
- [ ] Правильный префикс коммита.
- [ ] Runtime/build-артефакты не закоммичены.
- [ ] Результат зафиксирован в базе (инструкция «Отчитаться о выполненной работе»).

## 7. Аварийный минимум (если база недоступна)

Если `etn-remote` недоступен — не заводи новые сущности вслепую и не «вспоминай»
инструкции по памяти. Минимум, который нельзя нарушать:

- **Node 22 LTS** — не менять.
- **`better-sqlite3` — две несовместимые версии** (`server` 11.1.2 / `client`
  11.10.0): не выравнивать, не ставить `^`, после `npm install` —
  `npm -w @etn/client run rebuild:native`.
- **Спецификации `docs/` — истина**; код, расходящийся со спекой, — баг кода.

Полный свод стандартов, ADR и граблей — в базе (когда станет доступна).
