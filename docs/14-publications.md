# 14-publications — подсистема публикаций

**Автор:** Проект ETN

Подсистема публикаций: живые документы из мыслесети — рецепты, полки, экспорт, пересборка, слои.

<a id="pub-6642d7d6"></a>

## GET /publications/{id}/print — печатный HTML для экспорта в PDF

**Назначение.** Печатное представление публикации для экспорта в PDF: самодостаточный HTML документа (единый рендер с HTML-экспортом, `renderHtmlDocument`), картинки-вложения встроены как data-URI, водяной знак «Документ сгенерирован в ETN» на каждой странице. PDF собирает КЛИЕНТ — скрытое окно Electron (`webContents.printToPDF`); сервер печатать не умеет и PDF не формирует (0.11.2, задача 178f4921).

**Запрос.** `GET /networks/{nid}/publications/{id}/print`, права — участник сети. Тело ответа — `text/html; charset=utf-8`; заголовок `x-publication-slug` несёт детерминированный slug публикации (клиент предлагает имя файла `<slug>.pdf`). Форма ответа на клиенте — общий тип `PublicationPrint` (`@etn/shared`).

**Ошибки.** `NOT_FOUND` — публикации нет.

**Отличия от ZIP-экспорта.** ZIP (`POST …/export`) кладёт ассеты рядом в `assets/`; печатный HTML встраивает их инлайн, чтобы печать не зависела от схемы `etnimg` и файлов на диске. Водяной знак есть только в печатном представлении.

**Детерминизм.** Не требуется: PDF не байт-стабилен (метаданные и подмножество шрифтов Chromium) — см. ADR клиентской печати.

<a id="pub-f49c6420"></a>

## GET /thoughts/{fid}/publications — использование мысли

Членство мысли в публикациях текущего слоя: по рецептам (роль: раздел — с именами родительских разделов; текст) и по прямым значениям свойств типа «Публикация». Ленивый вызов (при разворачивании группы «Публикации» в «Упоминаниях»), лимит публикаций и серверный кеш с дебаунсом. Клиент семантику отбора не реплицирует.

Элементы с ролями `section`/`text` дополнительно несут `anchor` (детерминированный якорь вхождения — совпадает с `domId` первого вхождения в документе) и `page` (номер страницы корневых разделов сборки, 20 на страницу) — для открытия рабочей области сразу на разделе (0.11.1, задача 3275fd8d). Роль `direct` этих полей не имеет (раздела нет — открывается верх документа).

## POST /publications/{id}/export и GET /jobs/{id} — экспорт публикации

Инфраструктура джоб — по прецеденту существующего экспорта подграфа (`POST /export` + `GET /jobs/{id}`). Тело: `{ format: "md"|"html" }`, `with_assets` (default true). Сборка — тем же кодом, что `/assembly`, в контексте текущего слоя; исключённые не попадают.

**Markdown**: файл `<slug>.md` (slug названия, транслит; детерминированный) + каталог `assets/` с картинками-вложениями, доступными серверу; `src` картинок переписаны на относительные пути. **HTML**: единый самодостаточный файл (титул, оглавление, стили), ассеты — рядом в `assets/` при `with_assets`.

Оба формата — zip-артефакт джобы. Ссылки: на публикации и на мысли вне документа — названием текстом; на мысли внутри — якоря `#pub-<shortid>`. Недоступные вложения — списком в `warnings` отчёта джобы. Детерминизм: повторный экспорт без изменений в базе — байтово идентичный zip (пиннинг версии markdown-рендерера; временные метки файлов в zip фиксированы).

**PDF (0.11.2, задача 178f4921).** Формат PDF из экспортного меню публикации — КЛИЕНТСКИЙ: сервер его не собирает, `md|html`-zip остаётся как есть. Клиент запрашивает печатное представление `GET /publications/{id}/print` (тот же самодостаточный HTML `renderHtmlDocument`, картинки встроены как data-URI, есть водяной знак) и печатает его скрытым окном Electron (`webContents.printToPDF`); сохранение — диалогом клиента, имя файла `<slug>.pdf`. Внутренние якоря `#pub-<shortid>` в PDF проставляет сам Chromium (аннотации `/Subtype /Link` + `/Dest`) — постобработка не нужна. Решение и статус относительно детерминизма — ADR «Экспорт публикации в PDF: клиентская печать».

## publications — публикации

Ветвимая таблица сети. Одна строка — одна публикация.

| Столбец | Тип | Описание |
|---|---|---|
| `id` | TEXT PK | UUID v4 |
| `layer_id` | TEXT NOT NULL | слой строки (ветвимость) |
| `title` | TEXT NOT NULL | название (заголовок титула, H1) |
| `subtitle` | TEXT | подзаголовок титула; NULL — нет |
| `summary_md` | TEXT | резюме, markdown без заголовков (заголовки запрещены валидацией) |
| `authorship` | TEXT | авторство текстом; NULL — показывается создатель (`created_by`) |
| `cover_attachment_id` | TEXT | строка-вложение-обложка (общий файл с вложением мысли) |
| `cover_url` | TEXT | обложка внешним URL; взаимоисключимо с `cover_attachment_id` |
| `assembly_date` | TEXT (ISO date) | хранимая дата сборки; NULL — не собрана; обновляется только явным действием rebuild |
| `title_recipe` | TEXT (JSON) | рецепт заголовков: условия отбора в формате панели отбора «Структур мыслей» |
| `text_sources` | TEXT (JSON) | рецепт текстов: упорядоченный массив id свойств-связей; `[]` — пустой рецепт (текст = предисловие) |
| `extra_properties` | TEXT (JSON) | id свойств блока «дополнительные материалы»; пересечение с `text_sources` — VALIDATION_ERROR |
| `numbering_from` / `numbering_to` | INTEGER | диапазон уровней нумерации разделов; NULL — без нумерации |
| `active` | INTEGER NOT NULL | признак актуальности |
| `marked_for_deletion_*` | — | корзина (кто/когда), по образцу мыслей |
| `version`, `created_by`, `created_at`, `updated_by`, `updated_at` | — | стандартные служебные |

Ограничения: ровно один источник обложки (вложение ИЛИ URL, оба NULL — допустимо: заглушка «цвет + инициалы»); `cover_attachment_id` ссылается на строку вложения с `owner_type='publication'` и этим же id публикации.

## Real-time события публикаций

Каталог событий (REALTIME_EVENT_TYPES расширяется; карта видимости слоёв — прямое расширение switch по прецеденту):

| Событие | Когда |
|---|---|
| `publication.updated` | правка настроек/титула |
| `publication.order.reordered` | батч перестановок — ОДНО событие (по прецеденту thought.reordered) |
| `publication.exclusions.changed` | исключить/вернуть |
| `publication.rebuilt` | пересборка (дата сборки) |
| `publication.trashed` / `.restored` / `.purged` | корзина/удаление |
| `shelf.updated` / `.deleted` | полки и состав |

Гранулярность: одно действие = одно событие (не по узлу). Изменение мысли-исходника НЕ даёт события публикации — документ в чтении перерисовывается по событиям самой мысли. Живость чтения обеспечивается существующими событиями мыслей/комментариев.

## Ветвимость таблиц публикаций и свёртка порядка в слиянии

1. `publications`, `publication_order`, `publication_exclusions`, `shelves`, `shelf_items` — ветвимые таблицы: вносятся в закрытый реестр ветвимых таблиц (layer-chain), чтения только через `*_v`, теневые строки/надгробия — по общим правилам; правка спеки слоёв — частью той же задачи.
2. Свёртка перестановок: массовые правки только `position` в `publication_order` сворачиваются в одну позицию отчёта слияния (reorder_collapsed) — расширение существующего таблично-управляемого механизма свёртки (по прецеденту `links.position`).
3. Диффы слоёв (layers.diff / diff_doc): публикации и их настройки видны в текстовом диффе как отдельные сущности.
4. Персональные настройки вида и джоб-артефакты экспорта — НЕ ветвятся (не сетевые данные).

<a id="pub-71c2d194"></a>

## Владелец-вложение «публикация»: строка-копия с общим файлом

1. `owner_type` вложений расширяется значением `publication` (ATTACHMENT_OWNER_TYPES); модель «один владелец на строку» не меняется.
2. Обложка из существующего вложения: создаётся НОВАЯ строка вложения (новый id) с тем же физическим файлом — по механике существующего копирования вложений (`copyAttachmentsToTargets`); у исходной мысли своя строка остаётся.
3. Полное удаление публикации: её строки-вложения удаляются; физический файл — сборкой мусора (`storedFileInUse`), когда на него не осталось строк ни в одном слое.
4. Обратная операция (отдать обложку публикации мысли) — тем же механизмом копирования.

## Детерминизм экспортных zip: фиксированные метки и пиннинг рендерера

**Контекст.** Требование — байтово идентичный повторный экспорт; zip по умолчанию пишет текущие mtime и свой порядок.

**Решение.** Все записи zip (md/html/assets) создаются с фиксированной датой (константа, не время сборки), детерминированными именами (slug + суффикс -<shortid> при коллизии; имена ассетов — от стабильного id/хеша содержимого) и стабильным порядком добавления (сортировка). Содержимое файлов пиннится версией markdown-рендерера (MD_RENDER_VERSION инкрементируется с изменениями рендера).

**Почему.** git-дифф пересборок — главный сценарий публикации спек в репозиторий; плавающие метки превращают дифф в шум.

**Следствия.** Байты zip не зависят от времени; CLI-пересборка не меняет файлы без изменений в базе. **Запрет:** не записывать в артефакты время сборки (дата сборки публикации — хранимое поле, попадает в титул по решению техпроекта).

## Карточка публикации в панели редактора

Третий вид цели панели редактора — рядом с карточкой мысли и редактором связи (актуализировано 0.11.1, задачи b02ef1cf и d1a56d76; волна 2 — стороны свойств). Открывается: одиночным кликом по публикации в библиотеке/тулбаре просмотра, кнопкой-шестерёнкой в шапке рабочей области.

**Шапка карточки** — на каркасе панели мысли (3 строки): обложка+заголовок+шестерёнка настроек; подзаголовок; признак «актуально» + «Действия». Вкладки:

- **Резюме** — markdown-редактор (вставка заголовков запрещена), применение Ctrl+Enter, режим просмотра;
- **Рецепт** — три крупные группы с подсказками (как панель отбора «Структур»): отбор заголовков (переиспользуемый конструктор `lib/filter-builder`, включая «Родительские мысли»), свойства текстов (мульти-выбор из справочника; КАЖДАЯ сторона свойства-связи — отдельная строка с направлением, как поле «Свойство связи» entity-picker; порядок перетаскиванием, пересечение подсвечивается), доп. материалы (те же стороны); нумерация: диапазон уровней — нумерация начинается с 1 на заданном уровне, уровни выше — без номеров;
- **Вложения** — общий конструктор панели вложений любого владельца (`buildAttachmentsPane`), облачка владельцев с крестиками (подтверждение удаления последнего владельца), «Сделать обложкой публикации»;
- **Метаданные** — название, подзаголовок, автор, обложка (превью), дата сборки (readonly, меняется «Пересобрать»).

**Шестерёнка настроек**: полки — список живых полок с чек-боксами (отметил — публикация на полке, снял — исчезла), автор.

**Диалог обложки** — универсальный каркас выбора ресурса `editor/resource-picker.ts` (ADR a2cc7e9e): вкладки «Вложения» (список через компонент списка + nav-core, облачка владельцев, препросмотр со сплиттером, «Загрузить из файла») и «URL»; кнопки «Отмена» / «Без обложки» / «Применить и закрыть».

Изменения применяются к документу и библиотеке сразу (реактивный слой: точечные патчи без полной перечитки). Карточка обновляется при переключении публикаций в существующем DOM (без пересоздания — как карточка мысли). Встраивание: расширение `EditorTarget` третьим вариантом с подавлением канвас-специфичных механик (история посещений, halo, выделение) — решение в ADR.

## Карточка публикации — третий вариант EditorTarget панели редактора

**Контекст.** Панель редактора знает два типа цели (EditorTarget: мысль, связь) и связана с канвом (выделение, история, halo). Карту публикации можно встроить третьим вариантом или отдельным хостом рядом.

**Решение.** Расширить `EditorTarget` третьим вариантом `publication`; карточку — отдельным модулем (не наращивать монолит editor.ts): `editor/publication-card.ts` с собственным набором вкладок. Канв-специфичные механики (выделение на холсте, halo, история посещений) для цели publication отключаются guarded-ветками по типу цели.

**Почему.** Пользовательский принцип «выбрал сущность — правь в панели редактора» требует того же места; отдельный хост создал бы вторую панель и расколол единообразие. Изоляция в модуль сужает риск монолита; вкладки и фасады lib/ui переиспользуются.

**Следствия.** EditorTarget — union из трёх; тесты панели пополняются кейсом publication; сторож на использование карточки только через общую панель. **Запрет:** не создавать отдельную плавающую панель для карточки публикации.

<a id="pub-73cfcf64"></a>

## Обложка публикации — строка-вложение с общим файлом

**Контекст.** У вложения один владелец на строку. Обложку можно взять «дополнительной привязкой» (требует миграции на multi-owner), копией строки с тем же файлом, или отказом от переиспользования.

**Решение.** `owner_type` расширяется значением `publication`; выбор существующего вложения любой мысли создаёт НОВУЮ строку-вложение публикации с тем же физическим файлом (готовая механика копирования вложений).

**Почему.** Модель вложений не трогается — нет миграции и риска регрессий во всём, что связано с вложениями; файл не дублируется на диске; «другие ссылки на файл» считаются по строкам — готовая сборка мусора (`storedFileInUse`).

**Следствия.** У обложки свой id строки (не виден пользователю); удаление публикации не трогает исходную строку мысли. **Запрет:** не вводить таблицу привязок владелец↔вложение (multi-owner) ради обложек.

## Открытая публикация — рабочая область чтения и правки

Состояние экрана «Публикации» при открытой публикации (актуализировано 0.11.1, задачи b02ef1cf/d13fd645/ea1b5f14 и волны приёмки 1–7). Фон рабочей области следует активному слою (`--layer-bg`), фокус-выделения — слой-токенам, как на «Структурах» и в «Дневнике». Три зоны:

**Шапка** (прилипающая) — единая кликабельная КАРТОЧКА публикации: мини-обложка/заглушка, название, подзаголовок, автор/дата сборки; hover-подсветка; клик в любом месте карточки открывает карточку публикации в панели редактора. Кнопки-значки справа вне карточки: «Пересобрать» (rebuild; подсвечивается при устаревании документа — stale после изменения рецепта/вхождения, любая пересборка, в т.ч. внешняя, гасит подсветку), «Экспорт» (формат → джоба; по завершении — тост об успехе с путём сохранения или об ошибке с причиной; отмена — без уведомления), «Назад» (в библиотеку; Esc документ НЕ закрывает). Над рядом кнопок — ползунок ширины текста 50–100% (персональная настройка, тултип «NN%», применяется при открытии публикаций; на 100% от краёв минимум ~20px).

**Оглавление слева** (сворачиваемое): ТОЛЬКО мысли-заголовки разделов; счётчик повторов прокручивается по текстам, якоря совпадают с документом. Пометки: исключён (перечёркнут), повтор (переход к первому вхождению), обрез кольца. Клик по разделу — прокрутка к разделу И назначение текущим (программная прокрутка блокирует scroll-подсветку); при прокрутке документа текущий раздел подсвечивается в обе стороны. Ручной порядок: ручка ⠿ (тултипы), drag&drop мышью, Alt+↑/↓ для выбранной строки; сохранение PUT order; семантика «соседи одного родителя»; узел без ручной позиции держит сетевое место (фасад drag-list, ADR 442e7ff5).

**Документ в центре**: титульный лист — ВИРТУАЛЬНЫЙ ЛИСТ в портретной ориентации (высота = ширина×√2, aspect-ratio 1/1.414, всегда полной высоты; ширина — колонка ползунка). ОБЛОЖКА — фон листа: сверху, по центру, во всю ширину, пропорции сохранены (может покрывать весь лист или только верх — обложка и текст независимые слои, текст всегда поверх). Поверх — ДВЕ РАВНЫЕ вертикальные половины: заголовок в верхней (гор. центр, верт. — к нижнему краю половины; крупный кегль с контурной обводкой поверх обложки; не влезает — уменьшение шрифта фиттингом, в нижнюю половину не заходит), подзаголовок — в нижней (гор. и верт. центр; с обводкой; тот же фиттинг). Автор и дата сборки — в самом низу нижней половины, справа, с отступами от краёв, с обводкой; без обложки тексты обычные. Заголовки разделов ВСЕ выровнены по левому краю (треугольник свёртки и ручка — в жёлобе слева, текст не сдвигают), уровни различаются ШРИФТОМ (размер/насыщенность), не сдвигом. Нумерация: при диапазоне уровней N–M нумерация начинается с 1 на уровне N (уровни выше N — без номеров; N-й уровень — «1», «2»…, вложенные — «1.1»). Блочные отступы документа — единые с рендером комментария (comment-view); в оглавлении отступов нет. Мысли-тексты отображаются ВСЕГДА, включая пустые (пустой комментарий → видимый пустой блок высотой строки: выделяется, редактируется, перемещается, исключается). Пустой отбор (рецепт null или без условий) — документ НЕ рендерится: пустое состояние с подсказкой «В рецепте не задано ни одного условия…».

**Выделение мыслей в тексте** (двухрамочность, ADR e6d48e09): текущая — пунктирная рамка; открытая в редакторе (цель редактора, иначе фокус) — сплошная с двойной обводкой (--focus-ring-contrast); при совпадении — только сплошная; клик по разделу/тексту в документе — полный выбор.

**Управление блоками.** Ручки ⠿ + drag&drop (единый механизм с оглавлением); клавиатурный сдвиг Alt+↑/↓ и Ctrl+Shift+↑/↓. Контекстное меню блока — общие команды облачка мысли + подменю «В публикации»: «Сдвинуть вверх/вниз» (PUT order), «Переместить в раздел…» (дерево разделов; исключён сам блок и его поддерево — циклы невозможны), «Добавить раздел на этом уровне…» и «Добавить подчинённый раздел…» (РАЗДЕЛЬНЫЕ пункты, родитель заполняется автоматически по команде; поиск/создание мысли с предзаполнением под отбор, при невозможности — в «Родительскую мысль»; проверка вхождения с предупреждением), «Добавить текст раздела…» (в первое свойство-источник текстов блока; существующие значения сохраняются), «Исключить из публикации»/«Включить» (exclusions валидируют принадлежность), «Открыть мысль в редакторе». Общего подменю «Добавить» (мысли «вообще») на этом экране нет. Двойной клик по тексту — открыть мысль в редакторе, АКТИВИРОВАТЬ вкладку «Комментарий» (в любом текущем состоянии редактора: другая вкладка, карточка публикации, другая мысль), включить режим правки, курсор в месте клика (если точный офсет недостижим — начало абзаца; не падать).

Списки выбора свойств рецепта (тексты, доп. материалы) показывают СТОРОНЫ свойств-связей (как поле «Свойство связи» entity-picker). Выделение заголовка/текста — мысль в карточке мысли панели редактора; правки отражаются живьём через реактивный слой. Создание раздела/текста: предзаполнение из рецепта, проверка вхождения, при промахе — предупреждение. Прелоадеры на загрузку документа и страниц.

## Публикации: поузловые таблицы вместо JSON-хранения порядка

**Контекст.** Порядок и исключения публикации можно хранить JSON-полем строки publications (дёшево) или отдельными таблицами (дороже, но поузлово).

**Решение.** Отдельные ветвимые таблицы: `publication_order` (ключ узла — id ребра вхождения; для корневых разделов — id мысли; позиция) и `publication_exclusions` (по thought_id — исключение действует на все вхождения мысли). Рецепты/титул — JSON-поля строки publications (атомарная правка настроек). Срез принятых узлов `accepted_ids` (0.11.1, временная семантика кандидатов — задача e754527d) — тоже JSON-поле строки: это множество принятых id, как рецепты, а не позиция/исключение — запрет ниже не нарушает. Осознанное следствие: слияние слоёв по `accepted_ids` идёт с гранулярностью строки (last-write-wins) — если два слоя приняли разных кандидатов, победит один срез целиком; поузловая гранулярность не требуется, т.к. непринятый кандидат — это лишь плашка-подсказка, а не данные документа.

**Почему.** Слияние слоёв и real-time обязаны работать поузлово: правка порядка одного раздела не должна конфликтовать с правкой другого; свёртка пачек перестановок (reorder_collapsed) работает на строках — JSON-блоб сделал бы её невозможной, а любое переупорядочивание — перезаписью всей строки. Исключение — по мысли: пользовательское намерение «этой мысли тут нет» не зависит от места вхождения.

**Следствия.** Три ветвимые таблицы вместо одной; merge-свёртка расширяется на новую таблицу (таблично-управляемый механизм). **Запрет:** не хранить позиции и исключения в JSON-полях publications.

## Ссылка на публикацию в текстах ([[#pub:id]])

В редакторе комментария и в рендере: вставка ссылки на публикацию (меню вставки ссылки → пикер публикаций → `[[#pub:<uuid>|<название>]]`), подсветка и цельное выделение — как у ссылок на мысли, клик — переход на экран «Публикации» с открытием публикации (deep-link `?publication=`). Удалённая публикация — пометка «удалена», как у удалённых мыслей. Серверная часть (резолвер, скан упоминаний) — в требованиях.

<a id="pub-7f583ef9"></a>

## Ссылки на публикации [[#pub:<uuid>]] — серверная механика

1. Синтаксис — префиксная форма `[[#pub:<uuid>]]` (и с подписью `[[#pub:<uuid>|Название]]`); «голый» uuid в `[[#…]]` — как сегодня, только мысли.
2. Резолверы: клиентский wiki-резолвер и серверная подстановка названий распознают префикс; разрешение — по публикациям текущего слоя.
3. Скан упоминаний (backlinks) находит `[[#pub:]]` в комментариях мыслей/связей и отдаёт их отдельной группой публикаций (для карточки публикации — «кто ссылается»).
4. Удалённая/не найденная публикация — пометка «удалена» (как у мыслей), не ошибка рендера.
5. Deep-link `?publication=<id>` открывает экран публикаций; резолв в слоях — как у ссылок на мысли.

<a id="pub-7168009e"></a>

## Ссылки на публикации: явный префикс [[#pub:]] вместо автопоиска

**Контекст.** id публикации и мысли — оба UUID: в `[[#<uuid>]]` неразличимы. Варианты: автопоиск (сначала мысль, потом публикация) или явный префикс.

**Решение.** Явный префикс: `[[#pub:<uuid>]]` — по образцу кросс-сетевого префикса `n:`. Голый `[[#<uuid>]]` остаётся только мыслью.

**Почему.** Автопоиск делает ссылку двусмысленной при (теоретической) коллизии id и требует двойной lookup на каждый рендер; префикс даёт однозначный резолв без поиска, дешёвый парсинг и деградацию «не найдено» без ошибок типа.

**Следствия.** Резолвер, скан упоминаний и deep-link расширяются распознаванием префикса; вставка из UI всегда пишет префиксную форму — пользователь его не печатает. **Запрет:** не заводить автопоиск публикаций по голому uuid.

## Тип свойства «Публикация» (value_type publication)

Реестр свойств получает `value_type = publication` — ссылка на публикацию сети. По образцу `thought_ref` (прецедент cross_network_ref из 0.8.3):

1. Сервер: `PROPERTY_VALUE_TYPES` + колонка хранения + валидация (существование публикации в текущем слое); удаление цели блокирует живые значения (см. жизненный цикл публикации).
2. Отборы: операторы eq/ne/any_of/none_of по id — та же матрица `OPS_BY_VALUE_TYPE`; участие в `title_recipe` и прочих фильтрах наравне с другими свойствами.
3. Клиент: профиль пикера (`lib/entity-picker`) и рендер значения названием (см. элемент интерфейса поля выбора).
4. MCP/REST: тип в онтологии (`etn.ontology.write` значения свойств) и в ответах карточек.

## Членство в публикациях: runtime-исполнение рецептов, без материализации

**Контекст.** «+N новых» и «использование мысли» требуют знать состав публикаций. Варианты: материализованный индекс членства (обновлять при каждой правке мыслей) или расчёт исполнением рецептов по запросу.

**Решение.** Runtime-расчёт: серверные эндпойнты candidates/usage исполняют рецепты с лимитами, ленивые вызовы и кеш с дебаунсом (по (publication_id, слой) и (thought_id, слой)).

**Почему.** Индекс нужно инкрементально поддерживать при ЛЮБОЙ правке мысли/связи/свойства — сложная инфраструктура с риском рассинхрона; при десятках публикаций и ленивых вызовах runtime дешевле и всегда точен.

**Следствия.** Отклик группы «Упоминания» — с прелоадером; счётчик «+N» обновляется с дебаунсом. Если рост числа публикаций сделает отклик плохим — материализация отдельным решением (замер фиксируется как исследование). **Запрет:** не поддерживать индекс членства инкрементальными хуками записи мыслей.

## Экспорт публикации в PDF: клиентская печать и недетерминированный формат

**Контекст.** Публикацию нужно экспортировать в PDF (распространённый формат обмена документацией), сохранив оглавление, разметку, оформление, ВСЕ картинки и переходы по якорям. Сервер собирает детерминированные md/html-zip и не должен тянуть тяжёлый рендерер (puppeteer/playwright); клиент — Electron со встроенным `webContents.printToPDF`.

**Решение.** PDF формирует КЛИЕНТ. Сервер отдаёт самодостаточный печатный HTML (`GET /publications/{id}/print` — тот же `renderHtmlDocument`, картинки как data-URI, водяной знак); основной процесс клиента грузит его в СКРЫТОЕ окно и печатает `webContents.printToPDF` (`printBackground: true`, A4), сохраняет файл существующим диалогом, имя — `<slug>.pdf`. Формат `pdf` перехватывается клиентом в экспортном меню (одиночный экспорт публикации); `PUBLICATION_EXPORT_FORMATS` (`md|html`) и серверный/MCP/CLI-экспорт НЕ расширяются.

**Почему.** Ноль новых серверных зависимостей; переиспользование единого серверного рендера (превью и документ не расходятся); Chromium сам проставляет внутренние ссылки-якоря аннотациями `/Subtype /Link` + `/Dest` (проверено экспериментом printToPDF), поэтому дополнительная PDF-библиотека не нужна.

**Статус относительно детерминизма.** PDF ВНЕ инварианта ADR «Детерминизм экспортных zip»: байты Chromium-печати не стабильны между запусками (метаданные, подмножество шрифтов). Требование байтовой идентичности к PDF не применяется.

**Следствия.** Водяной знак «Документ сгенерирован в ETN» — только в печатном HTML/PDF, не в файловом HTML-экспорте. **Запрет:** не добавлять `pdf` в `PUBLICATION_EXPORT_FORMATS`, не изобретать серверную печать и не требовать байтовой идентичности PDF.

## Оглавление публикации: собственные строки вместо фасада дерева

**Контекст.** Элемент интерфейса 2ebacd12 «Открытая публикация» требует оглавления с drag&drop локального порядка разделов (любого уровня), пометками повтор/обрыв кольца/исключён, подсписком текстов и сворачиванием ветвей. Каталог `lib/ui` даёт единый фасад дерева `tree.ts` (требование 0086037c), но он рассчитан на списки выбора/каталоги: несёт `rowMenu`/`rowClass`/сворачивание/фильтр, но не drag&drop порядка и не произвольные пометки-действия в строке.

**Решение.** Оглавление рабочей области (`screens/publications/workspace.ts`) строится собственными строками-слотами (`pub-toc-*`) на фасадах `lib/ui/button` (каретка, пометка повтора) и общем словаре `lib/menu`/`lib/dialog`; коллекция строк — на инкрементальной сверке `reconcileKeyed`. Общий фасад `lib/ui/tree` под app-специфичное поведение НЕ расширяется.

**Почему.** DnD порядка и пометки — специфика именно этого экрана; протаскивание их в общий фасад раздуло бы компонент, которым пользуются каталоги типов, пикеры и структуры. Остальные роли оглавления (кнопки, состояния, меню, диалоги) взяты из словаря `lib/ui`/`lib/dialog`, самодельных классов под существующие роли нет.

**Границы.** Только оглавление рабочей области публикации. Документ, прелоадеры, диалоги, меню и кандидаты — фасады. Другие экраны с деревьями — только `lib/ui/tree.ts`.

**Следствия и запрет.** Не тиражировать `pub-toc-*` за пределами этого модуля и не считать это разрешением на свои деревья вообще.

**Критерий пересмотра.** Перевести оглавление на `lib/ui/tree`, если фасаду добавят drag&drop порядка и пометки строк (или появится второй экран с таким же оглавлением) — тогда расширение фасада перестанет быть app-специфичным.
