# 08. Спецификация пользовательского интерфейса

> Документ систематизирует описание UI из исходного замысла (`Мой аналог
> TheBrain.md`) и инженерных уточнений. Сохранена терминология словаря (см.
> [10-glossary.md](10-glossary.md)).

## 1. Общий layout

```
┌───────────────────────────────────────────────────────────────────────┐
│ [Tab1 *][Tab2][Tab3][+] [▾N]                              [👤 User ▾] │ ← верх (табы)
├───────────────────────────────────────────────────────────────────────┤
│ [🌐 Мыслесеть ▾] [🗺][🌳][📜] [📌 закреплённые мысли…]                │ ← toolbar видов
├───────────────────────────────────────────────────────────────────────┤
│ [Поиск... ___________________] [⚙]                              (карта)│ ← строка поиска
├──────────┬──────────────────────────────────────────────────┬─────────┤
│          │   ↰ родственные (родители родителей)              │         │
│  Список  │  ┌─────────────────────────────────────────────┐  │         │
│ выделен. │  │  источники (родители)      │ родственники    │  │ Редак-  │
│          │  │                            │                 │  │ тор     │
│          │  ├────────────────────────────┴─────────────────┤  │ мыс-    │
│          │  │              [  ФОКУС-МЫСЛЬ  ]                │  │ ли/     │
│          │  │                                              │  │ связи   │
│          │  ├──────────────────────────────────────────────┤  │         │
│          │  │   назначения (дети)                          │  │         │
│          │  └─────────────────────────────────────────────┘  │         │
│          │                                                    │         │
├──────────┴────────────────────────────────────────────────────┴─────────┤
│ Статус-бар: 🟢/🟡/🔴 • сеть • фокус • кол-во мыслей • последнее событие    │
└───────────────────────────────────────────────────────────────────────┘
```

- **Верхняя строка (табы, фаза Q)** — слева tab-strip с открытыми табами
  и табом «+», при переполнении справа от «+» появляется кнопка `[▾N]` с
  дропдаун скрытых табов; справа — подменю `[👤 User ▾]`. Свободное место
  между табами и user-блоком — пустое. Имя текущей мыслесети **не
  дублируется** — её показывает подсвеченный активный таб.
- **toolbar видов** — слева подменю работы с мыслесетью `[🌐 Мыслесеть ▾]`
  (§8), затем переключатель видов (§15.1: Карта / Структуры / Хроника),
  панель закреплённых мыслей (§16).
- **Строка поиска** (с шестерёнкой опций) — под toolbar, принадлежит виду
  «Карта мыслей» (§3); в видах «Структуры мыслей» и «Хроника» скрывается.
- **Список выделений** (слева) — появляется, когда в списке есть хотя бы одна
  мысль.
- **Холст** (центр) — четыре зоны (см. п. 2). Показан в виде «Карта мыслей»;
  в видах «Структуры мыслей» (§15) и «Хроника» (§17) холст и строка поиска
  скрываются, их место занимает пространство соответствующего вида.
- **Редактор** (справа по умолчанию) — положение настраивается: слева / сверху /
  снизу / скрыто. Общий для всех видов.

### 1.1. Tab-strip (фаза Q)

Tab-strip занимает всё свободное место слева; справа от него —
подменю `[👤 User ▾]`. Каждый таб — отдельная открытая «сеть + контекст»
(фокус, вид, фильтры, история). Одна сеть может быть открыта в нескольких
табах — состояния независимы.

**Элементы tab-strip (слева направо):**

```
[Tab «Название1» *] [Tab «Название2»] … [Tab «НазваниеN»] [+] [▾M]
```

- **Обычный таб** — название сети (с ellipsis при переполнении); опционально
  `*` в начале заголовка (маркер «есть непрочитанные изменения»); справа —
  `✕` (закрыть таб).
- **Активный таб** — визуально выделен (подсветка фона/рамки).
- **Таб «+»** — открывает экран списка сетей (новый выбор → `etn.tabs.open`).
  Не перетаскивается, всегда последний среди табов.
- **Кнопка `[▾M]`** — появляется, когда не все табы влезают; `M` — число
  скрытых табов. По клику — дропдаун со списком «скрытых» (каждый пункт:
  название сети, кнопки «Активировать» / «Закрыть»). Не перетаскивается,
  всегда справа от «+».
- **Inaccessible таб** (сеть, к которой пользователь потерял доступ) —
  заголовок рендерится с `opacity: 0.5` («блеклый»), `*` не показывается;
  при активации — заглушка «Нет доступа к сети» с кнопкой «Закрыть таб».

**Маркер «\*»:**

- Появляется на любом табе (включая неактивные), чья `network_id`
  совпадает с `evt.network_id` пришедшего realtime-события (любой тип,
  не своё эхо).
- Снимается при активации соответствующего таба (broadсast `tabs:clean`).
- Реализация: `client/src/renderer/realtime.ts` — точка в `onEvent`
  между `isRealtimeEvent` и fan-out к listeners.

**DnD reorder:**

- Pointer-gesture (как `drag-cloud.ts`), не HTML5 DnD.
- Перетаскивать можно только **видимые** табы; «+» и `[▾M]` не
  перетаскиваются и не являются целями drop.
- Цель drop — между табами; результат — обновлённый порядок
  `slot_idx`, отправляется одной транзакцией через
  `etn.tabs.reorder(orderedIds[])`.
- В v1 DnD для табов в `[▾M]` не реализован (только «Активировать» /
  «Закрыть»).

**Ширина таба:**

- Дефолт — `--tab-w: 180px`; допустимый минимум — `--tab-w-min: 120px`;
  название сети обрезается с ellipsis в 1 строку.
- При сжатии окна ширина таба уменьшается до минимума; при дальнейшем
  сжатии не вмещающиеся табы уходят в `[▾M]`.
- Расчёт видимости выполняется по `ResizeObserver` родителя.

**Закрытие последнего «настоящего» таба:**

- Если в strip остались только «+» и `[▾M]` (т.е. ни одного обычного
  таба) → renderer показывает экран списка сетей (`showScreen('networks')`).
  При выборе сети — `etn.tabs.open(networkId)` + `setActiveTab`.

### 1.2. Подменю работы с мыслесетью `[🌐 Мыслесеть ▾]` (фаза Q)

Подменю работы с текущей мыслесетью переехало из верхней строки в toolbar
видов (см. §8) — слева от переключателя видов.

## 2. Холст

### 2.1. Зоны

| Зона | Содержание | Сортировка | Ручной порядок |
|------|------------|------------|----------------|
| **Центр** | мысль в фокусе | — | — |
| **Верх-лево** | источники связей фокуса (родители) | да | да |
| **Верх-право** | родственники (мысли с тем же родителем) | да | нет |
| **Низ** (во всю ширину) | назначения связей фокуса (дети) | да | да |

> Замечание к исходному тексту: в документе верх-право названо «родственники,
> имеющие тех же родителей». Реализация: `DISTINCT siblings` = мысли,
   являющиеся дочерними по связи к любому из родителей фокуса (исключая сам
   фокус). Если у фокуса несколько родителей — родственники объединяются из
   всех.

**Исключительность зон.** Мысль отображается **не более чем в одной зоне**
(граф может содержать циклы и перекрёстные связи, поэтому сосед может
попадать в несколько списков). Приоритет зоны:

1. мысль в фокусе — не отображается ни в какой зоне;
2. источники связей (верх-лево) — исключаются из остальных зон;
3. назначения связей (низ) — исключаются из верх-право;
4. верх-право — только мысли, подчинённые родительским и не попавшие
   ни в одну из других зон.

Рёбра окрестности при этом рисуются по всем видимым мыслям независимо от
зоны, так что связи с «другой ролью» мысли не пропадают.

**Разделители зон (L8).** Границы зон — перетаскиваемые разделители:

- **Вертикальный** — между «верх-лево» и «верх-право»; перетаскивание меняет
  деление ширины верхней полосы между двумя зонами (по умолчанию 50/50).
- **Горизонтальный** — между фокус-рядом и нижней зоной; перетаскивание меняет
  высоту нижней зоны и верхней полосы. **Высота фокус-ряда при этом не
  меняется** (она по-прежнему определяется содержимым фокус-облачка).
- Каждой зоне гарантируется минимум 96 px; дальше разделитель не идёт.
- Двойной клик по разделителю — сброс соответствующей пропорции к значению по
  умолчанию (50/50 по вертикальному, 34% высоты холста по горизонтальному).
- Пропорции хранятся в L4-ключе `canvas_layout`
  ([11-settings-and-state.md](11-settings-and-state.md), п. 2.1) и
  восстанавливаются при открытии сети.

**Вид разделителей (L12).** Полоса захвата — 4 px; в покое она прозрачна и
несёт лишь тонкую линию-хинт (1 px) по центру, при наведении/перетаскивании
подсвечивается полупрозрачным акцентом. Разделители лежат **слоем ниже
связей**: визуальные линии проходят поверх полосы, а широкие hit-линии
оверлея связей перехватывают указатель в точке пересечения (hover связи
важнее захвата разделителя).

**Полоса фокуса (L12).** Фон холста несёт горизонтальную градиентную полосу
цвета `#1E62BE` на всю высоту фокус-ряда: к верхнему и нижнему краям холста
она плавно затухает до прозрачности. Центр полосы привязан к текущему
положению фокус-ряда (обновляется при смене фокуса, перетаскивании
разделителей зон и изменении размеров окна); сама полоса лежит под облачками
и под линиями связей.

**Добавление из зон (L19).** Двойной клик по пустому месту зоны (вне облачка)
открывает диалог добавления мысли (§4) с владельцем вызова — мыслью в фокусе:
«верх-лево» → родительская, «низ» → дочерняя. Одиночный клик по пустому месту
побочных эффектов не имеет. В зоне «верх-право» двойной клик по пустому месту
ничего не делает: у фокуса может быть несколько родителей, и непонятно, кому
подчинять новую мысль. Клики по облачку имеют собственное поведение: одиночный
клик открывает мысль в редакторе и подсвечивает её ореолом (§2.2.4), двойной
клик переводит её в фокус карты; двойные клики по облачку с зажатыми
модификаторами (Ctrl/Shift/Alt) игнорируются.

### 2.1.1. Виртуальная сетка

Зоны верх-лево, верх-право и низ представляются как **таблицы с ячейками
одинаковой ширины** (колонки фиксированы, высота строки — по содержимому).
Каждая ячейка содержит одно облачко. Это упрощает визуализацию и ручное
упорядочивание.

- **Размер ячейки:**
  - ширина = `cloud_width` (настраивается пользователем, L4);
  - высота строки = **наибольшее облачко строки**: высота облачка динамическая
    (1–3 строки заголовка + индикаторы, см. п. 2.2.1), строка не ниже своего
    самого высокого облачка и не выше самого низкого — «дыр» в сетке нет;
  - плюс отступ `cloud_gap` (настраивается, L4) между ячейками.
- **Масштаб холста (L9):** все размеры ячейки умножаются на множитель
  `canvas_zoom` (L4, см. п. 2.2.1): эффективная ширина = `cloud_width × zoom`,
  эффективный отступ = `cloud_gap × zoom`, эффективная высота — из
  масштабированного шрифта/эллипсов. `cols`/`rows` и виртуализация считаются
  по эффективным размерам.
- **Количество видимых облачков** в зоне вычисляется автоматически:
  `cols = floor(zone_width  / (cloud_width  + gap))`; число строк — по
  фактическим высотам.
- Если мыслей в зоне больше, чем видимых ячеек — возникает прокрутка (см. п. 2.5).
  Сетка виртуальная: рендерятся только видимые + небольшой запас.
- Позиция в сетке = **порядок** мысли в зоне (см. п. 2.7). Свободных (x, y)
  координат нет — только позиция в упорядоченном списке.
- **Порядок заполнения сетки — по строкам (row-major):** мысли идут слева
  направо в первом ряду, затем слева направо во втором и т. д. (в терминах
  индексов — `c + r × cols`: ячейка столбца `c`, ряда `r` содержит мысль
  с индексом `c + r × cols` в упорядоченном списке зоны). Чтение «слева
  направо, сверху вниз» даёт тот же список мыслей, что и упорядоченный
  список зоны — это и есть база для интуитивной курсорной навигации
  стрелками и `Ctrl+Shift+↑/↓` (п. 2.9).
- Ручное упорядочивание = перетаскивание облачка с зажатыми `Ctrl`+`Shift` на
  другую позицию (см. п. 2.3.1), что меняет `position` в `user_focus_order`
  ([11-settings-and-state.md](11-settings-and-state.md), п. 3).

> Центральная зона (фокус) **не** является частью сетки — фокус-облачко
> размещается по центру холста и имеет собственные правила размера (см. п. 2.2.2).

### 2.2. Облачко мысли

Структура одинакова для всех облачков; различаются только правила размера — у
простых облачек (в зонах) размер фиксирован, у фокус-облачка — переменный.

```
      ▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄      ← верхний эллипс — утолщение НА верхней рамке
 ┌────┬─────────────────────┐
 │ и  │ Заголовок           │
 │ к  │ в одну–три строки   │   ← иконка-полоса слева на всю высоту; справа
 │ о  ├─────────────────────┤     заголовок (по содержимому, до 3 строк),
 │ н  │ 📝 ♣ 3 📅 2 📎 1    │     под ним индикаторы — по левому краю
 └────┴─────────────────────┘     заголовка (шрифт мельче)
      ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀      ← нижний эллипс — утолщение НА нижней рамке
```

Верхняя и нижняя стороны рамки облачка несут **компактные эллипсы, лежащие
на самой рамке** (центр эллипса — на линии рамки, половина эллипса снаружи
карточки): высота 4 px (× zoom), ширина 25% ширины облачка, **по центру
облачка** — это индикаторы связей и одновременно точки drag/прикрепления
линий (см. п. 2.3 и 2.4). Каждый эллипс — **один**: закрашен, если есть
соответствующие связи, иначе прозрачен (визуально — почти плоская граница).

**Состав (общий для всех облачков):**
- **Иконка-полоса слева** — вертикальная полоса на всю высоту облачка
  (эмодзи или картинка, см. словарь), глиф крупный, по центру высоты.
- **Правая колонка** — заголовок **в 1–3 строки** (высота облачка растёт под
  содержимое: короткий заголовок — одна строка, длинный — до трёх с `…`),
  под ним строка индикаторов (шрифт мельче), выровненная по левому краю
  заголовка:
  - `📝` — есть постоянный комментарий. Серая, если постоянного нет. Кликабельная —
    открывает редактор на группе постоянного комментария.
  - `📅 N` — хронологические комментарии, число = кол-во. Кликабельно — разворачивает
    список хронологии в редакторе.
  - `📎 N` — вложения, число = кол-во.
- **Эллипсы сверху/снизу** — на рамках (см. выше); индикаторы входящих/исходящих
  связей и точки drag (см. п. 2.3). При наведении на эллипс он подсвечивается,
  а все видимые связи соответствующего направления — линии, входящие в мысль
  (верхний эллипс) или исходящие из неё (нижний), — перерисовываются сверху
  цветом выделения (см. п. 2.4).
- **Индикатор позиции (L-фикс)** — в зонах, отсортированных как «ручной»
  (`manual`), в правом нижнем углу облачка выводится маленький кружок
  (диаметр 16 px), центр которого совпадает с правым-нижним углом облачка
  (кружок слегка перекрывает угол). Фон чёрный, цифра — светло-серый
  (`#d0d0d0`), кегль ≈ 0.75 от облачкового, `pointer-events: none` (не
  мешает click/dblclick/contextmenu). Число = `position + 1` в `user_focus_order`
  (1-based), обновляется при каждом reorder-е и при `scheduleRefresh()`
  после `link.*`/`thought.*`. Для мыслей без записи в `user_focus_order`
  (например, только что добавленных в зону с включённой ручной сортировкой)
  индикатор скрыт — мысль визуально стоит в конце зоны, и пользователь
  решает сам, поставить ей номер перетаскиванием или `Ctrl+Shift+↑/↓`.
- Цвета/стиль мысль наследует от типа или собственного назначения. Если задан
  **только фон**, а цвет текста оставлен по умолчанию, клиент выбирает цвет
  текста по яркости фона автоматически (белый на тёмном, тёмный на светлом);
  явно заданный цвет текста всегда побеждает.
- Неактуальные мысли приглушены (прозрачность ×0.5, курсив), если показываются
  (см. п. 9).
- **Визуальный стиль (L11):** карточка скруглена сильнее панелей (радиус
  14 px), рамка — обычная (`--border`), тень мягкая двухслойная; на hover
  рамка берёт более сильный тон и тень усиливается (без сдвига карточки —
  чтобы не конфликтовать с FLIP-анимацией п. 2.8). Иконка — круглый «медальон»
  на приглушённом фоне; заголовок — плотный line-height 1.35; строка
  индикаторов мельче (0.8 em) и не раздувает высоту. Фокус-облачко
  дополнительно несёт свечение акцентного цвета (`--shadow-focus`).

#### 2.2.1. Простые облачка (зоны верх-лево, верх-право, низ)

- **Высота динамическая:** 1–3 строки заголовка + строка индикаторов + эллипсы
  сверху и снизу. Облачко растёт под содержимое (короткий заголовок — одна
  строка, длинный — до трёх); пользователем не редактируется. Вычисляется из
  CSS (высота строки × число строк + отступы + диаметр эллипса × 2).
- **Ширина = `cloud_width`** (L4), одинакова для всех простых облачков.
  Ограничена системными константами `CLOUD_WIDTH_MIN`/`CLOUD_WIDTH_MAX`
  (см. [11-settings-and-state.md](11-settings-and-state.md), п. 2.4).
- Заголовок обрезается до 3 строк с `…`. Полный текст — в tooltip при наведении.
- Размер шрифта — системная константа, масштабируется с `cloud_width` по
  фиксированному правилу; пользователем не редактируется.
- **Масштаб холста (L9):** множитель `canvas_zoom` (L4, 50–200%, шаг 5%,
  дефолт 100%; меняется клавишами — см. п. 13) применяется ко всем простым
  облачкам разом: эффективная ширина = `cloud_width × zoom`, шрифт, высота
  строки, высота эллипсов и вертикальные отступы тела пропорционально
  масштабируются (линии рамки остаются 1 px). `cloud_width`/`cloud_gap` при
  этом не перезаписываются — зум множитель поверх них, а не четвёртая настройка
  размера.

#### 2.2.2. Фокус-облачко (центр)

- **Не имеет фиксированной ширины.** Ограничено сверху шириной центральной зоны
  холста (с отступами). Короткий заголовок → узкое облачко; длинный → расширяется
  до предела зоны.
- **Высота зависит от содержимого:** заголовок выводится в столько строк, сколько
  нужно, но **не более 3**. Если не помещается в 3 строки — обрезается с `…`,
  полный текст — в tooltip при наведении (до 400 символов).
- Квадрат иконки и строка индикаторов — те же, что у простых облачков.
- Визуально выделено: более яркая заливка/рамка, увеличенный шрифт заголовка
  (множитель `FOCUS_FONT_SCALE`, системная константа). Пользователем не
  редактируется.
- Масштаб холста (п. 2.2.1) действует и на фокус-облачко: шрифт, иконка и
  минимальная ширина масштабируются тем же множителем `canvas_zoom`
  (переменная ширина «по содержимому» сохраняется).

#### 2.2.3. Составные имена мыслей

Имя мысли может быть **составным** — несколько частей, разделённых запятыми
(например, `Проект А, Задачи разработки`). Обрабатываются только первые
**4 части**: всё, что после 3-й запятой, считается одной частью.

Правила отображения:

- **В фокусе** — полное имя, как записано (все части).
- **На холсте вне фокуса** (облачка зон) — части, совпадающие с именами
  **видимых связанных мыслей**, скрываются. «Видимые связанные» — родители
  и дети мысли, отображаемые в текущем наборе фокуса; их связи перечислены
  в `edges` focus-response (03-server-api.md §6.2). Пример: у мысли
  `Проект А, Задачи разработки` родитель `Проект А` отображается — облачко
  показывает `Задачи разработки`; родитель не отображается — имя показывается
  полностью. Скрываются части, совпадающие с именами и родителей, и детей;
  если скрытыми оказались все части — имя показывается полностью.
- **В диалогах поиска** — полное имя, все части.
- Tooltip облачка всегда содержит полное имя.
- Совпадение части — полное равенство после обрезки пробелов, без учёта
  регистра, с именем связанной мысли **или с любой из частей её имени**
  (родитель сам составной: у мысли `ETN, Ошибки, Отложено на будущее`
  с видимым родителем `ETN, Ошибки` скрываются обе части `ETN` и `Ошибки`).

#### 2.2.4. Ореол мысли, открытой в редакторе

Одиночный клик по облачку (а также `Enter` клавиатурной навигации, §2.9)
открывает мысль в редакторе **без смены фокуса карты**: редактор переключается
на выбранную мысль, а её облачко подсвечивается **ореолом** — мягким свечением
акцентного цвета вокруг карточки. Ореол держится, пока эта мысль открыта в
редакторе. Клик по пустому месту холста или по фокус-облачку, смена фокуса
(двойной клик, `Ctrl+Enter`, навигация из истории/поиска) возвращают редактор
к фокусной мысли и снимают ореол. Мысль, открытая в редакторе из других видов
(«Структуры», «Хроника», ссылки), тоже получает ореол — если она присутствует
в текущем наборе облачков карты. Клик по фокус-облачку ничего не подсвечивает:
редактор и так показывает фокусную мысль.

Одиночный клик **также ставит курсор клавиатурной навигации на эту мысль** (§2.9):
после клика стрелки и `Ctrl+Shift+←/→` двигаются именно с кликнутого облачка,
а не с того, на котором курсор был случайно. Ореол и курсор — два независимых
визуальных состояния (ореол — «открыта в редакторе», курсор — «выбрана для
клавиатуры»); на одном облачке они могут стоять одновременно.

Мысль, входящая в выделение (п. 5), обводится **сине-зелёной рамкой**
(`--selection`) — во всех видах, где показаны облачка (карта, дерево
«Структур»); цвет намеренно отличен от ореола открытой в редакторе мысли,
чтобы состояния не путались.

### 2.3. Эллипсы и drag

- **Верхний эллипс** (утолщённая верхняя сторона рамки) = индикатор входящих
  связей и точка drag для создания **родителя** (источника связи).
- **Нижний эллипс** (утолщённая нижняя сторона рамки) = индикатор исходящих
  связей и точка drag для создания **ребёнка** (назначения связи).
- Drag-жест: `mousedown` в любой точке эллипса → перетаскивание → `mouseup`. На
  `mouseup` открывается диалог добавления мысли (см. п. 4) в соответствующем
  направлении. «Бросить» на другую мысль — связать с существующей.
- Жест всегда видим (L-фикс): на время перетаскивания курсор над всем окном —
  «прицел» (crosshair), нажатый эллипс подсвечен, облачко под курсором
  обводится как цель броска, а от эллипса к курсору тянется **пунктирная
  линия будущей связи**. Эллипс запускает именно этот жест и у облачков
  зон, где само облачко HTML5-draggable: native drag облачка на время
  нажатия подавляется и восстанавливается на `mouseup`.
- После «броска» на мысль связь создаётся немедленно, холст и раздел «Связи»
  редактора обновляются без участия realtime (действующему клиенту эхо
  событий не приходит, 04-realtime.md §5 — клиент обновляет себя сам).

### 2.3.1. Перетаскивание облачка (drag мышью)

Облачко **любой** зоны (родителей, детей, родственников) и фокус-облачко можно
перетащить мышью; модификаторы меняют смысл броска (модификаторы действуют в
любой момент перетаскивания). У облачков зон родителей/детей есть
зона-источник (перемещение/упорядочивание); облачка родственников и
фокус-облачко зоны-источника не имеют и ведут себя как элементы списков
(п. 5.5, 11.1): бросок на мысль — связь, бросок в зону родителей/детей —
связь с мыслью в фокусе в направлении зоны, бросок на панель закреплённых
(§16) — закрепление.

- **Обычное перетаскивание** (без модификаторов):
  - бросок на **верхний эллипс** мысли Б → создать связь A→Б (A становится
    родителем Б);
  - бросок на **тело** (или нижний эллипс) мысли Б → создать связь Б→A;
  - бросок в **другую** упорядочиваемую зону (родители↔дети) → развернуть
    направление связей мысли с фокусом (переместить в соседнюю зону), типы
    связей сохраняются;
  - бросок в **свою же** зону, в зону родственников или вне целей — ничего не
    происходит; **порядок мыслей при обычном перетаскивании не меняется**;
- **`Ctrl`/`⌘` + перетаскивание** — «переподчинить» (не копировать!): бросок
  на любую часть мысли Б (включая эллипсы) делает Б **единственным родителем**
  перетаскиваемой мысли — все её существующие родительские связи заменяются
  одной связью Б→A;
- **`Ctrl`+`Shift` + перетаскивание** — ручное упорядочивание; работает только
  при сортировке зоны «ручной» (п. 2.7): бросок на мысль Б ставит A сразу
  **перед** Б, последующие сдвигаются. Броски в пустую часть зоны — no-op.
  Во время перетаскивания эллипсы не задействуются (не подсвечиваются и не
  реагируют на наведение), а мысль-цель подсвечивается **зелёной** рамкой —
  в отличие от синей подсветки целей связи/переподчинения. Прочие облачка
  стоят на месте до броска; после броска облачка плавно переезжают на новые
  места (FLIP, п. 2.8) — сдвигаются вниз по порядку чтения, а старая позиция
  перетащенной мысли заполняется сдвигом остальных.

Перетаскивание — мышиный жест (не HTML5 drag-n-drop): удерживаемые модификаторы
не блокируют начало перетаскивания (HTML5 DnD с `Alt` перехватывается
браузером). Существующие связи переиспользуются (повторное создание — no-op);
обратная связь, если есть, удаляется первой,
а её тип переносится на новую связь.

**Отмена перетаскивания (`Esc`)** — во время активного drag (после
`mousedown` и до `mouseup`) нажатие `Esc` отменяет жест: визуальное
смещение облачка сбрасывается к исходному, drop-индикаторы и подсветка
зон скрываются, состояние drag полностью очищается. Повторные нажатия
(`event.repeat`) игнорируются — одно нажатие → одна отмена. Обработчик
`Esc` для drag стоит выше глобального Esc-обработчика приложения
(`preventDefault`), чтобы случайно не закрыть меню/диалог, открытый до
начала drag.

### 2.4. Связи

- Линия связи идёт **от нижней границы нижнего эллипса источника к верхней
  границе верхнего эллипса назначения** (т.е. от внешних краёв эллипсов,
  лежащих на рамках) **кубической кривой Безье** (L14): контрольные точки
  уходят от концов по нормалям точек крепления (от низа источника — вниз,
  от верха назначения — вверх), величина изгиба ограничена диапазоном и не
  масштабируется до гигантских петель на длинных рёбрах.
- Штрих линии — **градиент от цвета источника к цвету цели** (L14): цветом
  конца служит собственный или типовой цвет фона соответствующей мысли; если
  у конца цвета нет — цвет стиля связи (собственный override → тип →
  системный дефолт). Если оба конца дают один цвет — линия сплошная
  (градиент не строится).
- Подпись типизированной линии читается **от фокуса** (L6): связь, исходящая
  из фокусной мысли, подписывается `name_forward` (например «сотрудники» от
  компании), связь, входящая в фокус, — `name_reverse` («место работы» от
  сотрудника). Названия групп в разделе «Связи» редактора выбираются так же —
  от редактируемой мысли.
- Бейдж-счётчик пачки и подписи типов размещаются в **середине кривой**
  (точка t=0.5), а не на середине хорды.
- Линии проводятся только между **полностью видимыми** облачками: облачко,
  обрезанное краем видимой области зоны (виртуализация, п. 2.5), связей не
  показывает — линии появляются, когда оно целиком попадает в видимую область
  (и ведут только к другим видимым облачкам).
- **Интерактивна только видимая часть линии.** Визуальные кривые и широкие
  прозрачные hit-полосы лежат **под облачками**: наведение/клик работают на
  участках линии, открытых между облачками; часть линии, скрытая облачком,
  не перехватывает у него указатель (fix: раньше hit-полосы висели над
  облачками и «поднимали» связи при каждом наведении на облачко, мешая
  кликать в него). Выделенная при hover линия (и её подпись/бейдж)
  перерисовывается на верхнем слое **над** облачками.
- Если у связи есть тип — вдоль линии отображается подпись (по направлению от
  источника к назначению — `name_forward`).
- Hover на линии → линия и её подпись/бейдж-счётчик подсвечиваются цветом
  выделения, всплывает tooltip с `name_forward`/`name_reverse` и индикаторами
  комментариев/вложений связи. Концевые эллипсы связи при этом увеличиваются
  вдвое по высоте и получают оранжевую рамку на 1 px толще (как при hover
  эллипса).
- **Hover на эллипсе** → эллипс увеличивается вдвое по высоте (ширина та же,
  центр остаётся на линии рамки), рамка становится оранжевой и на 1 px
  толще; все видимые связи соответствующего направления перерисовываются
  поверх облачков цветом выделения: верхний эллипс — линии, входящие в мысль;
  нижний — исходящие из неё. Подсветка снимается, когда курсор покидает
  эллипс.
- Несколько связей между парой мыслей — линия толще, поверх — число. Hover →
  всплывающий список всех связей с их подписями и индикаторами. Клик по элементу
  списка → связь открывается в редакторе (фокус не меняется).
- Контекстное меню линии (правый клик; для пачки связей — сначала выбор связи
  из списка):
  - **Изменить свойства** — открывает диалог стиля линии (§6.9);
  - **Изменить актуальность** — включить/выключить связь;
  - **Инвертировать** — поменять местами источник и назначение той же связи:
    линия перекрашивается сразу, облачко перетекает между зонами с FLIP-анимацией
    (§2.8), раздел «Связи» редактора обновляется; если в обратном направлении
    такая связь уже есть — сообщение без изменений;
  - **Удалить** — с подтверждением.
- **Масштаб холста (L9)** действует и на оформление линий: кегль подписей,
  радиус бейджа-счётчика и толщина линий умножаются на `canvas_zoom` (п. 2.2.1).

### 2.5. Прокрутка и счётчики

- Количество одновременно видимых облачков определяется виртуальной сеткой
  (п. 2.1.1): `cols` колонок по ширине зоны, строки — по фактическим высотам.
- В каждой зоне своя прокрутка. **Уточнение по итогам H-фазы:** сетка
  раскладывает мысли по строкам (row-major, п. 2.1.1 — слева направо в
  строке, затем следующая строка), поэтому все зоны прокручиваются
  **вертикально** (в исходном замысле для верхних/нижней зоны предполагалась
  горизонтальная прокрутка — это противоречит фиксированным ячейкам;
  вертикальная прокрутка принята как реализованный вариант).
- На полосе прокрутки отображается диапазон видимых мыслей, например `12–36`.
- Перегрузка видимой области: показываем только видимые строки + небольшой
  запас (виртуализация рендера по сетке), далее подгружаем при прокрутке.
  Высоты строк динамические (п. 2.2.1) — неотрисованные строки оцениваются по
  минимальной высоте облачка, а после отрисовки измеряются, и раскладка один
  раз пересчитывается (виртуализация не расходится с DOM).

### 2.6. Контекстное меню мысли (правый клик)

```
┌─────────────────────────────┐
│ Добавить                    │→ ▸ добавить вверх (родитель)
│                             │  ▸ добавить вниз (ребёнок)
│                             │  ▸ добавить налево (родственник)*
├─────────────────────────────┤
│ Изменить актуальность        │
│ Изменить порядок          → │ ▸ сдвинуть вверх / первым
│                             │  ▸ сдвинуть вниз / последним
│ Изменить тип              → │ ▸ выбор типа / очистить
│ Изменить иконку             │
│ Добавить вложение           │
├─────────────────────────────┤
│ Открыть редактор            │
│ Закрепить мысль / Открепить │
│ Добавить к выделению        │
│ Копировать / Вырезать       │
│ Вставить                    │
│ Удалить                     │
└─────────────────────────────┘
```

Пункт **«Закрепить мысль»/«Открепить мысль»** (L18) присутствует во всех
отображениях мыслей: на холсте, в панели выделения, в дереве «Структур»,
в чипах истории и панели закреплённых (§16). Подпись отражает состояние
(toggle).

\* «Добавить налево» (родственник) — создаёт новую мысль как ребёнка того же
родителя, что и фокус (фактически добавляет связь к одному из родителей).
Доступно только если у фокуса есть хотя бы один родитель.

### 2.7. Контекстное меню зоны

Правый клик по зоне (H15) открывает её контекстное меню:

- **Добавить мысль** (L19) — только в зонах «верх-лево» и «низ»: открывает
  диалог добавления (§4) родительской («верх-лево») либо дочерней («низ»)
  мысли к фокусу. В зоне «верх-право» пункта нет: у фокуса может быть
  несколько родителей, и непонятно, кому подчинять новую мысль.
- **Сортировка** — меню порядка (для верх-лево, верх-право, низ):
  - по алфавиту (возр/убыв)
  - по дате создания (возр/убыв)
  - по дате последнего просмотра (возр/убыв)
  - ручной (только для родителей/детей; недоступен для родственников)

  Текущий для данной зоны пункт (по `focus.sorts[dir]`) отмечен галочкой
  слева от лейбла (стиль `.menu-item-checked`). При смене режима
  галочка переезжает на новый пункт сразу после ответа сервера.

Для **ручной** сортировки направление фиксировано — `asc` (сверху вниз по
порядку зоны, п. 2.1.1): «выше/ниже» здесь имеет смысл только относительно
самого списка, а не алфавита/даты. Переключатель `возр/убыв` для ручного
пункта скрывается; сервер отвергает `PUT focus-preferences` с
`sort='manual' && order='desc'` (`VALIDATION_ERROR`,
[03-server-api.md](03-server-api.md) §6.8).

При первом переключении на «ручной» клиент сначала коммитит текущий видимый
порядок зоны в `user_focus_order` через `POST focus-order` (replace-семантика,
02-data-model.md §3.10.4), затем вызывает `PUT focus-preferences`. Так
позиции 0..N-1 появляются сразу, и индикатор номера (см. §2.2) сразу
становится виден на всех облачках. Без этой инициализации все `manual_position`
равны `null` (записей в `user_focus_order` ещё нет) и индикатор скрыт у всех —
внешне это выглядит как «ручной режим сломан».

Порядок сохраняется **для мысли в фокусе** (per-focus). Дефолт — по дате создания
(возр).

Ручной порядок меняется перетаскиванием облачка с зажатыми `Ctrl`+`Shift`
(п. 2.3.1): мысль-цель подсвечивается зелёным, после броска облачка
переезжают с FLIP-анимацией; обычное перетаскивание порядок не меняет.

### 2.8. Анимация смены фокуса

Смена фокуса анимируется (FLIP по сеткам зон), всё представление — **не более
1 секунды**:

- выбранная мысль перемещается из своей зоны в центр (место фокуса), увеличиваясь
  до размера фокус-облачка;
- бывший фокус уменьшается и уезжает в свою зону (родитель/ребёнок/родственник);
- оставшиеся видимыми мысли плавно переезжают на новые места;
- мысли, покинувшие окрестность, затухают на прежнем месте; новые — проявляются;
- линии связей на время переезда гаснут и проявляются по прибытии облачков
  (маскируют мгновенную перегеометрию).

Анимация не играет при `prefers-reduced-motion: reduce`, при обновлениях того же
фокуса (правки, realtime, выделение) и не блокирует ввод (движение — только
`transform`/`opacity`, слой «призраков» прозрачен для указателя).

**Уточнение (L-фикс):** смена зон после изменения связей анимируется тем же
FLIP-приёмом. Когда установка/смена/удаление связи меняет состав зон
(исключительность зон, п. 2.1 — например, родственник стал ребёнком фокуса),
обновлённый холст проигрывает перетекание: мысль переезжает из старой зоны в
новую, линии гаснут и проявляются по прибытии облачков. Триггеры: бросок связи
с эллипса, drop облачка на облачко/зону, ручное упорядочивание
(Ctrl+Shift-drag, п. 2.3.1). Прочие обновления того же фокуса (правки,
realtime-события без смены состава зон, выделение) не анимируются.

### 2.9. Клавиатурная навигация по карте

Навигация клавиатурой доступна, пока фокус клавиатуры находится на холсте
карты (клик мышью по холсту или облачку оставляет его там).

- **Стрелки** перемещают курсор — пунктирную рамку на облачке: выбирается
  ближайшее облачко в направлении стрелки по видимой геометрии карты
  (включая фокус-облачко; до первого шага курсор считается стоящим на
  фокус-облачке). Если видимых облачков в направлении нет, но зона курсора
  может проскроллиться дальше, зона прокручивается и шаг повторяется против
  свежего окна виртуализации.
- **Tab / Shift+Tab** — то же, что стрелки → / ← (нативный порядок табуляции
  браузера по облачкам не используется: он следует порядку слотов
  виртуализации, а не видимой геометрии).
- **Home / End** — первое/последнее облачко зоны курсора (зона
  прокручивается к краю); с фокус-облачка — край первой/последней непустой
  зоны карты (Home: «верх-лево» → «верх-право» → «низ»; End — в обратном
  порядке).
- **Enter** — как одиночный клик: открыть мысль курсора в редакторе с
  ореолом (п. 2.2.4); на фокус-облачке — вернуть редактор к фокусной мысли.
- **Ctrl+Enter** — как двойной клик: перевести мысль курсора в фокус карты.
- **Ctrl+Shift+← / Ctrl+Shift+→** — переместить мысль курсора на одну
  позицию в порядке своей зоны (влево/вправо по `zoneOrder`, то же действие
  на сервере — `focus_order`). Работает только в зонах «верх-лево» и «низ»
  и только при их сортировке «ручной» (иначе — подсказка, как у
  Ctrl+Shift-drag, п. 2.3.1). При row-major-раскладке (п. 2.1.1) это
  естественное движение «на одну мысль влево/вправо в списке зоны» —
  совпадает с визуальным соседством по строке и переходом через конец
  строки на следующую/предыдущую (т. е. оборачивается по строкам без
  перескока через все ряды сразу).
- **Escape** — снять рамку курсора.
- Курсор сбрасывается при смене фокуса карты; рамка переезжает вместе с
  облачком при реордеринге и пере-применяется после любых перерисовок холста
  (в т.ч. виртуализации).

## 3. Строка поиска и поиск

Строка поиска (с шестерёнкой опций) — **строка вида «Карта мыслей»**: под
верхней панелью приложения, над холстом (L18). В виде «Структуры мыслей»
строка скрыта (п. 15.1), `Ctrl+F` там не действует.

### 3.1. Поведение
- Активация поиска (`Ctrl+F` или клик в строке) **восстанавливает** предыдущий
  запрос: текст, опции, результаты — и открывает панель результатов.
  Панель закрывается по `Escape` (пока она видна) или клику вне её; текст и
  результаты сохраняются до следующей активации.
- Во время ввода — автопоиск (debounce 250 мс) или по Enter (на выбор;
  рекомендуется по Enter для крупных сетей, чтобы не нагружать сервер).
  Поиск выполняется при длине запроса **от 3 символов**; более короткие запросы
  на сервер не отправляются (подсказка в панели результатов).
- Запрос использует мини-синтаксис (03-server-api.md §12): все слова
  обязательны (AND, порядок произвольный), `*` — подстановка, `-слово` —
  исключение; запрос из одних исключений ничего не находит.
- **Поиск по ID мысли.** Если запрос целиком совпадает с форматом ID мысли
  (UUID, например `099776db-2156-40b4-bcbb-1b9075dbcd83`; регистр и
  обрамляющие пробелы не важны), поиск идёт прямо по этому ID
  (`GET /thoughts/{id}`): в панели результатов отображается единственная секция
  «Мысль по ID (1)» с найденной мыслью — **игнорируя прочие опции поиска**
  (поддерево, типы, «показывать неактуальные»; находятся и неактуальные
  мысли). Клик по записи переводит мысль в фокус. Если мысли с указанным ID
  нет, в развёрнутой секции отображается «Мысль с указанным ID отсутствует».
- Результаты группируются в сворачиваемые секции:
  - Найдено по именам (N)
  - Найдено по текстам (N)
  - Найдено связей (N)
  - Найдено в хронологии (N)

  Пустые секции (N = 0) отображаются свёрнутыми.
- Панель результатов — dropdown с рамкой: левый край выровнен по левому краю
  строки поиска, правый отступ — ≥10% ширины окна, высота — ≤50% высоты окна.
- Каждая запись: иконка, заголовок, snippet с подсветкой матчей (`<mark>`).
  Записи внутри секции компактны и разделены тонкой линией.
- Клик по мысли → фокус и редактор. Клик по связи → фокус на источник связи,
  связь подсвечена и открыта в редакторе. После выбора записи панель поиска
  скрывается.
- Навигация клавишами в панели результатов: `↑`/`↓` перемещают выделение по
  секциям и записям; `Enter` на секции — свернуть/развернуть, на записи —
  выбрать её (как клик). Повторная активация поиска (`Ctrl+F`) выделяет
  последнюю выбранную запись.

### 3.2. Опции (шестерёнка в строке поиска)
- ☐ только в подчинённых мыслях (выбор subroot через дополнительный селектор,
  по умолчанию — текущий фокус)
- ☐ искать только мысли
- ☐ искать только связи
- ☐ искать только хронологию
- Тип мыслей (multi-select)
- Тип связей (multi-select)
- ☐ показывать неактуальные (по умолчанию = из предпочтений `show_inactive`)

Состояние опций сохраняется в `search_state` (см. [07-client-electron.md](07-client-electron.md),
п. 3.2) и восстанавливается при активации.

## 4. Диалог добавления/выбора мыслей

Назначение: **не дублировать** мысли. Поэтому любой ввод сопровождается живым
поиском существующих.

**Поиск по ID.** Если ввод целиком совпадает с форматом ID мысли (UUID, §3.1),
живой поиск идёт прямо по этому ID (`GET /thoughts/{id}`), игнорируя фильтр
типов вызова (`searchTypeIds`; находятся и неактуальные мысли): найденная
мысль показывается единственным кандидатом-«точным именем» — клик или Enter
выбирают её как существующую. Если мысли с указанным ID нет, под полем
выводится «Мысль с указанным ID отсутствует». Если найдена сама мысль-якорь
(связь с собой невозможна) — «Нельзя связать мысль с самой собой».

Диалог **универсален**: он накапливает список выбранных/новых мыслей и
возвращает его вызывающему месту, которое решает, что с ним делать (карта —
создаёт мысли и связи; поля выбора — используют id существующих). Параметры
вызова адаптируют его под задачу:

- **«запретить создание новых»** — разрешён выбор только существующих мыслей:
  поле «Тип мысли» скрыто, ввод без точного совпадения берёт первого
  найденного кандидата (или ничего, если не нашлось);
- **«разрешить выбор типа связи» = Ложь** — поле «Тип связи» скрыто;
- **«выбранные мысли»** — предзаполнение списка (режим «несколько» включается
  автоматически): так редактируется уже сделанный выбор;
- кнопка **«Очистить»** в шапке списка — очищает накопленный список.

### 4.1. Виды вызова
- Из контекстного меню мысли (вверх/вниз/налево).
- Из drag-жеста на эллипсе.
- Из диалога «несколько мыслей» в панели выделения.
- Двойным кликом по пустому месту зоны «верх-лево» (родитель) или «низ»
  (ребёнок); владелец вызова — мысль в фокусе (L19, п. 2.1).
- Из контекстного меню зоны «верх-лево»/«низ» → «Добавить мысль»
  (L19, п. 2.7).
- Как **пикер существующих мыслей** во всех местах выбора мыслей (без
  создания и типа связи): поле «мысли» отбора Хроники и «Связать с…» (§17),
  кнопки «выбрать» у полей `thought_ref` (редактор свойств, структуры,
  панель выделения), «подкорень» поиска, «добавить мысли» панели выделения,
  «перенести вложение в мысль».

### 4.2. Layout диалога

```
┌────────────────────────────────────────────────────┐
│ Добавить мысль (вниз к «Фирма 1С»)            [×]  │
├────────────────────────────────────────────────────┤
│ Режим: ( ) одна   (•) несколько                    │
│ Тип мысли: [без типа ▾]  Тип связи: [состоит из ▾] │
│ ┌────────────────────────────────────────────────┐ │
│ │ Введите название или вставьте список…          │ │
│ │ Иванов Иван | Ваня, Иваныч                     │ │
│ └────────────────────────────────────────────────┘ │
│ Найденные мысли:                                   │
│   [💼] Иванов Иван                        Родители │
│   [💡] Иван Иванов                        Фирма 1С │
│   [📄] Иванова (синоним «Ваня»)            1С-ники │
│                                                    │
│ Список добавляемых (только в режиме «несколько»):  │
│   ✓ Иванов Иван | Ваня, Иваныч           [↑][×]    │
│   ✓ Петров                                [↑][×]    │
│                                                    │
│              [Отмена]  [Добавить] / [Вставить все] │
└────────────────────────────────────────────────────┘
```

Компоновка сверху вниз: переключатель режима, поля выбора типов (создаваемой
мысли и связи; скрыты при «запрете создания» / «без типа связи»)
**на одной строке** — метки «Тип мысли» и «Тип связи», поле
ввода наименования, подсказка о клавишах, список найденных мыслей, ниже —
список добавляемых с шапкой «Выбрано: N» и кнопкой «Очистить» (режим
«несколько»). Ширина диалога ~620 px — на ~15% шире
прочих диалогов, чтобы поместились строка типов и списки. Шрифт диалогов
на шаг крупнее базового (14 px — против 13 px в интерфейсе).

Каждая строка списка найденных: иконка мысли (своя, иначе — типа мысли) и её
оформление (цвет, жирность и т.п.), заголовок и имя родителя (первые
60 символов) — оно помогает различить мысли с одинаковыми заголовками под
разными родителями. Точность совпадения (точное имя / синоним / частичное)
показана в подсказке строки. Кнопки «использовать» и пометки «частично» в
списке нет: выбор происходит кликом или Enter по строке (см. §4.3).

### 4.3. Поведение

**Режим «одна»:**
- При открытии диалога курсор — в поле ввода наименования.
- Ввод названия → живой поиск по `title` и `synonyms`; запрос понимает
  мини-синтаксис поиска на карте (п. 3.1): все слова обязательны (AND,
  порядок произвольный), `*` — подстановка, `-слово` — исключение.
- Мысль-владелец вызова (якорь) не показывается в списке найденных: связь
  мысли с самой собой невозможна.
- Под полем — список найденных (иконки и оформление мыслей, имя родителя).
- `Tab` из поля ввода переводит фокус в список найденных, `↓` — тоже; по списку
  работают `↑`/`↓`; `Enter` или клик по строке выбирает найденную мысль
  (создаётся связь с владельцем вызова); **`Shift+Enter`** подставляет полное
  имя выбранной мысли в поле ввода — заменяет набранный текст целиком,
  добавляет запятую в конце, курсор встаёт сразу после запятой (для
  составления составных имён, §2.2.3); `Esc` возвращает фокус в поле.
- `Enter` в поле ввода → создаётся **новая** мысль (или используется выбранная
  из найденных) со связью к владельцу вызова. При запрете создания новых —
  берётся точное совпадение, иначе первый найденный кандидат (нет
  совпадений — ничего не добавляется).
- `Ctrl+Shift+Enter` в поле ввода — то же, что `Enter`, но добавленная мысль
  сразу становится фокусом холста (L19); точный дубликат при этом
  связывается, и в фокус попадает он.
- Если в названии есть `|` — текст после `|` парсится как синонимы через запятую.

**Режим «несколько»:**
- Список добавляемых накапливает введённые/выбранные мысли.
- Enter добавляет в список добавляемых, поле очищается.
- **Клик или Enter по строке списка найденных добавляет существующую мысль
  в список добавляемых** (диалог не закрывается; повторное добавление той же
  мысли игнорируется).
- `Ctrl+Enter` — вставка всех мыслей списка добавляемых в выбранное место.
- `Ctrl+Shift+Enter` — вставка всех, после чего **первая из списка добавляемых**
  становится фокусом холста (L19); в режиме «одна» набранное имя вставляется
  как единственная строка и фокусируется.
- Любая строка списка добавляемых редактируется/удаляется; кнопка «Очистить»
  в шапке списка очищает его целиком.
- При вставке результата: **новые** мысли создаются с указанным типом (если
  задан), **существующие** свой тип не меняют; заданный тип связи назначается
  всем добавляемым связям.

**Вставка многострочного буфера:**
- При вставке многострочного текста автоматом включается режим «несколько».
- Программа обрабатывает каждую строку: ищет точное совпадение по имени/синониму,
  использует существующую мысль или помечает как «новая».
- Парсинг `|` для синонимов — на каждой строке.
- Результат показывается в списке добавляемых до вставки.

### 4.4. Дедупликация — правила

| Точность | Когда | Действие по умолчанию |
|----------|-------|----------------------|
| точное совпадение имени | `title_norm == input_norm` | предложить использовать существующую |
| совпадение синонима | `synonym_norm == input_norm` | то же |
| совпадение синонима с подстановкой | `*`-паттерн синонима совпал со вводом (02-data-model.md §3.2) | то же |
| частичное / подстрока | все слова ввода (мини-синтаксис п. 4.3) входят в `title` или `synonym` | пометить как кандидат |
| нет совпадения | — | создать новую |

Финальное решение — за пользователем (выбор строки списка найденных — кликом
или Enter, или «Добавить» для создания новой мысли).

## 5. Панель выделения (слева)

Панель видна, пока список не пуст: заголовок «Выделение (N)» с кнопкой «✕»
(очистить список), под ним — меню-бар из трёх меню («Выделение», «Действия»,
«Свойства»), ниже — список выделенных мыслей.

**Граница-ресайзер.** Правая граница панели — перетаскиваемый сплиттер:
перетаскивание изменяет ширину панели (140..480 px, по умолчанию 210), холст
занимает остальное. Ширина запоминается в `window_layout` (поле `s`,
11-settings-and-state.md §2.1 L4) и восстанавливается при следующем запуске.
При доке редактора слева сплиттер остаётся на границе панели (между панелью и
холстом); при доке сверху/снизу ресайзер скрыт.

### 5.1. Добавление в выделение
- Контекстное меню мысли → «Добавить к выделению» / «Убрать из выделенных» —
  подпись отражает текущее состояние, действие — toggle.
- Контекстное меню записи в результатах поиска → «Добавить к выделению».
- `Ctrl+клик` по мысли: добавить/удалить (toggle).
- `Ctrl+клик` по эллипсу мысли: верхний → добавить всех родителей; нижний → всех
  детей.
- Команды добавления (меню «Выделение», Ctrl+клик по эллипсу, поиск) пропускают
  мысли, уже присутствующие в списке, — дубликатов в списке не бывает; убрать
  мысль можно только toggle («✕» у элемента, «Убрать из выделенных»).
- Правый клик по элементу списка — контекстное меню мысли, как на холсте, без
  команды выделения. Клик по элементу переводит мысль в фокус, не меняя список.

### 5.2. Меню «Выделение»
- добавить подчиненные мысли (дети всех из списка)
- добавить родительские мысли (родители всех из списка)
- добавить мысль… — диалог поиска и выбора существующей мысли (живой поиск,
  кнопка «использовать»)
- очистить список выделенных мыслей — очищает список и закрывает панель

### 5.3. Меню «Действия»
Операции с мыслью в фокусе (недоступны, пока фокуса нет):
- добавить мысль в фокусе к родительским… — диалог выбора типа связи (допустим
  «Без типа»); создать связи фокус → каждая выделенная
- сделать мысль в фокусе единственным родителем… — диалог выбора типа связи,
  затем подтверждение: удалить у выделенных все входящие связи, кроме связи с
  фокусом; связь с фокусом приводится к выбранному типу (создаётся, если её не
  было)
- добавить мысль в фокусе к подчиненным… — диалог выбора типа связи; создать
  связи выделенная → фокус
- исключить мысль в фокусе из родителей — удалить связи фокус → выделенная
  (любого типа)
- исключить мысль в фокусе из подчиненных — удалить связи выделенная → фокус

Прочее:
- Экспорт → Markdown / PDF / HTML — асинхронная задача (`POST /export`) с
  опросом статуса и скачиванием файла
- Экспорт → zip-архив (.etnx) — диалог параметров (типы, вложения,
  хронология, подграф) + сохранение через main-процесс
- Импорт… — системный диалог выбора `.etnx`/`.zip` файла; импорт
  прикрепляется к сфокусированной мысли
- Удалить — подтверждение + групповое удаление (`thoughts.batch`)

### 5.4. Меню «Свойства»
- пометить неактуальными / пометить актуальными
- изменить настройки… — общий с редактором мысли диалог цветов и стилей
  шрифта; каждое изменение применяется ко всем выделенным сразу, «Сброс»
  очищает переопределения (наследование от типа)
- изменить тип мыслей… — диалог выбора типа с обязательной строкой поиска;
  пункт «Без типа» очищает тип
- изменить значение свойства… — таблица свойств, задаваемых всеми типами
  мыслей из списка выделенных; по кнопке «Применить» значения назначаются
  только тем мыслям, чей тип предусматривает эти свойства

### 5.5. Перетаскивание в панели выделения

- Элемент списка перетаскивается на холст по правилам п. 2.3.1: обычный бросок
  на мысль создаёт связь (верхний эллипс — источник, тело — назначение),
  `Ctrl` — переподчинение, бросок в зону родителей/детей — связь с мыслью в
  фокусе в направлении зоны (при отсутствии связи она создаётся; бросок в зону
  «братьев» не действует). Упорядочивание (`Ctrl`+`Shift`) недоступно — у
  элемента списка нет зоны-источника.
- Бросок перетаскиваемой мысли (с холста или из панели истории) в список
  выделенных добавляет её в выделение (с пропуском дублей, §5.1). Бросок
  элемента списка обратно в этот же список не действует.
- Перетаскивание эллипсов в списке не используется — их нет в строках списка.

## 6. Редактор мысли/связи

### 6.1. Положение
- По умолчанию справа. Переключается: слева / сверху / снизу / скрыто.
- Состояние запоминается в `ui_state.editor_position`.
- В редакторе по умолчанию — мысль в фокусе. При клике на связь на холсте —
  содержимое выбранной связи (фокус не меняется).

### 6.2. Заголовок панели и шапка редактора

**Заголовок панели** зависит от того, что выбрано: **«Мысль»** — когда выбрана
мысль, **«Связь»** — когда выбрана связь. Полей-подписей (лейблов) у полей шапки
нет — используется placeholder пустого поля.

#### 6.2.1. Шапка мысли

```
┌────────────────────────────────────────────────────┐
│ ┌──┐                                                │
│ │🖼│  Заголовок (крупный, жирный, до 5 строк)       │
│ └──┘                                                │
│ Синонимы (через запятую) __________________________│
│ [тип ▾]   [⚙]   [☑ актуально]                      │
├────────────────────────────────────────────────────┤
```

- **Квадратик иконки** слева. Если иконки нет — картинка-плейсхолдер «нет
  изображения». Клик по квадратику открывает **диалог выбора иконки** (§6.8).
- **Заголовок** — крупный (1.5× от нормального), жирный, многострочное поле
  ввода с авто-высотой (растёт под содержимое, но не более 5 строк).
- **Синонимы** — однострочное поле; запятая — разделитель.
- **Тип ▾** — поле с поиском по каталогу (combobox, §8.4): ввод фильтрует,
  строки списка несут иконку и стиль типа; есть пункт «без типа».
- **⚙ (настройки)** — открывает **диалог настроек мысли** (§6.9): цвет
  текста/фона и стиль шрифта, плюс кнопка «Сброс».
- **☑ актуально** — переключатель активности (для HOME — заблокирован).

**При смене типа** меняются только визуальные настройки, не заданные вручную
(`NULL`-поля наследуются от нового типа — см. 02-data-model.md §3.1.1): иконка,
стиль шрифта, цвета, а также состав свойств (свойства прежнего типа скрываются,
но не очищаются).

#### 6.2.2. Шапка связи

```
┌────────────────────────────────────────────────────┐
│ [тип связи ▾]   [⚙]   [☑ актуально]                │
├────────────────────────────────────────────────────┤
```

- Строк иконки/заголовка/синонимов **нет**.
- **Тип связи ▾**, **⚙ (настройки связи: цвет/штрих/толщина линии + «Сброс»,
  см. §6.9)**, **☑ актуально**.

### 6.3. Вкладки и сворачиваемые группы

Под шапкой редактора (§6.2) расположена панель **вкладок**:

| Вкладка | Применимо | Содержание |
|---------|-----------|------------|
| **Основное** | мысль и связь | сворачиваемые группы «Свойства (N)» (только мысль) и «Комментарий» (§6.3.1, §6.4) |
| **Вложения (N)** | мысль и связь | список вложений с областью перетаскивания + область просмотра (§6.5) |
| **Связи** | мысль и связь | для мысли — разделы «Прямые связи (N)», «Упоминания», «Использование» (§6.7); для связи — две мысли-эндпоинта |
| **Хроника (N)** | мысль и связь | таблица хронологических комментариев + область просмотра/редактирования (§6.6) |

- **Ленивая загрузка.** Содержимое вкладки строится только при её активации.
  Счётчики `(N)` в заголовках вкладок «Вложения» и «Хроника» загружаются всегда
  (легковесные запросы списка), чтобы пользователю было достаточно взгляда на
  заголовки, не открывая вкладку.
- **Активная вкладка не сбрасывается** при смене фокуса или выборе связи: клик
  по мысли из «Упоминаний»/«Использования»/«Связей» переводит её в фокус, вкладка
  остаётся прежней.
- Внутри вкладок секции оформлены **сворачиваемыми группами** (каретка, заголовок,
  счётчик, действия). Состояние (свёрнута/развёрнута) запоминается для конкретной
  мысли/связи в `ui_state.editor_collapsed_groups`; если записи нет — применяется
  состояние «по умолчанию». Идентификаторы групп: `properties`, `permanent`,
  `links` (прямые связи), `mentions`, `usage`, подгруппы типов связей
  `links:type:<id>`. Счётчик `(N)` в заголовке группы отображается у «Свойств»,
  «Прямых связей», «Вложений» и «Хроники»; у «Упоминаний» и «Использования» до
  первого разворота вместо счётчика стоит `…`, после поиска — количество найденного.
- **Сплиттеры и заполнение таба.** Области таба (таблица сверху + поле
  просмотра/редактирования снизу; группы вкладки «Связи») **в сумме занимают
  всю высоту таба**: между ними горизонтальные полосы, перетаскиванием которых
  высота верхней области меняется в пределах таба — нижняя область (или
  соседние развёрнутые группы вкладки «Связи») забирает остаток. Верхняя
  область ограничена содержимым: растянуть таблицу выше её фактических строк
  нельзя, уменьшить можно примерно до одной строки. Свёрнутая группа не
  растягивается и не сжимается — её полоса недеятельна; развёрнутое
  содержимое занимает всю оставшуюся высоту таба. Размеры не персистируются
  и сбрасываются при смене мысли/связи.

#### 6.3.1. Таб «Основное»: Свойства

Таблица значений по определениям типа **без заголовков колонок** (первая колонка —
имя свойства, вторая — значение). Высота — не более 5 строк; при большем
количестве появляется вертикальная прокрутка. Группа развёрнута по умолчанию;
наполняется только когда вкладка «Основное» активна (постоянно активная по
умолчанию). Функциональность строк не меняется: для строковых свойств с
предустановленным списком — выбор из списка (одно или несколько значений), причём
подсказки открываются и фильтруются прямо при наборе текста (в режиме нескольких
значений фильтр — по последнему фрагменту после запятой; Esc откатывает к
последнему сохранённому значению), произвольный ввод остаётся доступным; для
ссылок на мысль поле ввода редактируемое и работает как живой поиск кандидатов —
с учётом отбора по типам (набранный текст сам по себе значение не меняется,
записывается только явно выбранный кандидат), кнопки «выбрать» (диалог поиска) и
«очистить» сохранены как альтернативные способы. Для свойств типа URL рядом с
полем ввода есть кнопка **«Открыть»**: значение передаётся системному
обработчику по умолчанию — http/https открываются в браузере, `file://`-адреса
и локальные пути (в т.ч. UNC) — приложением ОС, прочие зарегистрированные в
системе протоколы (`obsidian://`, `mailto:` и т.п.) — связанным с ними
приложением. Кнопка неактивна при пустом поле; клик по ней сначала фиксирует
несохранённое значение поля (как потеря фокуса). Опасные схемы (`javascript:`,
`data:`, `vbscript:`, `blob:`, `about:`) не открываются; если адрес открыть не
удалось (протокол не зарегистрирован, путь недоступен) — пользователь получает
сообщение с причиной.

### 6.4. Комментарий (постоянный)
- Группа вкладки «Основное», развёрнута по умолчанию. Заголовок группы — «Комментарий».
- Содержимое отображается сразу HTML-рендером (единый рендерер
  `@etn/markdown`, 03-server-api.md §10). Пустой текст — пустое поле
  (без надписей «нет комментария» / кнопок-заглушек).
- **Двойной клик** по полю переключает в режим редактирования markdown —
  редактор на CodeMirror 6 (фаза M) с подсветкой markdown-разметки, историей
  (Undo/Redo), автопродолжением списков и переносом длинных строк. Высота
  поля адаптируется под содержимое, но не менее 5 строк.
- **Правила live preview.** Блочные элементы (заголовок, цитата, блок кода,
  картинка, таблица) показывают markdown-исходник, пока каретка находится
  внутри блока — от первого до последнего символа; внутристрочные
  (выделение, код, ссылки, wiki-ссылки) — пока каретка внутри элемента или
  непосредственно перед/после него. Пока блок редактируется, символы
  markdown-разметки **не скрываются** (их можно удалять и изменять).
- **Единая типографика режимов.** Редактор и HTML-просмотр используют один
  и тот же стиль: шрифт интерфейса для текста (не моноширинный), общий
  моноширинный стек для кода, размеры и отступы заголовков как у h1–h6,
  рамка и цвет цитат, плашка inline-кода, единый акцентный цвет ссылок
  (обычных и wiki-ссылок, без подчёркивания до наведения). Масштаб
  Ctrl+колесо действует и на виджеты-блоки редактора.
- **Клик вне поля** (на холсте, в любой панели, в другой части редактора)
  сохраняет markdown и возвращает режим HTML-просмотра; то же делает
  **Ctrl+Enter** в режиме редактирования. `Esc` — отмена и возврат к
  просмотру без сохранения.
- **Масштаб документа**: Ctrl+колесо над полем (в режиме редактирования и
  просмотра) масштабирует все markdown-поля через общий множитель,
  независимо от масштаба холста и структур; значение запоминается на сеть.
- **Wiki-ссылки** `[[имя мысли|синоним]]`: при вводе `[[` и наборе текста
  показывается выпадающий список мыслей сети (совпадения по названиям и
  синонимам); выбор вставляет `[[имя]]`, алиас дописывается вручную после
  `|`. В HTML-просмотре ссылка отображается текстом алиаса (или имени);
  клик по ней открывает мысль: на карте — фокус и открытие в редакторе;
  в структурах — активация мысли среди отображаемых (если её там нет —
  вопрос «Переключиться на карту мыслей?», при согласии — карта, фокус и
  редактор); неактуальная мысль при настройке «скрывать неактуальное» —
  уведомление о невозможности открытия; если мысль не найдена — уведомление.
- **Блоки кода** (```язык … ```) в просмотре подсвечиваются по синтаксису
  (highlight.js, светлая и тёмная палитры); в редакторе fenced-блоки
  подсвечиваются языками CodeMirror. Длинные строки кода **переносятся по
  ширине поля** (без горизонтальной прокрутки) во всех режимах: HTML-просмотр,
  live-preview виджет редактора, исходник блока в редакторе. Блоки
  ` ```mermaid ` рендерятся как диаграммы (mermaid.js) — и в просмотре, и в
  редакторе; синтаксическая ошибка диаграммы оставляет код для правки;
  отрендеренная диаграмма шире поля скроллится внутри блока.
- **Размер картинки** задаётся в alt-тексте: `![альт|600px](url)` — ширина
  в пикселях, `![альт|600x400](url)` — ширина и высота,
  `![альт|50%](url)` — процент ширины поля просмотра; без размера картинка
  масштабируется пропорционально ширине поля.
- **Вставка картинки из буфера** (Ctrl+V в режиме редактирования, работает и в
  хронологических комментариях): файл сохраняется на сервере в
  `networks/<nid>/attachments/` рядом с БД, автоматически создаётся вложение
  сущности, а у курсора вставляется markdown-ссылка `![имя](etnimg://…)`.
- **Авто-упоминания мыслей** (L24, 03-server-api.md §21): в HTML-просмотре
  (не в редактировании) слова, совпадающие с названием мысли сети — в том
  числе с **отдельной частью составного имени**, §2.2.3, — или с любым её
  синонимом (включая wildcard `*`), подчёркиваются **пунктирной** линией (в
  отличие от сплошного подчёркивания wiki-ссылок на hover). Клик открывает
  меню: «Перейти к «…»» (как у wiki-ссылки — фокус/структуры/хроника по
  правилам режима) и «Вставить ссылку на «…»» (заменяет подчёркнутый текст на
  `[[имя мысли|подчёркнутый текст]]` в источнике и сохраняет комментарий).
  Если фрагмент текста совпадает с несколькими мыслями (до 5), каждая мысль —
  отдельный пункт меню с обеими командами. Мысль, упомянутая в своём же
  комментарии, не подчёркивается: её название и синонимы исключаются из
  проверки (на рабочем столе «Хроника» исключается первая мысль-привязка
  записи). Текст внутри ссылок — обычных `[текст](url)` и wiki — не
  проверяется и не подчёркивается: он уже оформлен ссылкой. Неактивная
  мысль-кандидат участвует, только если включена настройка «Показывать
  неактуальные»; такое совпадение показывается приглушённым начертанием (как
  неактивные владельцы в «Упоминаниях», §6.7).
- **Контекстное меню редактора** (правый клик по полю в режиме редактирования):
  показывает пункт **«Вставить текст шаблона из типа мысли»**, когда у
  редактируемой мысли `type_id !== null` и у соответствующего типа
  `comment_template_md` непустой (после `trim`). Клик вставляет markdown-текст
  шаблона в позицию курсора (`MdEditor.insertAtCaret`). Пункт не активен,
  если условия не выполнены (тогда нативное контекстное меню редактора не
  перехватывается). Содержимое шаблона подставляется в источник как есть —
  пользователь редактирует его дальше в обычном режиме. Если поле в данный
  момент в view-режиме, перед вставкой оно переключается в edit-режим с уже
  подставленным текстом шаблона.

### 6.5. Вкладка «Вложения (N)»
Две области, разделённые сплиттером (перетаскиванием меняется высота таблицы).

**Верхняя область — список вложений** (высота по умолчанию — не более 5 строк,
при большем — вертикальная прокрутка): строки с превью (файлы-картинки через
`etnimg:`, favicon для интернет-адресов, картинка для URL-ссылок на изображения,
глиф для остальных), зона перетаскивания и кнопка «Добавить вложение». Список
заполняется только при активации вкладки; счётчик `(N)` в заголовке вкладки
загружается всегда.

- **Перетаскивание** ссылки/файла в зону вложений: автозаполнение заголовка (для
  файла — имя файла; для URL — сервер best-effort подтягивает `<title>` и
  favicon при создании вложения, см. 03-server-api.md §11).
- **Вставка из буфера обмена** в поле комментария: файлы любого типа
  загружаются на сервер (`attachments/file`) и вставляются ссылкой в markdown —
  картинки как `![имя](etnimg:…)`, остальные файлы как `[имя](etnimg:…)`.
- **Кнопка «Добавить вложение»** → диалог с двумя вкладками (workplan L25):
  - **«Создать новое»** — URL/путь, заголовок, комментарий. Для типа «Файл
    (путь)» рядом с полем пути есть кнопка **«Открыть с диска…»** — системный
    диалог выбора файла: выбранный путь подставляется в поле пути, имя файла —
    в заголовок (если тот пуст). Вложение создаётся только по нажатию
    «Добавить»; при этом содержимое файла загружается на сервер
    (`attachments/file`, копия в `networks/<nid>/attachments/`, ≤10 МиБ) — как
    при вставке из буфера, а не регистрируется путь без копии.
  - **«Найти существующее»** — поле ввода + список результатов поиска по
    вложениям сети (`GET /attachments?q=…&exclude_owner_type=…&exclude_owner_id=…`,
    исключает вложения текущего владельца, синтаксис `q` как в §12). Каждая
    строка списка — как в основной таблице (превью, заголовок, мета); пустой
    результат — «Ничего не найдено». Клик по строке создаёт новое вложение у
    текущего владельца со всеми видимыми полями выбранного (kind/url/
    file_path/mime_type/title/description/file_size) — файл на сервере не
    дублируется, новая строка указывает на тот же путь. Используется, чтобы
    переиспользовать ранее добавленный файл/ссылку без повторной загрузки.
- **Клик по строке** выбирает вложение и показывает его в области просмотра;
  **двойной клик** открывает в программе по умолчанию (как и раньше). Отдельной
  кнопки удаления в строке нет — удаление через контекстное меню.

**Нижняя область — просмотр содержимого** выбранного вложения:
- **Картинки** (файлы-изображения и URL-ссылки на изображения) — простой
  просмотр с масштабированием по ширине области; у URL-ссылок на изображения
  под картинкой — кнопка «Открыть в приложении по умолчанию» (открыть
  оригинал во внешнем обработчике).
- **Текстовые файлы и markdown** — как постоянный комментарий (§6.4): режим
  просмотра (для markdown — HTML-рендер сервера), двойной клик — редактирование,
  клик вне поля — сохранение (перезапись файла, 03-server-api.md §11
  `PUT …/attachments/{id}/content`) и возврат в просмотр.
- **Прочие типы** — вместо просмотра кнопка «Открыть в приложении по
  умолчанию».
- Пока вложение не выбрано — подсказка «Выберите вложение для просмотра».

#### 6.5.1. Контекстное меню вложения (ПКМ по строке)
- **Открыть в программе по умолчанию** — файл открывается системным
  приложением (`shell.openPath`); URL передаётся внешнему обработчику по
  умолчанию (`shell.openExternal`): http/https — браузер, `file://`-адреса и
  локальные пути — приложение ОС, прочие зарегистрированные в системе
  протоколы (`obsidian://`, `mailto:` и т.п.) — связанное приложение.
  Опасные схемы (`javascript:`, `data:`, `vbscript:`, `blob:`, `about:`) не
  открываются; при неудаче (протокол не зарегистрирован, путь недоступен)
  пользователь получает сообщение с причиной. Двойной клик по строке делает
  то же самое.
- **Назначить иконкой мысли** (только картинки и только когда владелец — мысль):
  иконкой становится превью (`icon_kind='image'`, самодостаточный `data:image`
  URL ≤256 КБ — большие картинки ужимаются в превью 256×256, а не отклоняются),
  `icon_attachment_id` указывает на вложение; `Ctrl+наведение` на иконку
  показывает полную картинку из вложения (L16).
- **Перенести в мысль…** — диалог поиска мысли; вложение переезжает к выбранной
  мысли (`PATCH owner_type/owner_id`).
- **Скопировать в мысли…** (workplan L25) — диалог мульти-выбора мыслей (без
  создания новых); для каждой выбранной создаётся новая строка вложения
  (`POST /attachments/{id}/copy`) с тем же содержимым (kind/url/file_path/
  mime_type/title/description/icon/file_size). Файл не дублируется — общая
  серверная копия в `networks/<nid>/attachments/` обслуживает все ссылки,
  правило §11 «файл удаляется, только когда никем не используется» работает
  as-is. Если в целевой мысли уже есть вложение с тем же url/file_path того
  же kind — пропускается тихо. По окончании — отчёт «Скопировано в N мыслей,
  уже было в M».
- **Удалить…** — с подтверждением; серверная копия файла удаляется вместе со
  строкой (клиентские пути не трогаются).

### 6.6. Вкладка «Хроника (N)»
Две области, разделённые сплиттером. Список заполняется только при активации
вкладки; счётчик `(N)` в заголовке вкладки загружается всегда.

**Верхняя область — таблица** (высота по умолчанию — не более 5 строк, при
большем — вертикальная прокрутка):
| Заголовок | С | По | Кратко |
Клик по строке выбирает комментарий для просмотра; двойной клик — выбирает и
сразу переводит текст в режим редактирования. Кнопка «Добавить» очищает область
редактирования под новый комментарий.

**Нижняя область — просмотр/редактирование выбранного комментария**: компактная
строка метаданных (Заголовок, Дата начала, Дата окончания — пусто = бессрочно;
при создании по умолчанию С = По = сегодня) и текстовое markdown-поле, работающее
как постоянный комментарий (§6.4): HTML-просмотр, двойной клик — редактирование,
клик вне поля — сохранение и возврат к просмотру, `Esc` — отмена. Автосохранение:
первый непустой blur по тексту **создаёт** комментарий с текущими метаданными,
дальнейшие — обновляют (`If-Match`); правки метаданных сохраняются по blur.
Для существующего комментария доступна кнопка «Удалить» (с подтверждением).
После каждого изменения таблица и счётчик вкладки обновляются.

### 6.7. Вкладка «Связи»
**Для мысли** — три сворачиваемые группы, разделённые сплиттерами (высота
группы над полосой изменяется перетаскиванием). Счётчика в заголовке вкладки
нет — счётчики несут сами группы. Наполнение — только при активной вкладке.

1. **«Прямые связи (N)»** — развёрнута по умолчанию. Содержимое — как раньше:
   группировка по типам связей, безтиповые — «Источники» (родители) и
   «Назначения» (дети); заголовок противоположной мысли кликабелен — клик
   переводит её в фокус (вернуться можно через историю фокуса внизу холста).
   **Подгруппы по типам тоже сворачиваемые** (при большом количестве связей
   одного типа остальное можно сложить). Высота списка по умолчанию — не более
   15 строк, при большем — вертикальная прокрутка. Группа перестраивается при
   изменении видимого набора связей вокруг фокуса — как после собственных
   операций (действующий клиент не получает realtime-эхо, 04-realtime.md §5),
   так и по чужим `link.*`-событиям.
2. **«Упоминания …»** — свёрнута по умолчанию. Поиск выполняется только при
   первом развороте: по заголовку мысли и её синонимам (03-server-api.md §13).
   Пока поиска не было, в заголовке вместо счётчика `…`; после — количество
   найденных упоминаний. Список — не более 15 строк, при большем — прокрутка.
   Сниппеты рендерятся с подсветкой совпадений (`<mark>`), как в панели
   поиска. Клик по упомянутой мысли переводит её в фокус, по упомянутой
   связи — открывает связь в редакторе; активная вкладка при этом не меняется.
3. **«Использование …»** — свёрнута по умолчанию. При развороте выполняется
   поиск всех мыслей, в свойствах которых использована текущая мысль
   (03-server-api.md §9.1, значения `thought_ref`). Найденные мысли
   группируются по именам свойств; эти группы свёрнуты по умолчанию для
   упрощения просмотра. Клик по мысли переводит её в фокус; вкладка не меняется.

Во всех трёх списках неактуальные мысли (и владельцы-связи в «Упоминаниях»)
подчиняются настройке «Показывать неактуальные…» (L3 `show_inactive`): при
выключенной настройке скрыты, при включённой — показаны с «бледным»
начертанием, как облачка неактуальных мыслей на карте (§2.2). Смена настройки
перестраивает вкладку.

Контекстное меню строки прямых связей (L5):
- **Открыть** — переводит противоположную мысль в фокус (дубль клика);
- **Изменить тип связи…** — диалог выбора типа связи (типы сети + «без типа»,
  текущий предвыбран) → `links.update` с `type_id`;
- **Удалить связь** — с подтверждением; линия пропадает с холста, список и
  счётчик группы обновляются;
- **Удалить мысль** — удаляет противоположную мысль с подтверждением (тот же
  путь, что и меню облачка, включая локальную зачистку автора по L4).

**Для связи:** вкладка содержит единственную группу — ровно 2 записи: мысль-источник
и мысль-назначение, без группировок и сплиттеров. Клик по записи переводит её
в фокус.

### 6.8. Диалог выбора иконки
Переключатель вверху: **Эмодзи / Файл / URL**.
- **Эмодзи** — полный набор эмодзи Unicode (16.0, сгенерированный модуль
  `emoji-data.ts`; варианты тона кожи не дублируются), сгруппированный по
  классическим категориям CLDR («Смайлики и эмоции», «Люди и тело»,
  «Животные и природа», «Еда и напитки», «Путешествия и места», «Занятия»,
  «Предметы», «Символы», «Флаги»). Группы сворачиваемые (первая развёрнута),
  контент группы строится при первом раскрытии; в заголовке — название и
  количество. Клик по эмодзи устанавливает его как иконку
  (`icon_kind = 'emoji'`) и закрывает диалог.
- **Файл** — сетка иконок типов мыслей (быстрый выбор иконки типа: клик
  применяет её сразу, как эмодзи) и кнопка **«Выбрать файл…»** (системный
  диалог; файлы до лимита вложения, 10 МБ) с квадратиком предпросмотра
  (`object-fit: contain`; при некорректном файле — символ ошибки). Строки
  ввода и кнопки **ОК** внутри вкладки нет — применяет нижняя кнопка
  **«Применить»** (`icon_kind = 'image'`, содержимое — `data:` URL). Иконка
  самодостаточна и ≤256 КБ: файлы больше ужимаются в превью (256×256, L16).
  Для **мысли** оригинал дополнительно загружается во вложения
  (`icon_attachment_id`): `Ctrl+наведение` на иконку показывает полную
  картинку из вложения. Для **типов мыслей** (вложений нет) сохраняется
  только превью.
- **URL** — поле ввода URL + предпросмотр (без кнопки выбора; применяет
  нижняя кнопка **«Применить»**; `icon_kind = 'image'`, `icon` — сам URL).
- Внизу, в футере диалога:
  - **Очистить** — убирает собственную иконку (`icon = NULL`) и закрывает
    диалог; мысль отображается с иконкой выбранного типа (если она есть).
  - **Отменить** — закрывает диалог без применения изменений.
  - **Применить** — применяет выбранный файл или URL активной вкладки;
    доступна, только когда на вкладке есть корректный выбор (загруженный
    файл или URL).

### 6.9. Диалог настроек (цвета и стиль)
- **Для мысли:** цвет текста, цвет фона облачка, четыре тогла стиля шрифта
  (жирный/наклонный/подчёркнутый/зачёркнутый).
- **Для связи:** цвет линии, стиль (`solid`/`dashed`/`dotted`), толщина.
- Кнопка **Сброс** убирает все ручные настройки (выставляет соответствующие
  поля в `NULL`): мысль/связь снова отображается со стилем выбранного типа.

## 7. Перетаскивание ссылок/файлов на холст (C3)

- Допустимые цели: **верх-лево** (создаёт родителя) и **низ** (создаёт ребёнка).
  Верх-право (родственники) — **запрещённая цель**, курсор `not-allowed`.
- При броске: создаётся мысль с заголовком (имя файла или, для URL, заголовок
  страницы — клиент на MVP не ходит в интернет, заголовок берётся из названия
  файла или остаётся пустым для URL), к ней автоматически добавляется вложение.
- Множественный drop — создаётся по мысли на каждый файл/ссылку.

## 8. Меню мыслесети и пользователя (фаза Q)

С фазой Q прежнее «Меню сети» разделилось на два разных меню, чтобы не
смешивать команды уровня «программа» и уровня «мыслесеть»:

- **Подменю `[🌐 Мыслесеть ▾]`** — кнопка в левой части toolbar видов
  ([§1](#1-общий-layout)). Команды относятся к **открытой** мыслесети.
- **Подменю `[👤 User ▾]`** — кнопка в правой части верхней строки
  ([§1](#1-общий-layout)). Команды относятся к **программе в целом**
  (управление набором сетей, отключение от сервера, администрирование).

Имя текущей мыслесети **нигде не дублируется** — её показывает
подсвеченный активный таб ([§1.1](#11-tab-strip-фаза-q)).

### 8.1. Подменю `[🌐 Мыслесеть ▾]` (toolbar видов)

Состав (сверху вниз):

```
┌────────────────────────────────────────┐
│ ▸ Участники сети          (только вла- │
│                            делец)      │
│ ▸ Выйти из сети           (если не     │
│                            владелец)   │
│ ─────────────                          │
│ ▸ Типы мыслей                          │
│ ▸ Типы связей                          │
│ ─────────────                          │
│ ▸ Настройки мыслесети                  │
└────────────────────────────────────────┘
```

- **Участники сети** — диалог управления участниками текущей сети
  (список, добавление/исключение, передача владения); доступен только
  владельцу сети. Реализация — `membersDialog()` в
  `client/src/renderer/screens/workspace-menus.ts`.
- **Выйти из сети** — покинуть текущую сеть (для не-владельца;
  помечена `danger`). При успехе сервер шлёт `member.removed` —
  realtime-хендлер возвращает на экран списка сетей.
- **Типы мыслей** / **Типы связей** — открывают менеджеры типов (§8.3).
  Это настройка сети (набор типов, доступных всем её участникам),
  поэтому они живут здесь, а не в подменю пользователя.
- **Настройки мыслесети** — открывает единый диалог настроек (§9)
  сразу на разделе «Мыслесеть». Название пункта явно указывает, что
  открывается **именно раздел настроек сети**, а не настройки
  пользователя/клиента.

### 8.2. Подменю `[👤 User ▾]` (верхняя строка)

Состав (сверху вниз):

```
┌────────────────────────────────────────┐
│ ▸ Открыть сеть (список доступных)      │
│ ▸ Создать сеть                         │
│ ─────────────                          │
│ ▸ Администрирование        (если admin)│
│ ─────────────                          │
│ ▸ Отключиться                          │
└────────────────────────────────────────┘
```

- **Открыть сеть** — переход на экран списка сетей (`showScreen('networks')`),
  тот же, что открывается по табу «+» ([§1.1](#11-tab-strip-фаза-q)).
  При выборе сети создаётся новый таб через `etn.tabs.open(networkId)` и
  активируется.
- **Создать сеть** — диалог создания новой сети (`showCreateNetworkDialog`,
  `screens/networks.ts`).
- **Администрирование** — только для пользователей с `is_admin`. Открывает
  админ-панель (§10). Помещён в это подменю, т.к. администрирование —
  функция уровня «программы», а не конкретной сети.
- **Отключиться** — разрыв соединения с сервером (`etn.server.disconnect`).
  Помечена `danger`.

### 8.3. Подменю `[☰]` — «Вид»

В toolbar видов и верхней строке осталось единственное layout-меню
(`☰`, правая часть верхней строки). Состав:

```
┌────────────────────────────────────────┐
│ ▸ Показать редактор / Скрыть редактор  │
│ ─────────────                          │
│ ▸ Все настройки ⚙                      │
└────────────────────────────────────────┘
```

- **Показать/Скрыть редактор** — единственная команда уровня «программы»,
  относящаяся к раскладке workspace: тоггл видимости редактора (когда
  редактор скрыт, добраться обратно можно только через этот пункт).
- **Все настройки** (с иконкой шестерёнки `settings`) — открывает единый
  диалог настроек (§9) на разделе по умолчанию («Пользователь»). Это
  вход в диалог со **всеми** разделами — отсюда название «Все настройки».
  Не путать с «Настройками мыслесети» в подменю `[🌐 Мыслесеть ▾]`
  (§8.1): тот пункт открывает тот же диалог, но сразу на разделе
  «Мыслесеть»; здесь — на разделе по умолчанию. Тёмная тема (L10, L5
  `client_meta.theme`) живёт в разделе «Клиент» этого диалога — отдельный
  тоггл в «Вид» больше не нужен.

**Иконки хрома (L13).** Кнопки тулбара, статус-бара, панели истории фокуса,
шестерёнки настроек, каретки раскрывающихся списков и крестик закрытия
диалога используют inline-SVG (стиль lucide: штрих 2 px, скруглённые
концы, `currentColor` — цвет следует теме). Эмодзи остаются только в
контенте пользователя: иконки мыслей/типов, индикаторы 📝/📅/📎 облачек и
поповеров. Индикатор соединения в статус-баре — CSS-точка, окрашенная по
состоянию (зелёная/жёлтая/красная), с tooltip.

### 8.4. Управление типами (L6)

Диалоги-менеджеры (диалоги складываются в стек: редактор и подтверждения
открываются поверх списка).

**Список типов мыслей:** **дерево** (L21, корень всегда развёрнут, остальные
свёрнуты) «иконка · название · комментарий», иконка и название отрисовываются
с **эффективными** настройками (L21: собственные значения типа, недостающие
наследуются от предков); внутри уровня — алфавитный порядок.
Кнопка «Добавить» → редактор нового типа; в каждой строке (кроме корневой)
«✕» — удаление. Клик по строке → редактор типа; клик по ▸/▾ — развернуть/
свернуть подчинённые (редактор при этом не открывается).

**Список типов связей:** то же дерево: «имя вперёд / имя назад · комментарий»
+ образец линии с эффективным стилем (L21: с учётом наследования); те же
действия.

**Редактор типа мысли:** верхняя строка — иконка · название (обязательно) ·
⚙ (подсказка «Настройки типа»; тот же диалог цветов/шрифта, что у мысли,
§6.9, режим типа: «Сброс» возвращается к обычным значениям, т.к. у типа
шрифтовые флаги NOT NULL). Ниже — комментарий (описание типа, правила
применения) — стандартное markdown-поле (§6.4) без заголовка, только
подсказка в поле. **Ещё ниже — «Шаблон комментария»** (маркированный
лейбл `muted` поясняет: «применяется к пустому комментарию мысли при
создании/назначении типа»): стандартное markdown-поле (§6.4) — общий
`createMarkdownField`: HTML-просмотр отрендеренного через `@etn/markdown`
содержимого, по двойному клику — CodeMirror-редактор, blur/Ctrl+Enter —
коммит, Esc — отмена. Поле оформлено в той же рамке, что и остальные
markdown-поля в программе. Автосохранение на blur через
`PATCH /thought-types/{id}` с `comment_template_md` (либо `null`, если
поле очищено). Шаблон применяется клиентом к пустому постоянному
комментарию: при создании мысли этого типа (`add-dialog`) и при
назначении/смене типа у существующей мысли (combobox в шапке редактора,
пункт «Изменить тип» в контекстном меню облачка). Если permanent уже
есть — шаблон автоматически не применяется; пользователь может вставить
текст шаблона через команду контекстного меню редактора комментария
«Вставить текст шаблона из типа мысли» (§6.4). Шаблон не наследуется от
родительского типа — это явное поле на каждом типе. Ещё ниже — таблица
свойств типа. Иконка, ⚙, поле шаблона и таблица видны всегда; для ещё не
созданного типа они недоступны (поле шаблона — тот же markdown-виджет
без `onSave`, отображается как инертный read-only просмотр без рамки), а
внизу — кнопка «Создать и продолжить»: создаёт тип и открывает доступ к
настройкам, шаблону и свойствам в том же диалоге. Для существующего типа
название, комментарий и шаблон комментария сохраняются автоматически
(по потере фокуса).

Имена типов уникальны **регистронезависимо** (`Тип` = `тип` = `ТИП`): при
вводе названия, совпадающего с именем существующего типа (кроме самого
редактируемого), появляется предупреждение «Тип с таким именем уже
существует», кнопка «Создать и продолжить» становится недоступной, автосохранение
по потере фокуса не выполняется; сервер дополнительно возвращает `409
DUPLICATE` (03-server-api.md §8).

Таблица свойств типа: имя, тип значения, значение по умолчанию, ▲/▼ — порядок
(`PUT …/properties/reorder`), ✕ — удаление. Клик по строке и «Добавить
свойство» открывают **диалог свойства**: заголовок (обязательно), тип значения
(строка / число / дата / булево / ссылка на мысль / URL), значение по
умолчанию (по типу; для ссылки на мысль не задаётся). Кнопки: новое свойство —
«Добавить»/«Отменить», существующее — «Применить»/«Удалить»/«Отменить».
Смена типа значения — только после подтверждения: сервер преобразует все
значения свойства к новому типу, несовместимые очищаются; на время обработки
показывается «Ждите: выполняется обработка значений…», затем «Обработка
выполнена». Значение по умолчанию применяется только к будущему (существующие
мысли не затрагиваются). Удаление свойства удаляет его значения у всех мыслей
(после подтверждения).

Дополнительные настройки диалога свойства (по типу значения):
- **строка** — флажок «выбирать из спис»: под ним поле вариантов (по одному в
  строке) и флажок «несколько значений (через запятую)», доступный только при
  включённом выборе из списка;
- **ссылка на мысль** — «Отбор по типам»: чек-лист типов мыслей, поиск
  кандидатов при заполнении значения идёт только по отмеченным типам.

Семантика (02-data-model.md §3.4): список вариантов — подсказка ввода, а не
ограничение — произвольное значение остаётся допустимым; удаление вариантов из
списка и смена отбора по типам **никогда не трогают уже сохранённые значения** —
пользователь сам решает, что делать с «отменёнными» вариантами.

**Редактор типа связи:** верхняя строка — имена «вперёд»/«назад» (оба
обязательны) · ⚙ (тот же диалог стиля линии, что у связи, §6.9, режим
типа; «Сброс» = наследовать от родителя, L21); ниже — комментарий. С L21
редактор типа связи получил те же секции свойств, что и тип мысли
(собственные + унаследованные). Доступность и «Создать и продолжить» — как у
типа мысли. Дубли пар имён проверяются так же (регистронезависимо, пара
уникальна; перестановка имён — другой тип): предупреждение «Тип связи с
такими именами уже существует», кнопка недоступна, автосохранение по потере
фокуса не выполняется.

**Выбор типа (combobox):** везде, где выбирается тип (шапка редактора
мысли/связи, диалог добавления мысли, смена типа связи), используется
поле с поиском: ввод фильтрует каталог, строки списка несут иконку, цвета
и начертание типа (для типов связей — цветную точку линии). Клавиатура:
↓/↑ — перемещение, Enter — выбор, Esc — закрыть список.

**Иерархия типов (L21):** типы мыслей и типы связей образуют деревья под
корневым типом «основной тип»:

- Корневой тип создаётся автоматически (при создании сети/миграцией),
  неудаляем. Его настройки применяются ко всем элементам **без типа**;
  **назначать корневой тип элементам запрещено**. В диалогах менеджеров
  «Типы мыслей»/«Типы связей» корень показывается (дерево типов целиком);
  **в списках выбора** (комбобоксы редактора, диалогов добавления/команд)
  корневой тип **не показывается** — только команда «без типа» и дерево
  типов без корня (бывшие дети корня — верхний уровень).
- Вложенность ограничена **4 уровнями, включая корень**.
- Каждый подчинённый тип наследует свойства, иконку, цвета и стили шрифта
  (для связей — цвет/стиль/толщину линии) родителя; переопределяет их
  своими значениями. «Сброс» в диалоге настроек типа = наследовать от
  родителя. Свойства родителя изменить/удалить нельзя — можно только
  **переопределить значение по умолчанию** для этого типа (кнопка
  «по умолчанию…» / «сбросить» в секции унаследованных свойств).
  Свойства подчинённых типов в редакторе не видны и не учитываются.
- Списки типов (менеджеры, выбор типа, отборы) показывают **деревья**: в
  менеджерах корневой тип всегда развёрнут, остальные по умолчанию свёрнуты;
  клик по строке-родителю с ▸/▾ разворачивает/сворачивает, вложенные строки —
  с отступом. Списки выбора показывают то же дерево без корня (см. выше);
  раскрывать/сворачивать группы в них можно теми же ▸/▾, клик по
  треугольнику не влияет на фильтрацию списка.
- В редакторе типа — выбор родителя (дерево): список открывается сразу
  полностью развёрнутым, строка «без родителя» означает подчинённость
  корневому типу (корневой тип отдельной строкой не дублируется); строки
  несут иконки/цвета/стили типа (для связей — образец линии). Ввод
  фильтрует список; **очистка родителя равносильна присвоению корневого
  типа**. Пока в сети есть мысли/связи с этим типом, смена родителя
  запрещена (сообщение сервера). Удаление типа с подчинёнными типами
  запрещено (сначала удалите/переместите их).
- **Отборы по типам** (структуры, хроника, поиск, свойства «ссылка на
  мысль»): выбор родительского типа соответствует также всем его
  подчинённым типам (OR) — сервер раскрывает фильтр до поддерева.
- У мыслей **без типа** в редакторе свойств показываются свойства корневого
  типа (с пометкой источника); унаследованные свойства в списке свойств
  помечаются «из ‹тип›».

**Удаление типа:** подтверждение → `DELETE …?force=1`. У мыслей/связей этого
типа `type_id` обнуляется (сами они остаются, становятся без типа);
определения свойств типа и все их значения удаляются сервером (03-server-api.md
§8). Каталоги типов и холст обновляются сразу.

## 9. Настройки (единый диалог)

> Полный каталог настроек и их уровней (где хранится каждая) — в
> [11-settings-and-state.md](11-settings-and-state.md). Эта секция описывает
> только UI: где живёт кнопка открытия и что внутри диалога.

### 9.0. Открытие

- Меню «Вид» (☰, правый верхний угол) → пункт **«Настройки»** с иконкой
  шестерёнки (`settings`). Это единственная точка входа в настройки
  приложения. Старые отдельные пункты меню («Настройки видимости»,
  «Размер облачка», «Тёмная тема», «Настройки сети») удалены.

### 9.1. Структура диалога

```
┌──────────────────── Настройки ──────────────── × ┐
│ ┌─────────┐ ┌─────────────────────────────────┐ │
│ │Пользова.│ │ Пользователь                    │ │
│ │Мыслесеть│ │ Имя для отображения [______]    │ │
│ │Клиент   │ │ Логин [____________] (readonly) │ │
│ │         │ │                                 │ │
│ │         │ │ ...                             │ │
│ └─────────┘ └─────────────────────────────────┘ │
├─────────────────────────────────────────────────┤
│ Shift+Enter — применить, …       [Применить][Применить и закрыть][Отменить] │
└─────────────────────────────────────────────────┘
```

- Слева — sidebar навигации по разделам (Пользователь / Мыслесеть /
  Клиент), текущий раздел подсвечен.
- Справа — содержимое выбранного раздела (скроллится при длинном
  содержимом).
- Внизу — **закреплённый footer** с тремя кнопками и подсказкой про
  шорткаты; footer всегда виден при прокрутке контента.
- Заголовок диалога — «Настройки», ширина — 640 px, высота —
  естественная или ограниченная `min(85vh, 720px)` (тело скроллится).

### 9.2. Кнопки и шорткаты

| Кнопка | Шорткат | Действие |
|--------|---------|----------|
| «Применить» | **Shift+Enter** | Применяет все изменённые поля, диалог остаётся открытым. |
| «Применить и закрыть» | **Ctrl+Enter** (primary) | Применяет и закрывает. |
| «Отменить» | **Esc** (built-in close) | Закрывает без применения несохранённых изменений. |

- Кнопки «Применить» и «Применить и закрыть» **disabled**, когда ни одно
  поле не менялось (`!isDirty`). В этом состоянии шорткаты
  Shift+Enter/Ctrl+Enter — no-op.
- Во время применения (`busy`) все три кнопки и кнопки разделов
  disabled, чтобы не запустить параллельную отправку.
- Ошибка сервера показывается строкой под формой (та же
  `error-text`, что в других диалогах), без закрытия диалога — пользователь
  может исправить значение и повторить.

### 9.3. Раздел «Пользователь»

- **Имя для отображения** (`users.display_name`, L1) — однострочное
  текстовое поле, `maxLength = 200`. Пустая строка после trim сохраняется
  как `null` (отображается как «Не задано»). Редактируется через новый
  self-service `PATCH /me` (см. [03-server-api.md](03-server-api.md) §3.1.1).
- **Логин** (`users.username`) — readonly, задан при создании учётной
  записи.
- Подпись: «Имя отображается в тулбаре и других местах интерфейса. Логин
  задаётся при создании учётной записи.»

### 9.4. Раздел «Мыслесеть»

Подраздел «Настройки сети» (L2, `networks.display_name` плюс четыре
markdown-поля самоописания сети и `node_section_type_id`, задача O5):

- «Название сети» — однострочное поле, `maxLength = 200`.

- **Четыре markdown-поля** в табах (см. `05-mcp-server.md` §3):
  - «Описание» (`description`) — назначение сети в 1–2 абзацах;
  - «Когда использовать» (`when_to_use`) — список use cases и какие поля
    сети для них релевантны;
  - «Правила» (`conventions`) — правила записи: формат хронологий, пометка
    `active`, нейминг, ссылки на типы и шаблоны;
  - «Примеры» (`examples`) — хорошие/плохие записи.
  - Каждое поле — **единый view/edit-виджет** (общий `createMarkdownField`,
    тот же, что в редакторе мысли/связи и в редакторе хронологических
    комментариев): в режиме просмотра отображается отрендеренный через
    `@etn/markdown` HTML, по двойному клику открывается редактор
    (CodeMirror), коммит по blur или `Ctrl+Enter`, отмена по `Esc`.
    `maxLength = 20_000`. Под полем — текстовая подсказка о назначении
    поля. Переключение между табами не теряет черновики.
  - Все четыре поля **доступны только владельцу сети** (для остальных —
    read-only с соответствующим курсором).

- «Узловой тип раздела» — `<select>` с типами мыслей этой сети (`null` —
  без структуры). Выбор типа задаёт `networks.node_section_type_id` —
  все активные мысли этого типа становятся разделами структуры
  (`etn.networks.structure`). Тип, выбранный здесь, нельзя удалить, пока
  ссылка не снята (REST отклоняет с `VALIDATION_ERROR`).

- Применение — одним `PATCH /networks/{id}` со всеми изменёнными полями
  одной транзакцией. Подпись под табами: «Эти поля задаёт владелец сети;
  изменения сохраняются для всех участников.» (владелец) или «Эти поля
  задаёт владелец сети. Вы можете посмотреть их, но не изменить.»
  (остальные).

Подраздел «Видимость» (L3 `user_preferences.show_inactive`):

- Чекбокс «Показывать неактуальные мысли и связи в этой сети».
- Подпись: «Общая настройка для всех ваших клиентов в этой сети.»
- Поведение: при выключении неактуальные мысли исчезают с холста и из
  поиска; их связи (с активными или неактивными мыслями) тоже не
  отображаются; в редакторе связи неактивные связи/мысли скрываются.
  При включении — приглушённое отображение (см. §2.2).

### 9.5. Раздел «Клиент»

Подраздел «Тема» (L5 `client_meta.theme`):

- Два radio: «Светлая» / «Тёмная».
- Применяется сразу к `data-theme` атрибуту корня документа (через
  `etn.meta.set(CLIENT_META_KEY.THEME, …)`) и сохраняется в L5.
- Подпись: «Применяется на всех экранах. Действует только на этом
  клиенте.»

Подраздел «Размер облачка» (L4 `ui_state.cloud_width` /
`ui_state.cloud_gap`):

- «Ширина облачка, px (120–400)» — числовое поле, клиппится в
  `[CLOUD_WIDTH_MIN, CLOUD_WIDTH_MAX]`.
- «Отступ между облачками, px (4–40)» — числовое поле, клиппится в
  `[CLOUD_GAP_MIN, CLOUD_GAP_MAX]`.
- Сохранение инициирует `scheduleRefresh()`, чтобы холст пересчитал
  сетку облачков.
- Подпись: «Хранится только на этом клиенте.»

### 9.6. Применение и синхронизация

Диалог накапливает изменения в локальном «черновике» (`draft`); нажатие
любой кнопки «Применить» отправляет **только изменённые** поля:

- `displayName` → `PATCH /me { display_name }`.
- `networkName` / `networkDescription` → `PATCH /networks/{id}`.
- `showInactive` → `PUT /networks/{id}/preferences/show_inactive`.
- `theme` → `etn.meta.set(CLIENT_META_KEY.THEME, …)`.
- `cloudWidth` / `cloudGap` → `etn.ui.setState(networkId, …)`.

Все запросы выполняются параллельно через `Promise.all`; ошибка любого из
них отменяет применение (UI остаётся на текущем состоянии, сообщение об
ошибке показывается под формой). После успеха черновик пересинхронизируется
с реальным состоянием (например, пустое `display_name` нормализуется в
`null`), и `isDirty` сбрасывается.

### 11.1. История фокуса в статус-баре

> Логика хранения и правила дедупликации — в
> [11-settings-and-state.md](11-settings-and-state.md), п. 2.3. Здесь — только
> визуальное представление.

Layout (в статус-баре, рядом с индикатором сети):

```
[ ← [облачко₁] [облачко₂] [облачко₃] [▾ N] ]
```

- **Три облачка слева направо** = три самые свежие мысли из истории (облачко₁ —
  самая свежая, только что бывшая в фокусе).
- Каждое облачко — миниатюра облачка холста: иконка + заголовок, цвет/стиль
  из типа или собственной настройки мысли. Заголовок в самой панели
  обрезается до 25 символов с многоточием (если длиннее); в выпадающем
  списке — до 200 символов с многоточием. Клик по облачку → мысль переходит
  в фокус (становится `current_focus_thought_id`).
- **`[▾ N]`** — раскрывающийся список (dropdown) с остальной историей, N = кол-во
  мыслей за пределами первых трёх. Элементы — те же мини-облачка с заголовком
  (обрезанным до 200 символов с многоточием). Клик → переход в фокус.
- При N = 0 кнопки `▾` нет.
- **Пустая история** (только что открытая сеть, после HOME) — область скрыта или
  показывает заглушку «нет предыдущих мыслей».

**Поведение при клике на элемент истории:**

- Обычная смена фокуса по правилам п. 2.3: текущая фокус-мысль попадает в
  историю (в начало), выбранная из истории удаляется (становится фокусом),
  история переупорядочивается.

**Перетаскивание элементов истории:**

- Мини-облачко или пункт раскрывающегося списка перетаскивается на холст по
  правилам п. 2.3.1: обычный бросок на мысль создаёт связь, `Ctrl` —
  переподчинение, бросок в зону родителей/детей — связь с мыслью в фокусе в
  направлении зоны (при отсутствии связи она создаётся). Упорядочивание
  (`Ctrl`+`Shift`) недоступно — у элемента истории нет зоны-источника.
- Бросок перетаскиваемой мысли (с холста, из списка выделенных) на панель
  истории или её раскрывающийся список — то же, что клик по элементу истории
  (открыть перетаскиваемую мысль).

**Отображение удалённых/неактивных мыслей в истории:**

- Удалённая на сервере мысль — автоматически **удаляется из локальной истории**
  при получении `thought.deleted`. В GUI не показывается. Автор удаления не
  получает realtime-эхо (04-realtime.md §5) — его клиент выполняет ту же
  зачистку локально сразу после успешного удаления.
- **Удаление мысли, находящейся в фокусе:** фокус автоматически переходит к
  предыдущей мысли из истории (самой свежей существующей записи); если истории
  нет/она неактуальна — к первой защищённой от удаления мысли (корень HOME).
  То же восстановление применяется, когда фокус удалён другим пользователем
  (`focus-lost`).
- Неактуальная мысль — отображается в истории **только если** включён
  `show_inactive`. При выключенном — скрывается из истории (как и с холста).
- Имена в истории — только актуальные (текущий заголовок), даже если мысль была
  переименована после попадания в историю.

## 13. Технические принципы UI

- **Рендеринг холста.** На больших сетях (десятки облачков в зоне, много связей)
  DOM+SVG может тормозить; предлагаемый путь — `<canvas>` (или WebGL через
  PixiJS/Konva) для холста и связей, DOM-оверлей для облачков. Финальный выбор
  библиотеки — отдельная задача (пункт открыт).
- **Виртуализация списков** в зоне холста, в результатах поиска, в редакторе
  (большая хронология, упоминания) — обязательна.
- **CSS-переменные** для цветов/размеров с самого начала — задел под темы.
  **Темы реализованы (L10):** светлая и тёмная; тема — атрибут
  `data-theme` на корне документа, тёмная меняет только блок переменных
  (`color-scheme` переключается вместе с ним, поэтому нативные контролы и
  скроллбары следуют теме). Все цвета, встречающиеся в правилах (hover
  primary-кнопок, заливка эллипсов, бейджи, `<mark>`, backdrop диалогов,
  дефолтная линия связи), выражены переменными — прямые hex-значения вне
  `:root`/`[data-theme]` не используются. Тема хранится в L5
  `client_meta.theme` и применяется на boot до показа первого экрана.
- **Фон холста** — точечная сетка (dot grid) поверх базового цвета
  (`radial-gradient` с шагом 24 px, цвет — переменная `--canvas-dot`);
  даёт ощущение «пространства» и опору для восприятия зума (L10).
- **Микроанимации (L10):** hover-состояния кнопок, вкладок, меню и карточек
  переходят плавно (~120 мс: background/border/color/box-shadow); при
  `prefers-reduced-motion` переходы отключаются. Сдвиги transform на
  hover не используются — transform облачков зарезервирован под FLIP-анимацию
  (п. 2.8).
- **Шрифты** — системные стеки для каждой ОС.
- **Иконки (L13):** хром интерфейса (тулбар, статус-бар, история фокуса,
  кнопки-шестерёнки, каретки, × диалогов) — inline-SVG из локального модуля
  `lib/icons.ts` (без внешних ресурсов, CSP-совместимо), цвет — `currentColor`.
  Эмодзи — только контент пользователя (иконки мыслей/типов, индикаторы
  📝/📅/📎).
- **Клавиатурные команды:**
  - `Ctrl+F` — поиск.
  - На карте (фокус клавиатуры на холсте, п. 2.9): стрелки — перемещение
    курсора-рамки по облачкам; `Home`/`End` — край зоны; `Enter` — открыть
    мысль курсора в редакторе (поведение одиночного клика, п. 2.2.4);
    `Ctrl+Enter` — фокус; `Ctrl+Shift+↑/↓` — ручная перестановка в зоне.
  - `Ctrl+клик` — toggle выделения.
  - `Ctrl+=` / `Ctrl++` — масштаб холста +5% (до 200%); `Ctrl+-` — −5%
    (до 50%); `Ctrl+0` — сброс к 100% (L9). Действуют на экране сети; масштаб
    показывается в статус-баре и сохраняется (L4 `canvas_zoom`).
  - Стрелки без модификаторов — навигация по облачкам карты (п. 2.9); стрелки
    с `Alt`/`Shift` навигации не выполняют.
  - В диалогах: `Escape` — закрыть верхний диалог без применения изменений
    (эквивалент «Отмена»); нижележащие диалоги и открытые списки-подсказки
    при этом не закрываются (удержание клавиши тоже закрывает только один
    слой); `Ctrl+Enter` — закрыть с применением (эквивалент
    «OK»/«Применить»/«Сохранить», срабатывает кнопка подтверждения). В полях,
    где `Ctrl+Enter` имеет своё значение (пакетное добавление мыслей, выбор
    кандидата в поиске мысли), действует оно.
  - `Escape` — выход из диалога/снятие выделения.
  - `Ctrl+наведение` на иконку-картинку — «лупа»: всплывашка с картинкой в
    полном размере у курсора (не более 70% ширины/высоты окна). Действует на
    все иконки-изображения (история, результаты поиска, вложения, списки
    связей, картинки в комментариях); скрывается при отпускании `Ctrl`, уходе
    курсора, скролле или `Escape`. Иконка мысли, назначенная из вложения
    (L16), показывает не превью, а полную картинку вложения.
  - Полная таблица — отдельным приложением к документу.
- **Локализация.** MVP — русский. Использовать i18n-библиотеку с самого начала;
  переводы — отдельные JSON-каталоги.

## 15. Структуры мыслей — второй вид workspace (L15)

Второй взгляд на сеть: вместо фокус-холста — отбор мыслей по критериям и
обход их иерархии деревом (как дерево каталогов в проводнике). Отбор
настраивается, применяется и сохраняется под именем; раскрываются и родители,
и дети — в отличие от холста, дерево можно охватить целиком.

### 15.1. Переключатель видов (toolbar)

- Сразу после меню сети — сегмент из трёх кнопок-иконок (inline-SVG):
  «Карта мыслей» (схема-холст), «Структуры мыслей» (дерево) и «Хроника»
  (лента истории, §17). Подпись — всплывающая подсказка при наведении.
  Активный вид выделен (pressed-стиль).
- «Карта мыслей»: холст, строка поиска и весь функционал холста (п. 2–4).
- «Структуры мыслей»: вместо холста и строки поиска — пространство §15.2.
- «Хроника»: вместо холста и строки поиска — пространство §17.1.
- Панель редактора, сплиттер, статус-бар, панель выделения и **панель
  закреплённых мыслей** (§16) — общие для всех видов и не скрываются при
  переключении.
- Активный вид — L4 `active_view` ([11-settings-and-state.md](11-settings-and-state.md)
  п. 2.1): на каждом клиенте свой, восстанавливается при открытии сети.
- `Ctrl+F` действует только в виде «Карта мыслей» (строка поиска скрыта в
  остальных видах).

### 15.2. Компоновка пространства

```
┌──────────────────────────┬──────────────────────────────────────────────┐
│ Отбор (панель, ~33%)     │ Результаты (скролл)                          │
│ ┌──────────────────────┐ │ ┌──────────────────────────────────────────┐ │
│ │ Ключевые слова [...] │ │ │ [ Домашние счёта                ]  ⬤     │ │
│ │ Типы мыслей ☑…       │ │ ├─(содержит)──────────────────────────────┤ │
│ │ Свойства [+]         │ │ │   [ Счётчик электричества      ]  ⬤     │ │
│ │ Типы связей ☑…       │ │ ├─(содержит)──────────────────────────────┤ │
│ │ Сортировка [▾] [▾]   │ │ │   [ Счётчик воды              ]  ⬤     │ │
│ │ [Применить]          │ │ └─ …                                       │ │
│ │ Сохранить как [___]  │ │          [ Показать ещё ]  Показано 100 из 240│
│ └──────────────────────┘ │                                              │
└──────────────────────────┴──────────────────────────────────────────────┘
```

- Слева панель настройки отбора (~33% ширины пространства), справа — поле
  результатов. Область выделения (п. 5) при появлении сдвигает пространство
  вправо, как и на холсте.
- Граница панели — **ресайзер**: перетаскивание изменяет ширину панели
  (230..420 px), результаты занимают остальное. Ширина запоминается в
  `structures_state` (L4) и восстанавливается при входе в вид.

### 15.3. Панель отбора

Все поля панели — однообразные и компактные: одна строка на группу в
свёрнутом виде, раскрытие/диалог — только когда нужно указать значения.
Ниже — приклеенная к нижнему краю панель кнопок и блок сохранённых отборов,
остальные группы прокручиваются.

- **Ключевые слова** — текстовое поле с мини-синтаксисом (слова через пробел,
  все обязательны — AND; `*` — любое количество символов; `-слово` —
  исключение; поиск по названию и синонимам, регистр не важен,
  03-server-api.md §6.10) + кнопка очистки поля справа. При активизации поля
  — выпадающий список истории (10 последних применённых значений
  ключевых слов, клиент-локально, свежие в начале, без дублей); клик по
  записи истории подставляет её в поле. История пополняется при
  «Применить»/Enter с непустым полем.
- **Родительские мысли** (новая группа) — поле, в котором через запятую
  перечислены выбранные мысли (иконка, цвет, стиль шрифта каждой — как на
  холсте) + кнопка очистки справа. Клик по полю открывает диалог
  поиска-выбора мыслей (тот же, что при добавлении мысли на холсте, п. 4).
  Смысл отбора: остальные критерии применяются только среди мыслей,
  подчинённых любой из указанных (объединение поддеревьев по активным
  связям, глубина до 20 уровней включительно, с дедупом; сами указанные
  мысли в результат не входят). Список пуст — критерий не участвует.
- **Типы мыслей** и **Типы связей** — поле, в котором через запятую
  перечислены выбранные типы (иконка, цвет, стиль каждого) + кнопка очистки
  справа. Клик по полю открывает диалог выбора типа: строка поиска
  (фильтрует список по мере набора), чекбокс-список в несколько колонок —
  столько, сколько помещается по ширине диалога (при нехватке места —
  вертикальный скролл), отмеченные всегда вверху, остальные — по алфавиту.
  Кнопка «Применить» переносит отмеченные типы в поле панели (через запятую,
  с иконками/цветами/стилями); диалог можно закрыть без применения (Escape/
  крестик) — выбор в поле не меняется. Выбор по OR внутри списка; L21:
  каждый отмеченный тип соответствует и своему поддереву (03-server-api.md
  §6.10).
- **Свойства** — сворачиваемая группа: список условий
  `[свойство][операция][значение]` с добавлением/удалением строк (AND между
  условиями). Операции по типу значения: текст/url — «содержит/равно/в
  списке/не в списке»; число и дата — «равно/больше/меньше»; да/нет —
  «равно»; ссылка на мысль — «равно/в списке/не в списке». Редактирование
  значений — как в редакторе мысли (п. 6.3): текстовые свойства со списком
  допустимых значений (`config.options`) получают выпадающий выбор с
  фильтрацией по мере набора; ссылка на мысль — поле с живым поиском
  кандидатов (по типам из `config.allowed_type_ids`) и кнопкой «выбрать»
  (модальный пикер). Список — несколько значений, объединённых по OR;
  «+ значение» добавляет строку, не теряя введённого. В свёрнутом виде, если
  заданы условия, заголовок группы — жирным шрифтом и цветом акцента.
- **Дополнительно** (новая сворачиваемая группа) — пять списков выбора:
  «Свойства», «Комментарий», «Вложения», «Хроника» — со значениями
  «есть» / «нет» / «не важно» — и «Актуальность» со значениями
  «актуальные» / «не актуальные» / «не важно». «Есть» — у мысли есть хотя бы
  одно значение свойства / постоянный комментарий / вложение / хроникальная
  запись соответственно; «нет» — обратное; «не важно» — критерий не участвует
  в отборе. «Актуальность» ограничивает отбор актуальными/неактуальными
  мыслями и доступна только при включённой настройке «Показывать
  неактуальное» (иначе — заблокирована с подсказкой). Условия объединяются
  по AND с остальными (03-server-api.md §6.10, поля `has_properties`/
  `has_comment`/`has_attachments`/`has_chronology`/`active`).
- **Маркировка групп**: заголовок любой группы, у которой заданы значения
  (непустые ключевые слова, выбранные мысли/типы, условия свойств, значения
  «Дополнительно»), — жирным шрифтом и цветом акцента, свёрнута группа или
  нет — единое оформление, чтобы видно было, что в свёрнутой группе что-то
  установлено. «Сортировка» всегда имеет значение и не маркируется.
- **Сортировка** — `alpha|created|viewed` × `asc|desc`.
- Нижняя приклеенная панель:
  - строка **«Применить»** (выполняет отбор; также Enter в поле ключевых
    слов; выбор сохранённого отбора применяется сразу), **«Очистить»** рядом
    на одной строке — сбрасывает все критерии отбора, кроме
    «Сортировка», — и кнопка **«Команды ▾»** (при нехватке ширины панели
    переносится на следующую строку) — меню массовых команд отбора (§15.3.1);
  - следующая строка — поле **«имя отбора»** и кнопки **«Сохранить»**,
    **«Удалить»**. При активизации поля — выпадающий список сохранённых
    отборов (сервер, L3) с поиском по набору символов; клик по записи
    подставляет имя в поле **и применяет отбор**. «Сохранить» — создаёт
    отбор под введённым именем или обновляет существующий с этим именем;
    «Удалить» — удаляет отбор с введённым именем (после подтверждения).
    Контекстное меню записи списка (переименовать/удалить) — как раньше.
    Отборы доступны с любых клиентов пользователя, синхронизируются
    real-time (`saved-filter.*`).
- Текущее состояние панели (критерии + сортировка + выбранный сохранённый
  отбор + ширина панели) — L4 `structures_state`: сохраняется на клиенте и
  автоматически восстанавливается при переключении в вид «Структуры».
- **Пустой отбор** (нет критериев) и «очистка отбора» возвращают начальную
  мысль сети — HOME (создаётся с сетью, защищена от удаления, показывается
  первой) — и всех «сирот»: мысли без родительских связей (нет active-связи,
  где мысль — цель). Сироты идут за HOME в выбранной сортировке; неактуальные
  сироты показываются только при включённой настройке «Показывать
  неактуальное».

### 15.3.1. Команды по отбору

Кнопка **«Команды ▾»** (строка «Применить»/«Очистить») открывает меню
массовых команд. Каждая команда применяется ко **всем мыслям последнего
применённого отбора — без учёта пагинации** результатов (id собираются
серверным запросом `ids_only`, 03-server-api.md §6.10; команды действуют на
применённый отбор, а не на черновик полей панели). Пустой отбор — тоже отбор:
команды действуют на HOME и сирот (защищённая HOME возвращается в списке
неудач). По завершении показывается уведомление («Применено к N мыслям» /
число неудач с первой причиной), дерево результатов перезапрашивается.

- **добавить к выделенным** — все мысли отбора попадают в панель выделения
  (п. 5, дубликаты пропускаются);
- **удалить из выделенных** — убрать мысли отбора из панели выделения
  (отсутствующие игнорируются);
- **сделать актуальными** / **сделать неактуальными** — групповая операция
  `set_active`/`set_inactive`;
- **изменить тип мыслей…** — диалог выбора типа мысли (тот же, что в панели
  выделения, п. 5.4, с пунктом «Без типа»); выбранный тип применяется ко всем
  отобранным;
- **добавить родительские мысли…** — диалог выбора мыслей, допускающий и
  **создание новых** (тип мысли из диалога применяется только к новым,
  существующие не меняются); создаются связи `выбранная → каждая отобранная`
  с типом связи из диалога (по умолчанию — без типа; уже связанная пара не
  меняется);
- **сделать единственными родителями…** — тот же диалог (с созданием новых),
  затем подтверждение: у каждой отобранной удаляются **все** входящие связи,
  кроме связей с выбранными; недостающие связи с выбранными создаются с
  типом связи из диалога (по умолчанию — без типа);
- **разорвать связи с родителями…** — диалог выбора **существующих** мыслей
  (создание новых и выбор типов запрещены), затем подтверждение: удаляются
  все связи отобранных с выбранными мыслями (любого типа);
- **добавить подчинённые мысли…** — аналогично родительским, связи
  `отобранная → выбранная` (с созданием новых и типом связи);
- **разорвать связи с подчинёнными…** — аналогично: диалог только из
  существующих, удаляются все связи отобранных с выбранными подчинёнными;
- **удалить** — после подтверждения (с числом мыслей) групповое удаление;
  защищённая HOME возвращается в списке неудач.

Разрушительные команды («единственные родители», оба «разорвать…»,
«удалить») требуют подтверждения с числом затрагиваемых мыслей. Массовые
операции со связями выполняются одной групповой командой
(03-server-api.md §6.6).

### 15.4. Результаты

- Облачка мыслей в столбик — **такие же, как на холсте, 1-в-1**: та же
  ширина (`cloud_width × zoom`), компоновка, иконка, стиль типа, 1–3 строки
  заголовка, строка индикаторов (постоянный комментарий 📝 / хроника 📅 /
  вложения 📎 с тем же lazy-обновлением), эллипсы, `.dim` для неактуальных.
- Эллипсы корней закрашиваются **сразу после отбора** — ответ запроса несёт
  `directions` для всей страницы (03-server-api.md §6.10), ждать раскрытия не
  нужно.
- Порция — 100 мыслей; при `total` больше выведенного — кнопка
  **«Показать ещё»** (+100) и подпись «Показано X из Y».
- Клик по облачку открывает мысль в редакторе **без смены фокуса холста**
  (фокус и история холста не затрагиваются); мысль получает ореол подсветки
  (§15.7) и попадает в историю вида (§15.9).
- Real-time: изменения мыслей/связей/значений свойств инициируют перезапрос
  текущей страницы; раскрытия дерева сохраняются.

### 15.5. Дерево раскрытия

Каждая видимая строка — полноценный узел: оба её эллипса работают в обе
стороны независимо, у любой мысли (корня, потомка, раскрытого родителя).

- Клик по **нижнему эллипсу** — под узлом появляются его непосредственные
  дети (сдвиг вправо на один уровень отступа), как раскрытие папки в
  проводнике. Работает и для раскрытого родителя: его дети появляются под
  ним на уровень отступа ниже него. Повторный клик — скрыть детей (и всё,
  что раскрыто ниже них). Раскрытие рекурсивно: дети могут дальше
  раскрывать своих детей, каждый уровень — ещё один отступ вправо.
- Клик по **верхнему эллипсу** — сама мысль и уже раскрытое под ней
  поддерево детей смещаются вправо примерно на **1/4 ширины облачка**;
  выше, на один структурный уровень отступа левее (столбец её родителей),
  появляются её непосредственные родители, ещё не показанные в ветке.
  Повторный клик по тому же эллипсу — скрыть список родителей (и всё, что
  раскрыто выше по цепочке предков этого узла).
  Раскрытие рекурсивно вверх: клик по верхнему эллипсу мысли, уже
  показанной в списке родителей, **сдвигает и её саму** — со всем, что
  раскрыто ниже неё (исходный узел и его потомки) — ещё на один шаг вправо,
  а её собственные родители появляются выше в её столбце. Несколько
  поколений предков образуют «лестницу» вверх-вправо: каждый уровень — своя
  ступень, мысли каждого раскрытия выровнены вертикально; раскрытие
  следующих поколений не ломает геометрию, уже видимую ниже.
- **Каждый эллипс — только своя зона**: верхний эллипс показывает/скрывает
  исключительно родителей этой мысли, нижний — исключительно её потомков;
  сворачивание одного направления не трогает другое направление узла и его
  поддерево.
- **Клик по эллипсу (и Ctrl+↑/Ctrl+↓, §15.10) только раскрывает/сворачивает
  направление**: мысль не открывается в редакторе, не получает ореол (§15.7)
  и не попадает в выделение — побочная активация мысли вызывает повторный
  рендер дерева, который убивает анимацию раскрытия.
- **Если новых мыслей нет** (все соседи уже показаны в ветке — дедуп), клик
  по эллипсу ничего не меняет (без сдвига и без пустого раскрытия).
- Эллипсы закрашены, если у мысли есть соответствующие связи (как на холсте).
- **Анимация раскрытия/сворачивания**: изменение состава дерева
  анимируется (FLIP) — «кликнутая» мысль с потомками плавно отъезжает
  вправо, вновь раскрытые строки проявляются, а скрываемые растворяются
  на месте (и наоборот при сворачивании) — иначе не видно, что именно
  изменилось.
- **Пагинация по узлу**: сервер отдаёт не более 100 соседей за раскрытие
  одного направления (03-server-api.md §6.11); если соседей больше — под
  списком родителей/детей этого узла появляется кнопка **«Показать ещё»**
  (+100, `offset` следующей страницы), а не просто метка усечения.
- **Дедуп в пределах ветки**: при раскрытии узла из его соседей исключаются
  мысли, уже показанные в ветке того же корневого результата (`exclude_ids`
  в 03-server-api.md §6.11). Между разными корнями дедупа нет: мысль может
  показываться и в детях корня A, и в детях корня B.
- **Рамки ветвей**: вокруг каждого результата отбора и всего, что раскрыто
  под ним и над ним, рисуется тонкая рамка — после раскрытия нескольких
  уровней видно, какие родители/потомки относятся к какому результату.
- **Маркер результата**: сами отобранные мысли помечаются оранжевым
  треугольником слева от облачка — сразу видно, что было отобрано изначально.

### 15.6. Связи в дереве

- Связи рисуются **как на карте мыслей** (п. 2.4): для каждой активной связи,
  оба конца которой видны **внутри рамки одного результата отбора** — плавная
  кривая от **нижнего эллипса** источника к **верхнему эллипсу** назначения
  (та же геометрия Безье, цвет/стиль/ширина линии — переопределение самой
  связи, иначе цепочка типа). Связи между мыслями из разных рамок не
  рисуются — рамка результата остаётся визуальным контекстом.
- Линии лежат под облачками, интерактивна только видимая часть кривой;
  **при наведении** связь утолщается, подсвечивается (`--warn`) и
  **всплывает над облачками** вместе с подписью; то же — у выделенной
  связи (sticky, сброс — клик по пустому месту).
- **Наведение на эллипс** поднимает над облачками все связи этой мысли.
- Несколько связей одной пары — одна линия, толщина растёт с числом связей;
  подпись «Тип ×N»; клик по линии открывает связь в редакторе (несколько —
  меню выбора).
- Подпись названия типа — **от источника к назначению** (`name_forward`;
  «—», если тип не задан), видна только у приподнятой/выделенной линии.
- Контекстное меню связи — то же, что на холсте (п. 2.4).

### 15.7. Подсветка активной мысли

- Мысль, открытая в редакторе из вида «Структуры», обводится рамкой-ореолом
  вокруг облачка — той же, что у открытой в редакторе мысли на карте
  (п. 2.2.4). Сквозная горизонтальная полоса не используется.
- Ореол гаснет при открытии связи (подсвечивается связь) и при смене
  активной мысли.

### 15.8. Выделение и контекстные меню

- `Ctrl+клик` по облачку — toggle выделения; `Ctrl+клик` по эллипсу —
  добавить всех родителей/детей — те же правила, панель и групповые
  операции, что на холсте (п. 5). Выделение общее для обоих видов.
- Контекстное меню мысли — то же, что на холсте (п. 2.6); «Открыть
  редактор» в этом виде открывает мысль в редакторе без смены фокуса.
- **«Найти на карте мыслей»** (L23) — дополнительный пункт сразу после
  «Открыть редактор»: открывает вид «Карта мыслей» с фокусом на этой мысли
  (обычная смена фокуса — анимация, история фокуса). В остальных
  контекстных меню мысли (холст, панель выделения, закреплённые) пункта нет.

### 15.9. История посещённых мыслей вида

- У каждого вида своя история (L4, локальная): на холсте — мысли, побывавшие
  в фокусе (п. 11.1); в «Структурах» — мысли, открываемые в редакторе.
- Панель истории в статус-баре показывает историю активного вида; клик по
  чипу в «Структурах» открывает мысль в редакторе (без смены фокуса).
- **Применение нового отбора** («Применить», Enter в ключевых словах, выбор
  сохранённого отбора) **очищает историю «Структур»** — старые записи могут
  не попадать в новые условия отбора, и их нельзя открыть/выделить из
  дерева.
- Лимит и правила уникальности — как у истории фокуса (50, свежие в начале);
  удалённая на сервере мысль исчезает из обеих историй.

### 15.10. Клавиатурная навигация по дереву

Дерево ведёт себя как дерево папок в проводнике (у каждой мысли может быть
несколько родителей), поэтому курсор — пунктирную рамку — стрелки двигают
**последовательно по видимому порядку дерева** (плоский порядок строк:
родители выше своего узла, дети ниже), а не по геометрии. Навигация
доступна, пока клавиатурный фокус на поле результатов.

- **↑ / ↓** и **Tab / Shift+Tab** — на предыдущую/следующую видимую строку
  в порядке дерева (при первом нажатии без курсора — на первую строку).
- **→** — раскрыть детей курсорной мысли (если они есть и не раскрыты, как
  клик по нижнему эллипсу, §15.5); если детей нет или они уже раскрыты —
  на следующую строку.
- **←** — свернуть детей курсорной мысли; если они не раскрыты — свернуть
  родителей; если и их нет — на предыдущую строку.
- **Ctrl+↑** — раскрыть/свернуть родителей курсорной мысли (то же, что клик
  по верхнему эллипсу, §15.5).
- **Ctrl+↓** — раскрыть/свернуть детей курсорной мысли (клик по нижнему
  эллипсу).
- **Home / End** — на первую/последнюю видимую строку дерева.
- **Enter** — открыть мысль курсора в редакторе (как клик); **Escape** —
  снять рамку курсора.
- Ручного упорядочивания и отдельного «фокуса» у этого вида нет — **Ctrl+Enter**
  и **Ctrl+Shift+↑/↓** здесь не действуют.

## 16. Закреплённые мысли (L18)

Панель быстрого перехода: пользователь закрепляет мысли, чтобы открывать их
одним кликом из любой точки приложения. Список хранится на **сервере**
(уровень L3, пользователь × сеть: `user_pinned_thoughts`,
[02-data-model.md](02-data-model.md) §3.10.6; API — [03-server-api.md](03-server-api.md)
§19) и синхронизируется между клиентами пользователя событием
`pinned-thoughts.updated` (`audience=user`).

### 16.1. Компоновка

- Панель — на верхней строке приложения (toolbar), **сразу справа от кнопок
  «Карта мыслей»/«Структуры мыслей»**; видна в обоих видах и занимает **всю
  свободную ширину тулбара** (до меню пользователя) — это одна большая цель
  броска. От краёв панели до чипов — отступы, между чипами — зазоры, в
  которые можно вставить мысль перетаскиванием.
- Закреплённые мысли — чипы в одну строку: иконка мысли + заголовок
  (обрезанный до **64 символов**), цвета/стиль мысли (из типа или собственных
  настроек), полный заголовок — в tooltip. Неактуальная мысль — приглушена
  (`.dim`), как в истории.
- Если все закреплённые не помещаются в строку — остальные уходят в
  выпадающий список «▾ N» (как «Остальная история», п. 11.1); список
  открывается под панелью.
- Пустой список — заглушка «📌 закрепите мысль» **без рамки**: рамка панели —
  это подсветка перетаскивания и появляется только под перетаскиваемой
  мыслью (§16.3).

### 16.2. Закрепление и открепление

- Команда **«Закрепить мысль»/«Открепить мысль»** — в контекстном меню мысли
  во всех отображениях (холст, выделение, структуры, история, сама панель,
  п. 2.6). Закрепление добавляет мысль в конец списка.
- **Максимум 20** закреплённых. При попытке закрепить сверх лимита —
  сообщение о превышении с предложением сначала открепить лишние (сервер
  дополнительно отклоняет список длиннее 20: `422 VALIDATION_ERROR`).
- Дубли не допускаются: закрепление уже закреплённой мысли перемещает её
  (в контекстном меню такой мысли команда показывает «Открепить»).

### 16.3. Перетаскивание

- **Бросок мысли на панель** (между чипами, в начало или в конец) закрепляет
  её ровно в это место; закрепление уже закреплённой мысли = перемещение
  (реордер). Строки выпадающего списка «▾ N» — такие же цели.
- Пока мысль перетаскивают над панелью, панель подсвечивается рамкой, а
  **тонкая вертикальная метка** между чипами показывает место вставки;
  рамка и метка исчезают, когда перетаскивание заканчивается или уходит с
  панели.
- **Вынос из панели** — по стандартным правилам п. 2.3.1 (связь с мыслью,
  `Ctrl` — переподчинение, бросок в зону — связь с фокусом, бросок в
  выделение — добавить в выделение, в историю — открыть). При этом
  **из панели закреплённых мысль не удаляется** — открепление только
  командой меню.
- Источники перетаскивания: чипы панели и строки её выпадающего списка
  (как чипы истории, п. 11.1), а также облачка холста любой зоны и
  фокус-облачко (п. 2.3.1).

### 16.4. Выбор закреплённой мысли

- **На карте мыслей** клик по чипу помещает мысль в фокус и открывает в
  редакторе (как клик по облачку холста).
- **В структурах мыслей** клик открывает мысль в редакторе (без смены
  фокуса холста); если мысль есть среди видимых отобранных — она
  подсвечивается полосой активной мысли (§15.7), если нет — подсветка
  снимается с прежней активной мысли.
- Правый клик по чипу — то же контекстное меню мысли (п. 2.6).

### 16.5. Видимость и удаление

- Неактуальные закреплённые скрываются при выключенной настройке
  «Показывать неактуальное» и показываются приглушённо при включённой
  (п. 9).
- Удалённая мысль покидает панель: запись в таблице удаляется каскадом, чип
  убирается по `thought.deleted` (автор удаления — локально по ответу
  `DELETE`).

## 17. Хроника: третий рабочий стол (L20)

Вид-лента всех хронологических комментариев с их привязками к мыслям и
связям. Панель выделенных мыслей и редактора мысли/связи остаются на месте;
вид меняет только пространство холста/структур (§15.1). Нижняя область
просмотра/редактирования — как вкладка «Хроника» редактора (§6.6), с
отличиями: чипы всех привязок записи (с контекстным меню) и подсветка
включённых ключевых слов отбора в режиме просмотра.

### 17.1. Компоновка

```
┌─ Панель отбора (4 строки) ──────────────────────────────────────────────┐
│ [Сохранённые отборы ▼] [Период с][дата] [по][дата] [строка поиска: …]   │
│ Мысли: [чип×][чип×]… [Выбрать…] [Очистить]  ☑ +подчинённые мысли        │
│ [типы мыслей ▼] [типы связей ▼] [способ отбора по связям ▼]             │
│ Сортировка [возр/убыв ▼] [Применить] [Очистить отбор] [имя] [Сохранить] [Удалить] │
├─ Таблица хронологических комментариев ──────────────────────────────────┤
│ С | По | Заголовок | Мысли/связи | Кратко                                 │
│ …                                                                        │
├─ Пагинация: [≪][‹] Записи X–Y из Z [›][≫] ───────────────────────────────┤
├─ Область просмотра/редактирования записи ────────────────────────────────┤
│ [Заголовок] [с] [по] [Удалить]   (чипы привязок)                          │
│ markdown-текст (просмотр/правка)                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

В статус-баре — панель истории этого вида (п. 17.8).

### 17.2. Панель отбора

- **Сохранённые отборы** — список выбора; выбор отбора заполняет все
  настройки и автоматически применяет их (таблица обновляется).
- **Период с / по** — границы дат записей; стоят на первой строке между
  списком отборов и строкой поиска.
- **Строка поиска** — как строка поиска на карте (§3): символы `*` и
  `-слово`; ключевые слова ищутся в заголовках мыслей, синонимах,
  постоянном и хронологических комментариях мыслей и связей. Слово,
  найденное только в комментарии связи, отбирает обе стороны связи.
- **Мысли** — одна или несколько мыслей, выбранных в универсальном диалоге
  выбора мыслей (кнопка **«Выбрать…»**, §4: без создания новых, выбранные
  предзаполняют список; Enter/клик — добавить в список, Ctrl+Enter —
  применить); выбранные перечислены чипами, кнопка **«Очистить»** убирает
  все. Флажок **«+подчинённые мысли»** добавляет подчинённых до 20 уровня
  включительно с контролем дублей.
- **Типы мыслей** и **типы связей** — один или несколько типов, выбираются
  галочками в списке (диалог-чек-лист; «Очистить» снимает все).
  **Способ отбора по связям** — «только источники связей / только
  назначения связей / источники и назначения связей».
- **Сортировка** — «по возрастанию / по убыванию» (колонки «с» + «по» +
  заголовок), на одной строке с кнопками действий.
- **Применить** — применяет отбор и обновляет таблицу; срабатывает по
  `Ctrl+Enter`; очищает историю вида (п. 17.8). По настройкам отбора
  отбираются **мысли**, а уже по ним строится таблица.
- **Очистить отбор** — очищает все поля отбора.
- **Имя отбора** + **Сохранить отбор** — сохраняет настройки под именем;
  если имя уже существует — отбор перезаписывается. **Удалить отбор** —
  удаляет выбранный сохранённый отбор. Хранятся на сервере (L3,
  `view="chronicle"`, синхронизация `audience=user`).

### 17.3. Таблица

- Колонки: **с**, **по**, **заголовок**, **мысли/связи**, **кратко**
  (фрагмент тела). Сортировка всегда «с» + «по» + заголовок в направлении
  переключателя.
- **«с»** отображается серым, если дата начала лежит за пределами
  заданного периода; **«по»** — серым, если дата окончания за пределами
  периода (или открыта при заданном «по»).
- **Мысли/связи** — все привязки записи (их может быть несколько). Мысли —
  с иконками и форматом как в прочих списках (неактуальные — приглушённо);
  связь — в виде `<Мысль-источник> — тип связи (если есть) — <Мысль-назначение>`.
  Шапка таблицы зафиксирована и не скроллится с телом; все строки всегда
  одной высоты (одна строка): чипы колонки «мысли/связи» не переносятся,
  выходящие за ширину колонки обрезаются (достижимы клавиатурой).
- Пагинация по 50 записей; внизу — «Записи X–Y из Z» и кнопки `≪ ‹ › ≫`.
- Выделенная строка подсвечивается; при выделении обновляется нижняя
  область (поля и текст комментария).
- Навигация клавиатурой: стрелки ↑/↓ — по строкам; ←/→ — по колонкам
  (в колонке «мысли/связи» — по всем мыслям и связям); Tab — следующая
  колонка; Enter — открыть выбранную мысль/связь.
- Клик по мысли/связи в колонке «мысли/связи» открывает её в панели
  редактора (фокус холста не меняется).
- Контекстное меню строки: **Добавить** (новая запись; привязки — мысли из
  поля «мысли» отбора без подчинённых, иначе начальная (защищённая) мысль
  сети; даты «с» и «по» — сегодня), **Копировать** (копия записи с теми же
  привязками и текстом; даты — сегодня), **Удалить** (с подтверждением).
- Контекстное меню чипа: **Открыть** (в редакторе), **Отвязать** (удаляет
  привязку; если не остаётся ни одной — запись автоматически привязывается
  к начальной мысли сети), **Связать с…** (диалог выбора мысли;
  добавление связей не рассматривается), а для мыслей —
  **Добавить к выделению / Убрать из выделенных**.

### 17.4. Перетаскивание

- В таблицу перетаскиваются мысли из панели выделенных, истории мыслей и
  панели прикреплённых: на строку — мысль привязывается к записи этой
  строки (дубли не допускаются); на шапку таблицы или пустое место (вне
  строк) — создаётся новая запись с этой привязкой; на панель отбора —
  мысль добавляется в поле «мысли» отбора.
- Из таблицы перетаскиваются мысли (не строки и не связи) — в панель
  выделенных и в панель закреплённых.

### 17.5. Нижняя область просмотра/редактирования

- То же, что вкладка «Хроника» редактора (§6.6): заголовок, даты «с»/«по»,
  markdown-текст (просмотр — по клику, правка — по двойному; автосохранение
  по blur, Esc — отмена), кнопка «Удалить».
- Дополнительно — чипы всех привязок записи с контекстным меню чипа
  (п. 17.3) и их редактирование вживую.
- Если в настройках отбора заданы ключевые слова, в режиме просмотра
  текста они подсвечиваются.

### 17.6. Realtime

- Таблица обновляется по событиям `comment.created/updated/deleted` и
  изменениям мыслей/связей (подписка, как у структур §15). Выделение
  строки сохраняется, пока запись существует.

### 17.7. Состояние вида (L4)

- Критерии отбора, страница и выбранный сохранённый отбор — L4
  `chronicle_state` ([11-settings-and-state.md](11-settings-and-state.md)
  п. 2.1); восстанавливаются при входе в вид.

### 17.8. История посещённых мыслей и связей вида

- Внизу — панель истории мыслей и связей, открывавшихся в редакторе в этом
  виде; аналогична панели истории структур (§15.9), но хранит и связи
  (чипы «источник → назначение»). Отдельная L4-таблица `chronicle_history`.
  При каждом «Применить» история очищается.
- Клик по записи истории открывает мысль/связь в редакторе; чипы мыслей —
  источники перетаскивания (как §11.1).
