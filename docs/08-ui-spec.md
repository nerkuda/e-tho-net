# 08. Спецификация пользовательского интерфейса

> Документ систематизирует описание UI из исходного замысла (`Мой аналог
> TheBrain.md`) и инженерных уточнений. Сохранена терминология словаря (см.
> [10-glossary.md](10-glossary.md)).

## 1. Общий layout

```
┌───────────────────────────────────────────────────────────────────────┐
│ [Меню сети ▾] [Поиск... ___________________] [⚙]    [👤 User]  [Статус]│ ← toolbar
├──────────┬──────────────────────────────────────────────────┬─────────┤
│          │   ↰ родственные (родители родителей)              │         │
│  Список  │  ┌─────────────────────────────────────────────┐  │         │
│ выделен. │  │  источники (родители)      │ родственники    │  │ Редак-  │
│          │  │                            │                 │  │ тор     │
│          │  ├────────────────────────────┴─────────────────┤  │ мыс-    │
│          │  │              [  ФОКУС-МЫСЛЬ  ]                │  │ ли/     │
│          │  │                                              │  │ связи   │
│          │  ├──────────────────────────────────────────────┤  │         │
│          │  │   назначения (дети)                          │  │         │
│          │  └─────────────────────────────────────────────┘  │         │
│          │                                                    │         │
├──────────┴────────────────────────────────────────────────────┴─────────┤
│ Статус-бар: 🟢/🟡/🔴 • сеть • фокус • кол-во мыслей • последнее событие    │
└───────────────────────────────────────────────────────────────────────┘
```

- **toolbar** — переключатель сети, строка поиска, шестерёнка опций поиска,
  пользователь, индикатор статуса соединения.
- **Список выделений** (слева) — появляется, когда в списке есть хотя бы одна
  мысль.
- **Холст** (центр) — четыре зоны (см. п. 2).
- **Редактор** (справа по умолчанию) — положение настраивается: слева / сверху /
  снизу / скрыто.

## 2. Холст

### 2.1. Зоны

| Зона | Содержание | Сортировка | Ручной порядок |
|------|------------|------------|----------------|
| **Центр** | мысль в фокусе | — | — |
| **Верх-лево** | источники связей фокуса (родители) | да | да |
| **Верх-право** | родственники (мысли с тем же родителем) | да | нет |
| **Низ** (во всю ширину) | назначения связей фокуса (дети) | да | да |

> Замечание к исходному тексту: в документе верх-право названо «родственники,
> имеющие тех же родителей». Реализация: `DISTINCT siblings` = мысли,
   являющиеся дочерними по связи к любому из родителей фокуса (исключая сам
   фокус). Если у фокуса несколько родителей — родственники объединяются из
   всех.

**Исключительность зон.** Мысль отображается **не более чем в одной зоне**
(граф может содержать циклы и перекрёстные связи, поэтому сосед может
попадать в несколько списков). Приоритет зоны:

1. мысль в фокусе — не отображается ни в какой зоне;
2. источники связей (верх-лево) — исключаются из остальных зон;
3. назначения связей (низ) — исключаются из верх-право;
4. верх-право — только мысли, подчинённые родительским и не попавшие
   ни в одну из других зон.

Рёбра окрестности при этом рисуются по всем видимым мыслям независимо от
зоны, так что связи с «другой ролью» мысли не пропадают.

### 2.1.1. Виртуальная сетка

Зоны верх-лево, верх-право и низ представляются как **таблицы с ячейками
одинакового размера**. Каждая ячейка содержит одно облачко. Это упрощает
визуализацию и ручное упорядочивание.

- **Размер ячейки:**
  - ширина = `cloud_width` (настраивается пользователем, L4);
  - высота = высота облачка (3 строки + эллипсы, см. п. 2.2.1);
  - плюс отступ `cloud_gap` (настраивается, L4) между ячейками.
- **Количество видимых облачков** в зоне вычисляется автоматически:
  `cols = floor(zone_width  / (cloud_width  + gap))`,
  `rows = floor(zone_height / (cloud_height + gap))`.
- Если мыслей в зоне больше, чем видимых ячеек — возникает прокрутка (см. п. 2.5).
  Сетка виртуальная: рендерятся только видимые + небольшой запас.
- Позиция в сетке = **порядок** мысли в зоне (см. п. 2.7). Свободных (x, y)
  координат нет — только позиция в упорядоченном списке.
- Ручное упорядочивание = перетаскивание облачка на другую позицию, что меняет
  `position` в `user_focus_order` ([11-settings-and-state.md](11-settings-and-state.md),
  п. 3).

> Центральная зона (фокус) **не** является частью сетки — фокус-облачко
> размещается по центру холста и имеет собственные правила размера (см. п. 2.2.2).

### 2.2. Облачко мысли

Структура одинакова для всех облачков; различаются только правила размера — у
простых облачек (в зонах) размер фиксирован, у фокус-облачка — переменный.

```
      ▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄▄      ← верхний эллипс (один, вытянутый по горизонтали;
   ┌──────────────────────┐     утолщённая верхняя граница облачка)
   │ ┌──┐ Заголовок       │
   │ └──┘ может быть      │   ← квадрат иконки слева, 2 строки заголовка справа
   │ 📝 ♣ 3 📅 2 📎 1     │     ← строка индикаторов (шрифт мельче)
   └──────────────────────┘
      ▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀      ← нижний эллипс (тот же принцип, снизу)
```

Верхняя и нижняя стороны рамки облачка **раздуваются в вытянутые по горизонтали
эллипсы** — это и есть индикаторы связей и одновременно точки drag/прикрепления
линий (см. п. 2.3 и 2.4). Каждый эллипс — **один**: закрашен, если есть
соответствующие связи, иначе прозрачен (визуально — почти плоская граница).

**Состав (общий для всех облачков):**
- **Верхние 2 строки** — квадрат иконки **слева**, заголовок справа от неё.
  Иконка — эмодзи или картинка (см. словарь). Квадрат иконки фиксированного
  размера (системная константа); его сторона ≈ высоте двух строк.
- **Нижняя 1 строка** — индикаторы (шрифт мельче верхних строк):
  - `📝` — есть постоянный комментарий. Серая, если постоянного нет. Кликабельная —
    открывает редактор на группе постоянного комментария.
  - `📅 N` — хронологические комментарии, число = кол-во. Кликабельно — разворачивает
    список хронологии в редакторе.
  - `📎 N` — вложения, число = кол-во.
- **Эллипсы сверху/снизу** — вытянутые горизонтально утолщения верхней/нижней
  сторон рамки; индикаторы входящих/исходящих связей и точки drag (см. п. 2.3).
- Цвета/стиль мысль наследует от типа или собственного назначения.
- Неактуальные мысли приглушены (прозрачность ×0.5, курсив), если показываются
  (см. п. 9).

#### 2.2.1. Простые облачка (зоны верх-лево, верх-право, низ)

- **Высота фиксирована:** ровно 3 строки (2 заголовка + 1 индикаторы) + эллипсы
  сверху и снизу. Не зависит от содержимого. Вычисляется из CSS (высота строки × 3
  + отступы + диаметр эллипса × 2); пользователем не редактируется.
- **Ширина = `cloud_width`** (L4), одинакова для всех простых облачков.
  Ограничена системными константами `CLOUD_WIDTH_MIN`/`CLOUD_WIDTH_MAX`
  (см. [11-settings-and-state.md](11-settings-and-state.md), п. 2.4).
- Заголовок обрезается до 2 строк с `…`. Полный текст — в tooltip при наведении.
- Размер шрифта — системная константа, масштабируется с `cloud_width` по
  фиксированному правилу; пользователем не редактируется.

#### 2.2.2. Фокус-облачко (центр)

- **Не имеет фиксированной ширины.** Ограничено сверху шириной центральной зоны
  холста (с отступами). Короткий заголовок → узкое облачко; длинный → расширяется
  до предела зоны.
- **Высота зависит от содержимого:** заголовок выводится в столько строк, сколько
  нужно, но **не более 4**. Если не помещается в 4 строки — обрезается с `…`,
  полный текст — в tooltip при наведении (до 400 символов).
- Квадрат иконки и строка индикаторов — те же, что у простых облачков.
- Визуально выделено: более яркая заливка/рамка, увеличенный шрифт заголовка
  (множитель `FOCUS_FONT_SCALE`, системная константа). Пользователем не
  редактируется.

### 2.3. Эллипсы и drag

- **Верхний эллипс** (утолщённая верхняя сторона рамки) = индикатор входящих
  связей и точка drag для создания **родителя** (источника связи).
- **Нижний эллипс** (утолщённая нижняя сторона рамки) = индикатор исходящих
  связей и точка drag для создания **ребёнка** (назначения связи).
- Drag-жест: `mousedown` в любой точке эллипса → перетаскивание → `mouseup`. На
  `mouseup` открывается диалог добавления мысли (см. п. 4) в соответствующем
  направлении. «Бросить» на другую мысль — связать с существующей.

### 2.4. Связи

- Линия связи идёт от нижнего эллипса источника к верхнему эллипсу назначения.
- Линии проводятся только между **полностью видимыми** облачками: облачко,
  обрезанное краем видимой области зоны (виртуализация, п. 2.5), связей не
  показывает — линии появляются, когда оно целиком попадает в видимую область
  (и ведут только к другим видимым облачкам).
- Если у связи есть тип — вдоль линии отображается подпись (по направлению от
  источника к назначению — `name_forward`).
- Hover на линии → tooltip с `name_forward`/`name_reverse` и индикаторами
  комментариев/вложений связи.
- Несколько связей между парой мыслей — линия толще, поверх — число. Hover →
  всплывающий список всех связей с их подписями и индикаторами. Клик по элементу
  списка → связь открывается в редакторе (фокус не меняется).

### 2.5. Прокрутка и счётчики

- Количество одновременно видимых облачков определяется виртуальной сеткой
  (п. 2.1.1): `cols × rows` в каждой зоне.
- В каждой зоне своя прокрутка. **Уточнение по итогам H-фазы:** сетка раскладывает
  мысли по строкам, поэтому все зоны прокручиваются **вертикально** (в исходном
  замысле для верхних/нижней зоны предполагалась горизонтальная прокрутка — это
  противоречит фиксированным ячейкам; вертикальная прокрутка принята как
  реализованный вариант).
- На полосе прокрутки отображается диапазон видимых мыслей, например `12–36`.
- Перегрузка видимой области: показываем до `cols × rows` облачков, далее
  подгружаем при прокрутке (виртуализация рендера по сетке).

### 2.6. Контекстное меню мысли (правый клик)

```
┌─────────────────────────────┐
│ Добавить                    │→ ▸ добавить вверх (родитель)
│                             │  ▸ добавить вниз (ребёнок)
│                             │  ▸ добавить налево (родственник)*
├─────────────────────────────┤
│ Изменить активность         │
│ Изменить порядок          → │ ▸ сдвинуть вверх / первым
│                             │  ▸ сдвинуть вниз / последним
│ Изменить тип              → │ ▸ выбор типа / очистить
│ Изменить иконку             │
│ Добавить вложение           │
├─────────────────────────────┤
│ Открыть редактор            │
│ Добавить к выделению        │
│ Копировать / Вырезать       │
│ Вставить                    │
│ Удалить                     │
└─────────────────────────────┘
```

\* «Добавить налево» (родственник) — создаёт новую мысль как ребёнка того же
родителя, что и фокус (фактически добавляет связь к одному из родителей).
Доступно только если у фокуса есть хотя бы один родитель.

### 2.7. Сортировка зон

Меню порядка (для верх-лево, верх-право, низ):
- по алфавиту (возр/убыв)
- по дате создания (возр/убыв)
- по дате последнего просмотра (возр/убыв)
- ручной (только для родителей/детей; недоступен для родственников)

Порядок сохраняется **для мысли в фокусе** (per-focus). Дефолт — по дате создания
(возр).

### 2.8. Анимация смены фокуса

Смена фокуса анимируется (FLIP по сеткам зон), всё представление — **не более
1 секунды**:

- выбранная мысль перемещается из своей зоны в центр (место фокуса), увеличиваясь
  до размера фокус-облачка;
- бывший фокус уменьшается и уезжает в свою зону (родитель/ребёнок/родственник);
- оставшиеся видимыми мысли плавно переезжают на новые места;
- мысли, покинувшие окрестность, затухают на прежнем месте; новые — проявляются;
- линии связей на время переезда гаснут и проявляются по прибытии облачков
  (маскируют мгновенную перегеометрию).

Анимация не играет при `prefers-reduced-motion: reduce`, при обновлениях того же
фокуса (правки, realtime, выделение) и не блокирует ввод (движение — только
`transform`/`opacity`, слой «призраков» прозрачен для указателя).

## 3. Строка поиска и поиск

### 3.1. Поведение
- Активация поиска (`Ctrl+F` или клик в строке) **восстанавливает** предыдущий
  запрос: текст, опции, результаты — и открывает панель результатов.
  Панель закрывается по `Escape` (пока она видна) или клику вне её; текст и
  результаты сохраняются до следующей активации.
- Во время ввода — автопоиск (debounce 250 мс) или по Enter (на выбор;
  рекомендуется по Enter для крупных сетей, чтобы не нагружать сервер).
  Поиск выполняется при длине запроса **от 3 символов**; более короткие запросы
  на сервер не отправляются (подсказка в панели результатов).
- Результаты группируются в сворачиваемые секции:
  - Найдено по именам (N)
  - Найдено по текстам (N)
  - Найдено связей (N)
  - Найдено в хронологии (N)

  Пустые секции (N = 0) отображаются свёрнутыми.
- Панель результатов — dropdown с рамкой: левый край выровнен по левому краю
  строки поиска, правый отступ — ≥10% ширины окна, высота — ≤50% высоты окна.
- Каждая запись: иконка, заголовок, snippet с подсветкой матчей (`<mark>`).
  Записи внутри секции компактны и разделены тонкой линией.
- Клик по мысли → фокус и редактор. Клик по связи → фокус на источник связи,
  связь подсвечена и открыта в редакторе. После выбора записи панель поиска
  скрывается.
- Навигация клавишами в панели результатов: `↑`/`↓` перемещают выделение по
  секциям и записям; `Enter` на секции — свернуть/развернуть, на записи —
  выбрать её (как клик). Повторная активация поиска (`Ctrl+F`) выделяет
  последнюю выбранную запись.

### 3.2. Опции (шестерёнка в строке поиска)
- ☐ только в подчинённых мыслях (выбор subroot через дополнительный селектор,
  по умолчанию — текущий фокус)
- ☐ искать только мысли
- ☐ искать только связи
- ☐ искать только хронологию
- Тип мыслей (multi-select)
- Тип связей (multi-select)
- ☐ показывать неактуальные (по умолчанию = из предпочтений `show_inactive`)

Состояние опций сохраняется в `search_state` (см. [07-client-electron.md](07-client-electron.md),
п. 3.2) и восстанавливается при активации.

## 4. Диалог добавления мыслей

Назначение: **не дублировать** мысли. Поэтому любой ввод сопровождается живым
поиском существующих.

### 4.1. Виды вызова
- Из контекстного меню мысли (вверх/вниз/налево).
- Из drag-жеста на эллипсе.
- Из диалога «несколько мыслей» в панели выделения.

### 4.2. Layout диалога

```
┌────────────────────────────────────────────────────┐
│ Добавить мысль (вниз к «Фирма 1С»)            [×]  │
├────────────────────────────────────────────────────┤
│ Режим: ( ) одна   (•) несколько                    │
│                                                    │
│ Список добавляемых (только в режиме «несколько»):  │
│   ✓ Иванов Иван | Ваня, Иваныч           [↑][×]    │
│   ✓ Петров                                [↑][×]    │
│                                                    │
│ ┌────────────────────────────────────────────────┐ │
│ │ Введите название или вставьте список…          │ │
│ │ Иванов Иван | Ваня, Иваныч                     │ │
│ └────────────────────────────────────────────────┘ │
│ Тип связи: [состоит из ▾]   (если применимо)       │
│                                                    │
│ Найденные мысли:                                   │
│   🟡 Иванов Иван (точно)            [использовать] │
│   ⚪ Иван Иванов (частично)          [использовать] │
│   ⚪ Иванова (синоним «Ваня»)        [использовать] │
│                                                    │
│              [Отмена]  [Добавить] / [Вставить все] │
└────────────────────────────────────────────────────┘
```

### 4.3. Поведение

**Режим «одна»:**
- Ввод названия → живой поиск по `title` и `synonyms`.
- Под полем — список найденных с пометкой точности (точное имя / синоним /
  частичное).
- Enter → создаётся **новая** мысль (или используется выбранная из найденных)
  со связью к владельцу вызова.
- Если в названии есть `|` — текст после `|` парсится как синонимы через запятую.

**Режим «несколько»:**
- Верхний список накапливает введённые/выбранные мысли.
- Enter добавляет в верхний список, поле очищается.
- `Ctrl+Enter` — вставка всех мыслей верхнего списка в выбранное место.
- Любая строка верхнего списка редактируется/удаляется.

**Вставка многострочного буфера:**
- При вставке многострочного текста автоматом включается режим «несколько».
- Программа обрабатывает каждую строку: ищет точное совпадение по имени/синониму,
  использует существующую мысль или помечает как «новая».
- Парсинг `|` для синонимов — на каждой строке.
- Результат показывается в верхнем списке до вставки.

### 4.4. Дедупликация — правила

| Точность | Когда | Действие по умолчанию |
|----------|-------|----------------------|
| точное совпадение имени | `title_norm == input_norm` | предложить использовать существующую |
| совпадение синонима | `synonym_norm == input_norm` | то же |
| частичное / подстрока | `input` входит в `title` или `synonym` | пометить как кандидат |
| нет совпадения | — | создать новую |

Финальное решение — за пользователем (кнопка «использовать» у каждого найденного,
или «создать новую»).

## 6. Редактор мысли/связи

### 6.1. Положение
- По умолчанию справа. Переключается: слева / сверху / снизу / скрыто.
- Состояние запоминается в `ui_state.editor_position`.
- В редакторе по умолчанию — мысль в фокусе. При клике на связь на холсте —
  содержимое выбранной связи (фокус не меняется).

### 6.2. Заголовок панели и шапка редактора

**Заголовок панели** зависит от того, что выбрано: **«Мысль»** — когда выбрана
мысль, **«Связь»** — когда выбрана связь. Полей-подписей (лейблов) у полей шапки
нет — используется placeholder пустого поля.

#### 6.2.1. Шапка мысли

```
┌────────────────────────────────────────────────────┐
│ ┌──┐                                                │
│ │🖼│  Заголовок (крупный, жирный, до 5 строк)       │
│ └──┘                                                │
│ Синонимы (через запятую) __________________________│
│ [тип ▾]   [⚙]   [☑ актуально]                      │
├────────────────────────────────────────────────────┤
```

- **Квадратик иконки** слева. Если иконки нет — картинка-плейсхолдер «нет
  изображения». Клик по квадратику открывает **диалог выбора иконки** (§6.8).
- **Заголовок** — крупный (1.5× от нормального), жирный, многострочное поле
  ввода с авто-высотой (растёт под содержимое, но не более 5 строк).
- **Синонимы** — однострочное поле; запятая — разделитель.
- **Тип ▾** — выпадающий (с пунктом «без типа»).
- **⚙ (настройки)** — открывает **диалог настроек мысли** (§6.9): цвет
  текста/фона и стиль шрифта, плюс кнопка «Сброс».
- **☑ актуально** — переключатель активности (для HOME — заблокирован).

**При смене типа** меняются только визуальные настройки, не заданные вручную
(`NULL`-поля наследуются от нового типа — см. 02-data-model.md §3.1.1): иконка,
стиль шрифта, цвета, а также состав свойств (свойства прежнего типа скрываются,
но не очищаются).

#### 6.2.2. Шапка связи

```
┌────────────────────────────────────────────────────┐
│ [тип связи ▾]   [⚙]   [☑ актуально]                │
├────────────────────────────────────────────────────┤
```

- Строк иконки/заголовка/синонимов **нет**.
- **Тип связи ▾**, **⚙ (настройки связи: цвет/штрих/толщина линии + «Сброс»,
  см. §6.9)**, **☑ актуально**.

### 6.3. Сворачиваемые группы

| Группа | Применимо | По умолчанию | Содержание |
|--------|-----------|--------------|------------|
| **Комментарий** | мысль и связь | развёрнута | постоянный комментарий: HTML-просмотр / редактирование markdown (§6.4) |
| **Хронологические комментарии** | мысль и связь | свёрнута | таблица (заголовок, даты, краткий текст), кнопка «Добавить» (§6.6) |
| **Вложения** | мысль и связь | свёрнута | список вложений (превью для картинок, иконки для прочих), кнопка «Добавить вложение» |
| **Свойства** | только мысль | развёрнута | таблица свойств согласно типу (если тип задан и у него есть свойства) |
| **Связи** | мысль и связь | развёрнута | для мысли — сгруппированы по типам (§6.7); для связи — 2 мысли (источник и назначение) |
| **Упоминания** | только мысль | развёрнута | список мыслей/связей, в текстах которых встречается название или синоним |

Состояние (свёрнута/развёрнута) каждой группы **запоминается** для конкретной
мысли/связи в `ui_state.editor_collapsed_groups`; если записи нет — применяется
состояние «по умолчанию» из таблицы. В заголовке группы отображается счётчик
`(N)` для Хронологических комментариев, Вложений, Свойств, Связей.

### 6.4. Комментарий (постоянный)
- Группа всегда развёрнута по умолчанию. Заголовок группы — «Комментарий».
- Содержимое отображается сразу HTML-рендером. Пустой текст — пустое поле
  (без надписей «нет комментария» / кнопок-заглушек).
- **Двойной клик** по полю переключает в режим редактирования markdown.
  Высота поля адаптируется под содержимое, но не менее 5 строк.
- **Клик вне поля** (на холсте, в любой панели, в другой части редактора)
  сохраняет markdown и возвращает режим HTML-просмотра. `Esc` — отмена и возврат
  к просмотру без сохранения.
- **Вставка картинки из буфера** (Ctrl+V в режиме редактирования, работает и в
  хронологических комментариях): файл сохраняется на сервере в
  `networks/<nid>/attachments/` рядом с БД, автоматически создаётся вложение
  сущности, а у курсора вставляется markdown-ссылка `![имя](etnimg://…)`.
  В HTML-просмотре картинка масштабируется пропорционально ширине поля
  комментария.

### 6.5. Вложения — добавление
- **Перетаскивание** ссылки/файла в зону вложений: автозаполнение заголовка (для
  файла — имя файла; для URL — сервер best-effort подтягивает `<title>` и
  favicon при создании вложения, см. 03-server-api.md §11).
- **Вставка из буфера обмена** в поле комментария: файлы любого типа
  загружаются на сервер (`attachments/file`) и вставляются ссылкой в markdown —
  картинки как `![имя](etnimg:…)`, остальные файлы как `[имя](etnimg:…)`.
- **Кнопка «Добавить вложение»** → тот же диалог (URL/путь, заголовок, комментарий).
- В списке: превью для картинок-файлов (сама картинка через `etnimg:`), favicon
  сайта для интернет-адресов (заполняется сервером), картинка для URL-ссылок на
  изображения, иконка-глиф для остальных. Отдельной кнопки удаления в строке
  нет — удаление через контекстное меню.

#### 6.5.1. Контекстное меню вложения (ПКМ по строке)
- **Открыть в программе по умолчанию** — файл открывается системным
  приложением (`shell.openPath`), URL — в браузере (`shell.openExternal`).
  Двойной клик по строке делает то же самое.
- **Показать** (только картинки, текстовые файлы и markdown) — встроенный
  просмотрщик: картинка или текст (читается через `etnimg:`).
- **Назначить иконкой мысли** (только картинки и только когда владелец — мысль):
  файл читается и сохраняется как самодостаточная иконка (`icon_kind='image'`,
  `data:image` URL, лимит 256 КБ — как в диалоге выбора иконки).
- **Перенести в мысль…** — диалог поиска мысли; вложение переезжает к выбранной
  мысли (`PATCH owner_type/owner_id`).
- **Удалить…** — с подтверждением; серверная копия файла удаляется вместе со
  строкой (клиентские пути не трогаются).

### 6.6. Хронологические комментарии
Таблица:
| Заголовок | С | По | Кратко | ⋯ |
- «Добавить» → диалог (заголовок, даты начала/окончания, текст). По умолчанию
  С = По = сегодня.
- **Двойной клик** → диалог просмотра/редактирования (заголовок, даты, текст).
  Поле текста работает как постоянный комментарий: HTML-просмотр, двойной клик —
  редактирование markdown, клик вне — возврат к HTML.

### 6.7. Связи
**Для мысли:** группировка по типам; в каждой группе — список связей этого типа
с именем и иконкой противоположной мысли. Безтиповые связи — две группы:
«Источники» (родители) и «Назначения» (дети). **Заголовок связанной мысли
кликабелен — клик переводит эту мысль в фокус** (вернуться можно через историю
фокуса внизу холста). Отдельной команды «Открыть» (открывавшей связь в
редакторе) нет.

Контекстное меню строки (L5):
- **Открыть** — переводит противоположную мысль в фокус (дубль клика);
- **Изменить тип связи…** — диалог выбора типа связи (типы сети + «без типа»,
  текущий предвыбран) → `links.update` с `type_id`;
- **Удалить связь** — с подтверждением; линия пропадает с холста, список и
  счётчик группы обновляются;
- **Удалить мысль** — удаляет противоположную мысль с подтверждением (тот же
  путь, что и меню облачка, включая локальную зачистку автора по L4).

**Для связи:** группа содержит ровно 2 записи — мысль-источник и
мысль-назначение, без группировок. Клик по записи переводит её в фокус.

### 6.8. Диалог выбора иконки
Переключатель вверху: **Эмодзи / Файл / URL**.
- **Эмодзи** — сетка эмодзи; клик по любому устанавливает его как иконку
  (`icon_kind = 'emoji'`) и закрывает диалог.
- **Файл** — поле ввода пути + кнопка выбора файла (системный диалог). Ниже —
  квадратик предпросмотра (`object-fit: contain`, без искажения пропорций); при
  некорректном файле в нём показывается символ ошибки. Кнопка **ОК** (устанавливает
  файл как иконку, `icon_kind = 'image'`, содержимое — `data:` URL) доступна только
  при корректном файле. Лимит размера — 256 КБ.
- **URL** — поле ввода URL + предпросмотр + ОК (как для «Файл», но без кнопки
  выбора; `icon_kind = 'image'`, `icon` — сам URL).
- Внизу — **Очистить**: убирает собственную иконку мысли (`icon = NULL`) и
  закрывает диалог. Если уникальная иконка очищена, мысль отображается с иконкой
  выбранного типа (если она есть).

### 6.9. Диалог настроек (цвета и стиль)
- **Для мысли:** цвет текста, цвет фона облачка, четыре тогла стиля шрифта
  (жирный/наклонный/подчёркнутый/зачёркнутый).
- **Для связи:** цвет линии, стиль (`solid`/`dashed`/`dotted`), толщина.
- Кнопка **Сброс** убирает все ручные настройки (выставляет соответствующие
  поля в `NULL`): мысль/связь снова отображается со стилем выбранного типа.

## 7. Перетаскивание ссылок/файлов на холст (C3)

- Допустимые цели: **верх-лево** (создаёт родителя) и **низ** (создаёт ребёнка).
  Верх-право (родственники) — **запрещённая цель**, курсор `not-allowed`.
- При броске: создаётся мысль с заголовком (имя файла или, для URL, заголовок
  страницы — клиент на MVP не ходит в интернет, заголовок берётся из названия
  файла или остаётся пустым для URL), к ней автоматически добавляется вложение.
- Множественный drop — создаётся по мысли на каждый файл/ссылку.

### 8.1. Управление типами (L6)

Диалоги-менеджеры (диалоги складываются в стек: редактор и подтверждения
открываются поверх списка).

**Список типов мыслей:** таблица «иконка · название · комментарий», название
отрисовывается с собственными цветами/шрифтом типа; порядок алфавитный
(серверный). Кнопка «Добавить» → редактор нового типа; в каждой строке «✕» —
удаление. Клик по строке → редактор типа.

**Список типов связей:** «имя вперёд / имя назад · комментарий», алфавитный
порядок; те же действия.

**Редактор типа мысли:**
- иконка — тот же диалог выбора иконки, что у мысли (§6.8), применяется сразу;
- название — обязательно (кнопка «Сохранить»);
- ⚙ «Свойства типа» — тот же диалог цветов/шрифта, что у мысли (§6.9, режим
  типа: «Сброс» возвращается к обычным значениям, т.к. у типа шрифтовые флаги
  NOT NULL);
- комментарий (описание типа, правила применения) — многострочное поле;
- таблица свойств типа: имя (key), тип значения, значение по умолчанию
  (хранится в `config.default_value`; для `thought_ref` не задаётся);
  ▲/▼ — порядок (`PUT …/properties/reorder`), ✕ — удаление. Имя и тип
  значения фиксированы после создания (key адресует значения, `value_type`
  определяет колонку хранения). Операции применяются сразу.

**Редактор типа связи:** имена «вперёд»/«назад» (оба обязательны), ⚙ — тот же
диалог стиля линии, что у связи (§6.9, режим типа), комментарий.

**Удаление типа:** подтверждение → `DELETE …?force=1`. У мыслей/связей этого
типа `type_id` обнуляется (сами они остаются, становятся без типа);
определения свойств типа и все их значения удаляются сервером (03-server-api.md
§8). Каталоги типов и холст обновляются сразу.

- 🟢/🟡/🔴 — состояние соединения.
- Имя сети.
- Заголовок фокус-мысли (кратко).
- **История фокуса** — три облачка предыдущих мыслей + раскрывающийся список с
  остальной историей (см. п. 11.1).
- Кол-во мыслей в сети.
- Последнее событие real-time («Петя добавил мысль X», исчезает через 5 с или
  по клику).
- При конфликте версий — индикатор «⚠ изменено другим пользователем» с кнопкой
  «показать».

### 11.1. История фокуса в статус-баре

> Логика хранения и правила дедупликации — в
> [11-settings-and-state.md](11-settings-and-state.md), п. 2.3. Здесь — только
> визуальное представление.

Layout (в статус-баре, рядом с индикатором сети):

```
[ ← [облачко₁] [облачко₂] [облачко₃] [▾ N] ]
```

- **Три облачка слева направо** = три самые свежие мысли из истории (облачко₁ —
  самая свежая, только что бывшая в фокусе).
- Каждое облачко — миниатюра облачка холста: иконка + заголовок (обрезанный до
  ~40 символов), цвет/стиль из типа или собственной настройки мысли. Клик по
  облачку → мысль переходит в фокус (становится `current_focus_thought_id`).
- **`[▾ N]`** — раскрывающийся список (dropdown) с остальной историей, N = кол-во
  мыслей за пределами первых трёх. Элементы — те же мини-облачка с заголовком.
  Клик → переход в фокус.
- При N = 0 кнопки `▾` нет.
- **Пустая история** (только что открытая сеть, после HOME) — область скрыта или
  показывает заглушку «нет предыдущих мыслей».

**Поведение при клике на элемент истории:**

- Обычная смена фокуса по правилам п. 2.3: текущая фокус-мысль попадает в
  историю (в начало), выбранная из истории удаляется (становится фокусом),
  история переупорядочивается.

**Отображение удалённых/неактивных мыслей в истории:**

- Удалённая на сервере мысль — автоматически **удаляется из локальной истории**
  при получении `thought.deleted`. В GUI не показывается. Автор удаления не
  получает realtime-эхо (04-realtime.md §5) — его клиент выполняет ту же
  зачистку локально сразу после успешного удаления.
- **Удаление мысли, находящейся в фокусе:** фокус автоматически переходит к
  предыдущей мысли из истории (самой свежей существующей записи); если истории
  нет/она неактуальна — к первой защищённой от удаления мысли (корень HOME).
  То же восстановление применяется, когда фокус удалён другим пользователем
  (`focus-lost`).
- Неактуальная мысль — отображается в истории **только если** включён
  `show_inactive`. При выключенном — скрывается из истории (как и с холста).
- Имена в истории — только актуальные (текущий заголовок), даже если мысль была
  переименована после попадания в историю.

## 12. Первичная настройка клиента

При первом запуске:
1. Экран приветствия → «Подключиться к серверу ETN».
2. Поля: URL сервера, API-key.
3. Проверка `GET /me` → успех: сохранение профиля, переход к списку сетей.
   Ошибка: понятное сообщение (неверный ключ / сервер недоступен / не та версия).

## 13. Технические принципы UI

- **Рендеринг холста.** На больших сетях (десятки облачков в зоне, много связей)
  DOM+SVG может тормозить; предлагаемый путь — `<canvas>` (или WebGL через
  PixiJS/Konva) для холста и связей, DOM-оверлей для облачков. Финальный выбор
  библиотеки — отдельная задача (пункт открыт).
- **Виртуализация списков** в зоне холста, в результатах поиска, в редакторе
  (большая хронология, упоминания) — обязательна.
- **CSS-переменные** для цветов/размеров с самого начала — задел под темы.
- **Шрифты** — системные стеки для каждой ОС.
- **Клавиатурные команды:**
  - `Ctrl+F` — поиск.
  - `Enter` на облачке — фокус.
  - `Ctrl+клик` — toggle выделения.
  - Стрелки с `Alt`/`Shift` — навигация по зонам.
  - `Escape` — выход из диалога/снятие выделения.
  - `Ctrl+наведение` на иконку-картинку — «лупа»: всплывашка с картинкой в
    полном размере у курсора (не более 70% ширины/высоты окна). Действует на
    все иконки-изображения (история, результаты поиска, вложения, списки
    связей, картинки в комментариях); скрывается при отпускании `Ctrl`, уходе
    курсора, скролле или `Escape`.
  - Полная таблица — отдельным приложением к документу.
- **Локализация.** MVP — русский. Использовать i18n-библиотеку с самого начала;
  переводы — отдельные JSON-каталоги.
