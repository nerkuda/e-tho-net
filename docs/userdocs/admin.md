# ETN — администрирование

**Автор:** Проект ETN

Администрирование сервера ETN: пользователи и API-ключи, мыслесети и доступ, аудит, логи.

<a id="pub-249edd9f"></a>

## Пользователи и API-ключи

Эта страница — про управление учётными записями на сервере. Раздел доступен администратору: меню пользователя → «Администрирование» → «Пользователи».

### Первый администратор

Первый пользователь-администратор создаётся один раз при установке сервера командой `etn init` — вместе с ним выдаётся первичный API-key (см. «Установка сервера ETN»). Пока администратора нет, сервер не стартует. Первого пользователя сервера удалить нельзя — иначе сервер останется без администратора.

### Создание пользователя

Нажмите **«Добавить пользователя»** и укажите имя пользователя (логин) и отображаемое имя; при необходимости отметьте «администратор». При создании сразу генерируется API-key.

### API-ключи

- **Ключ виден один раз.** Сразу после создания ключ показывается полностью — скопируйте его кнопкой и передайте пользователю по надёжному каналу. Хранится только необратимая отметка ключа; посмотреть или восстановить полный ключ позже нельзя.
- **Список ключей** показывает только начала (префиксы) ключей пользователя.
- **(Пере)генерировать ключ** выпускает новый ключ. Старый продолжает работать, пока вы не отзовёте его из списка ключей.
- **Отзыв ключа** делает ключ недействительным; активные подключения с ним закрываются.
- **Дополнительные ключи.** Пользователь может выпускать ключи и сам — это удобно, чтобы завести отдельный ключ для AI-агента или другого устройства. Такому ключу можно разрешить только чтение и ограничить число записей в минуту. Отдельного экрана для этого в клиенте нет — ключ выдаётся через серверный интерфейс.

### Отключение и удаление

- **Отключить учётную запись** — пользователь и его ключи перестают действовать, данные сохраняются.
- **Удалить пользователя** нельзя, если он владеет хотя бы одной мыслесетью: сначала передайте владение.
- **Пользователя-автора** нельзя удалить физически, пока есть записи, где он указан автором или редактором: сервер откажет и перечислит мешающие записи. Вместо удаления такую учётную запись «выводят из оборота» — отзывают ключи и исключают из сетей; история авторства при этом сохраняется.

## Мыслесети: владение и доступ

Мыслесеть — это отдельная база знаний. Данные мыслесети изолированы от остальных.

### Создание и владение

Пользователь создаёт мыслесеть и становится её **владельцем**. Владелец управляет составом участников.

### Участники

Владелец открывает меню «Мыслесеть» → «Участники сети» и может:

- добавить участника;
- исключить участника;
- **передать владение** другому участнику. Владельцем становится выбранный участник, прежний владелец переходит в обычные участники; двух владельцев одновременно не бывает.

### Права администратора

Администратор видит список всех мыслесетей («Администрирование» → «Сети») и может сменить владельца или удалить любую сеть. При этом **читать данные чужой сети администратор не может**, пока не станет её участником — это сознательное ограничение приватности.

### Удаление мыслесети

Мыслесеть можно удалить; действие необратимо. Перед удалением убедитесь, что нужные данные сохранены — например, выгрузите сеть архивом из клиента.

## Журнал аудита — для администратора

Журнал аудита фиксирует важные действия на сервере: входы и отказы аутентификации, изменения пользователей и их ключей, создание и удаление мыслесетей, изменение состава участников, действия AI-агентов и другие административные операции.

### Где смотреть

«Администрирование» → «Аудит». Записи можно отфильтровать по пользователю, мыслесети, категории и периоду.

### Что даёт

- разобраться, кто и когда изменил настройки или состав участников;
- проверить, что делал тот или иной AI-агент (его действия фиксируются как действия владельца ключа);
- увидеть попытки подбора ключей (защита от перебора срабатывает автоматически: серия неудачных попыток временно блокируется).

## Логи и диагностика

Когда программа ведёт себя странно — «клик по мысли не срабатывает», «редактор висит с надписью „загрузка“», «всё тормозит» — причина чаще всего видна только в журналах диагностики: текстовых файлах, куда клиент и сервер записывают, что с ними происходило. Эта страница — как включить журналы, где их взять и как передать в поддержку.

### Кому что доступно

- **Журнал клиента** — свой на каждом компьютере; включается пользователем для себя и работает даже без подключения к серверу.
- **Журнал сервера** — общий, лежит на сервере и доступен **только администратору сервера**. Обычный пользователь не может ни включить, ни скачать, ни удалить серверные журналы — соответствующие управляющие операции закрыты для неадминистраторов.

### Как включить

Журналы включаются в диалоге **«Все настройки»** (меню «Вид» ☰ → «Настройки») → раздел **«Логирование»**. Переключатели применяются **сразу** — кнопка «Применить» не нужна.

- **Логирование клиента** — пишет журнал этого компьютера. Работает и без подключения к серверу. Запоминается — после перезапуска клиента остаётся включённым.
- **Логирование сервера** — пишет журнал на сервере. Доступно только администратору сервера и только когда сервер подключён; после перезапуска сервера сбрасывается в «выключено» (напоминание об этом есть в разделе).

Типовой сценарий диагностики: включить оба переключателя → воспроизвести проблему → «Скачать…» файл сервера и открыть/скопировать клиентский → передать файлы в поддержку.

### Где лежат файлы

- **Клиент:** каталог `logs` внутри профиля клиента (`<userData>/logs`), файлы вида `client-ГГГГ-ММ-ДД.log` — по одному на сутки. Точный путь текущего файла показан в разделе «Логирование».
- **Сервер:** каталог `logs` в данных сервера, файлы вида `server-ГГГГ-ММ-ДД.log` (дата UTC), хранятся 30 суток. Список файлов с размерами и датами — в разделе «Логирование».

Важно: даже при выключенном переключателе в журнал всегда пишутся ошибки (ERROR) — они могут уже содержать подсказку.

### Кнопки раздела

- **Открыть** — открыть текущий файл журнала в системной программе (у сервера: если файл недоступен с этого компьютера, скачивается временная копия и открывается она).
- **Скачать…** — сохранить выбранный в списке файл журнала сервера на этот компьютер (без выбора — текущий).
- **Удалить** — удалить **все** файлы журналов (клиента или сервера соответственно) после подтверждения; текущий суточный файл очищается. Действие необратимо.

Ошибки любых операций показываются прямо в разделе — текстом под кнопками.

### Параметр запуска клиента

Клиент можно запустить с уже включённым журналом, не трогая настройки:

```
etn.exe --logging      # включить журналирование на этот запуск (и запомнить)
etn.exe --no-logging   # выключить на этот запуск (и запомнить)
```

Параметр переопределяет сохранённое значение. Если клиент не запускается вовсе и добраться до настроек нельзя — это способ получить журнал старта.
