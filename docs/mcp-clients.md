# Подключение AI-агентов к ETN (MCP)

ETN предоставляет MCP-сервер, через который внешние AI-агенты (Claude Desktop,
IDE-агенты, кастомные скрипты) читают и изменяют мыслесети наравне с людьми.

## 1. Авторизация

Агент действует от лица пользователя, чей API-key передан:

- Видит и меняет только сети, где этот пользователь — участник.
- Для «только чтение» выпустите read-only ключ: `POST /api/v1/me/keys`
  с `read_only: true` (ключ пропускает только чтение; проверяется перед
  каждым изменяющим вызовом).
- Лимит записи `max_writes_per_minute` можно переопределить на ключ
  (`NULL` — серверный дефолт): задаётся при создании ключа и меняется через
  `PATCH /api/v1/me/keys/{id}`. Составной `etn.thoughts.upsert_bundle`
  считается одной записью для лимита.

```bash
curl -X POST https://etn.example.com/api/v1/me/keys \
  -H "Authorization: Bearer etn_..." -H "Content-Type: application/json" \
  -d '{"label":"agent","read_only":true,"max_writes_per_minute":30}'
```

## 2. Режим stdio (локальные агенты)

```json
{
  "mcpServers": {
    "etn": {
      "command": "node",
      "args": ["/opt/etn/server/dist/mcp-stdio.js", "--api-key", "etn_..."],
      "env": { "ETN_DATA_DIR": "/var/lib/etn" }
    }
  }
}
```

> Точное имя stdio-точки входа см. в README сервера (`etn mcp` — CLI-команда).
> Ключ также можно передать через `ETN_API_KEY`.

## 3. Режим HTTP (удалённые агенты)

Включите на сервере `ETN_MCP_ENABLED=1`. Эндпоинт: `POST /mcp` (заголовок
`Authorization: Bearer <key>`). Для выделенного порта только под MCP —
`ETN_MCP_PORT`.

## 4. Инструменты

### Чтение и поиск

| Инструмент | Назначение |
|-----------|------------|
| `etn.networks.list` | список доступных сетей (с `description`, `when_to_use`, `has_structure`) |
| `etn.networks.get` | одна сеть с полным самоописанием (`conventions`, `examples`) |
| `etn.networks.structure` | «оглавление» сети: активные мысли узлового типа с превью комментариев и счётчиками |
| `etn.thoughts.search` | полнотекстовый поиск (имена, тексты, связи, хроника; `scope`, `in_subtree_of`, пагинация `offset`) |
| `etn.thoughts.query` | структурная выборка: ключевые слова (мини-синтаксис `*`/`-слово`), тип, поддерево, актуальность, пометка на удаление, свойства, даты |
| `etn.thoughts.get` | чтение мысли: `meta` (счётчики, превью постоянного комментария), резолв `thought_ref`-свойств в `{id, title}` |
| `etn.thoughts.neighbors` | окружение мысли (родители/дети/братья, `depth` до 20) |
| `etn.thoughts.subgraph` | подграф радиуса N — ключевой RAG-инструмент (см. §9 про `max_chars`) |
| `etn.thoughts.path` | кратчайший путь между мыслями |
| `etn.thoughts.mentions` | комментарии, упоминающие мысль по имени/синониму |
| `etn.thoughts.backlinks` | комментарии с явными ID-ссылками `[[#<id>]]` на мысль |
| `etn.thoughts.usage` | кто ссылается на мысль через свойства, по свойствам |
| `etn.thoughts.find_duplicates` | **обязателен перед созданием** — поиск дубликатов |
| `etn.types.list` | оба каталога типов (иерархия + эффективные свойства); `in_subtree_of` — только типы раздела |
| `etn.attachments.search` | поиск вложений по ключевым словам |
| `etn.changes.list` | дельта-фид событий с `since_seq` — для собственного кеша агента |
| `etn.metrics.reads` | счётчики чтения мыслей (топ/холодные) — где горячие и мёртвые зоны |

### Запись

| Инструмент | Назначение |
|-----------|------------|
| `etn.thoughts.create` / `update` / `delete` | мысли; тип — по `type_id` или имени |
| `etn.thoughts.upsert_bundle` | составная запись «единицы знания» (мысль + постоянный комментарий + свойства + связи + вложения) **одной транзакцией**; `on_duplicate: fail\|reuse\|update` |
| `etn.thoughts.set_active` | актуальность |
| `etn.links.create` / `delete` / `get` | связи; тип — по `type_id` или по паре имён |
| `etn.comments.upsert` | постоянный (create-or-update) или хронологический комментарий; `targets[]` — привязка одной записи к нескольким владельцам |
| `etn.comments.update` / `delete` / `get` | правка/удаление/полный текст по `comment_id` |
| `etn.properties.set` | значения свойств: одно (`key`+`value`) или набор (`values`), массивы для multi-value |
| `etn.attachments.add` / `copy` | вложения: URL/путь; копия существующего на несколько владельцев |
| `etn.export.subgraph` | подграф как Markdown/HTML-документ |

### Захваты (0.7.1)

Серверная мягкая блокировка объекта при редактировании — открытие
редактора/диалога автоматически захватывает объект за вами, чужие записи
через любой канал (клиент/REST/MCP) блокируются до конца редактирования.
Подробности — в [user-guide.md](user-guide.md) §12.

| Инструмент | Назначение |
|-----------|------------|
| `etn.locks.list` | активные захваты сети: кто, какой объект, с какого момента |
| `etn.locks.release_all` | снять все захваты указанного пользователя (доступно любому участнику сети) |

### Слои (см. §7)

| Инструмент | Назначение |
|-----------|------------|
| `etn.layers.list` / `create` / `update` / `delete` | список/создание/переименование/каскадное удаление слоёв |
| `etn.layers.select` | переключить сессионный слой **этого API-ключа** |
| `etn.layers.merge` | слить слой в родителя (полностью или частично) |
| `etn.layers.diff` / `diff_doc` | структурный и текстовый диффы слоя с родителем |

### Корзина (см. §8)

| Инструмент | Назначение |
|-----------|------------|
| `etn.thoughts.trash` / `etn.links.trash` | пометить/снять пометку на удаление |
| `etn.trash.list` | корзина сети с предвычисленными блокировками |
| `etn.trash.purge` | физически удалить всё незаблокированное |
| `etn.thoughts.deletion_check` / `etn.links.deletion_check` | что блокирует физическое удаление |
| `etn.thoughts.usage_clear` | очистить все ссылки на мысль из чужих свойств |

### Журнал активности (0.7.1)

Таблица `activity_log` — лента сетевых событий «кто что сделал». Источник
рабочего стола «События». Операции обслуживания (свёртка, обрезка)
**необратимы**. Подробности — в [user-guide.md](user-guide.md) §12.

| Инструмент | Назначение |
|-----------|------------|
| `etn.activity.list` | лента событий с фильтрами `since`/`until`/`user_id`/`entity_type` (период в миллисекундах, участник, тип сущности), пагинация |
| `etn.activity.rollup` | свёртка журнала до даты `until_ms` |
| `etn.activity.truncate` | обрезка журнала до даты `until_ms` |

## 5. Важное правило: не плодить дубликаты

Перед `etn.thoughts.create` агент **обязан** вызывать
`etn.thoughts.find_duplicates` и переиспользовать существующую мысль при
совпадении имени/синонима. `etn.thoughts.upsert_bundle` делает эту проверку
сам (параметр `on_duplicate: fail|reuse|update`, по умолчанию `fail`) — для
записи «мысль + всё остальное» одним вызовом предпочтительнее его, а не
связку `find_duplicates` → `create` → … .

## 6. Самоописание сети: маршрутизация и формат записи

Когда у пользователя несколько сетей, агент должен сам решить, в какую
писать:

1. `etn.networks.list` — прочитать `description` и `when_to_use` каждой сети,
   выбрать подходящую задаче. Не читайте все поля всех сетей подряд —
   лишний расход контекста.
2. Если `has_structure: true` — начать с `etn.networks.structure`
   («оглавление» из узловых разделов с превью комментариев и счётчиками).
3. Для записи в раздел — контекстный каталог типов:
   `etn.types.list { in_subtree_of: <section.id> }` (только используемые в
   разделе типы, с `usage_count`).
4. Drill-down по разделу: `etn.thoughts.query { in_subtree_of: … }` /
   `etn.thoughts.search` / `subgraph`.
5. Перед `create`/`update` прочитать `conventions` (правила записи сети;
   приходят в `etn.networks.structure` одним вызовом) и при сомнениях по
   форме — `examples` (`etn.networks.get`).

Запись одной «единицы знания» — идемпотентный `upsert_bundle`: мысль +
комментарий + свойства + связи + вложения одной транзакцией. Политика
`on_duplicate` делает повторный импорт безопасным.

## 7. Слои изменений

Слой — copy-on-write «ветка» сети: правки слоя не видны в основе, пока слой
не слит. Каждый **API-ключ имеет собственную сессионную слой-сессию**:
`etn.layers.select` переключает слой для всех последующих вызовов этого
ключа (чтения и записи), не влияя на другие ключи того же пользователя.

- `etn.layers.list` — слои с `current`-флагом; `create` — от родителя
  (по умолчанию — текущий слой ключа), **комментарий настоятельно
  рекомендуется** — по нему коллега-агент поймёт назначение слоя; `select` —
  переключение (после него `etn.changes.list` требует полного ресинка).
- Все инструменты чтения и записи слоистые: видят и пишут контекст сессии
  ключа; неперекрытые строки «прозрачны» — виден текущий слой-предок.
- Каждый пишущий инструмент возвращает эхо `layer: {id, title}` — проверяйте,
  куда попала запись.
- `etn.layers.merge` — полное или частичное слияние в родителя: конфликт
  (строка менялась и в слое, и в родителе) отвергает **всю** операцию со
  списком `conflicts`; успех возвращает отчёт и `reserve_layer_id`
  (автоматический резервный слой-точка отката). Перед merge полезен
  `etn.layers.diff` (структурный) и `diff_doc` (текстовый).
- `delete` каскадно удаляет поддерево слоёв и требует `cascade=<N>` —
  число потомков из `children_count` ответа списка.

## 8. Корзина и двухфазное удаление

Физическое удаление блокируется использованием мысли в `thought_ref`-свойствах
других мыслей и удерживающими слоями. Порядок агента:

1. `etn.thoughts.trash { trashed: true }` — пометка (без блокировок); снимается
   тем же вызовом с `false`.
2. `etn.thoughts.deletion_check` — что блокирует: `blocking.properties`
   (использование в свойствах) и `blocking.layers` (удержание слоями).
3. Разблокировка: `etn.thoughts.usage_clear` (обнуляет все ссылки на мысль из
   чужих свойств) или удаление удерживающего слоя.
4. `etn.thoughts.delete` — физическое удаление; либо `etn.trash.purge` для
   всей корзины сразу.
   `etn.trash.list` показывает корзину с уже вычисленными блокировками.

Отборы (`query`, `search`) по умолчанию скрывают помеченные — `trashed: "any"`
показывает и их.

## 9. Экономия контекста ответов

- **`view: "compact"`** (дефолт в `get`/`neighbors`/`subgraph`/`usage`) —
  выкидывает визуальные поля (цвета, шрифты, стили линий); `view: "full"` —
  для визуализации графа.
- **`max_chars` у `subgraph`** — мягкий бюджет символов: сервер сначала
  обрезает превью комментариев до 500 символов (полный текст — всегда
  `etn.comments.get` по `comment_id` из превью), затем отбрасывает самые
  дальние от seed'ов узлы; seed'ы не удаляются никогда. Результат
  подписывается `truncated`/`reason`/`budget`.

```jsonc
// дайджест по разделу с жёстким бюджетом 12 KB:
{ "name": "etn.thoughts.subgraph",
  "arguments": { "network_id": "<net>", "seed_ids": ["<id>"], "radius": 2,
                 "include_comments": true, "max_chars": 12000 } }
```

Если ответ пришёл с `reason: 'max_chars_nodes'` и полноты не хватило —
сузьте `radius`, разбейте по seed'ам или выключите `include_comments` и
подтяните комментарии точечно.

## 10. Warnings о незаполненных required-свойствах

Тип мысли может объявлять обязательные свойства. `etn.thoughts.create`,
`etn.thoughts.update` (при смене типа) и `etn.thoughts.upsert_bundle`
**не падают** на неполной карточке — возвращают
`warnings: [{code: "REQUIRED_PROPERTY_MISSING", key, …}]`: карточка записана,
но её нужно дозаполнить.

- `warnings` появляются только при расхождениях (у `upsert_bundle` поле есть
  всегда, включая пустой массив).
- Дефолты значений **не маскируют** предупреждение — значение нужно записать
  явно (`etn.properties.set` или в `properties` следующего bundle).
- Перед записью список обязательных ключей подскажет `etn.types.list`.

```jsonc
// bundle вернул warnings: [{ key: "status", ... }] — закрываем gap:
{ "name": "etn.properties.set",
  "arguments": { "network_id": "...", "owner_type": "thought",
                 "owner_id": "<id>", "values": { "status": "active" } } }
```

## 11. Поведение

- Изменения агента проходят те же проверки прав и валидацию, что у людей.
- Участники сети видят изменения агента в реальном времени (WebSocket).
- Каждый изменяющий вызов фиксируется в аудите (`category=data`).
- Каждая запись фиксирует **автора** (`user_id` запроса → `created_by`/
  `updated_by` сущности) — это та же пользователь, чей API-key
  использовался. У сущностей, созданных агентом, автор = владелец ключа.
  История авторства в ленте «События» показывает, что сделал именно
  этот агент (а не другие ключи того же пользователя — у них будет тот
  же пользователь, но разные `key_id`).
- Агент подчиняется **захвату**: если другой участник (человек или другой
  агент) уже редактирует объект, запись через MCP вернёт
  `409 LOCK_HELD` с указанием текущего редактора. Перед записью в
  конкретный объект полезно проверить `etn.locks.list`.
- Лимиты: `max_nodes_per_subgraph` (default 500) и `max_writes_per_minute`
  (default 60; переопределяется на ключ, §1).

## 12. Пример: собрать дайджест по теме

1. `etn.networks.list` → выбрать сеть по `when_to_use`.
2. `etn.thoughts.search { query: "конкуренты", scope: "all" }`.
3. `etn.thoughts.subgraph { seed_ids: [топ-5], radius: 2,
   include_comments: true, max_chars: 12000 }`.
4. Сгенерировать дайджест в своей LLM.
5. Опционально: `etn.comments.upsert` — сохранить дайджест как
   хронологический комментарий у корневой мысли (`targets[]`, если несколько).
