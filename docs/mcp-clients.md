# Подключение AI-агентов к ETN (MCP)

ETN предоставляет MCP-сервер, через который внешние AI-агенты (Claude Desktop,
IDE-агенты, кастомные скрипты) читают и изменяют мыслесети наравне с людьми.

## 1. Авторизация

Агент действует от лица пользователя, чей API-key передан:

- Видит и меняет только сети, где этот пользователь — участник.
- Для «только чтения» выпустите read-only ключ (в клиенте: «Мои ключи» → создать
  с опцией read-only).

## 2. Режим stdio (локальные агенты)

```json
{
  "mcpServers": {
    "etn": {
      "command": "node",
      "args": ["/opt/etn/server/dist/mcp-stdio.js", "--api-key", "etn_..."],
      "env": { "ETN_DATA_DIR": "/var/lib/etn" }
    }
  }
}
```

> Точное имя stdio-точки входа см. в README сервера (`etn mcp` — CLI-команда).
> Ключ также можно передать через `ETN_API_KEY`.

## 3. Режим HTTP (удалённые агенты)

Включите на сервере `ETN_MCP_ENABLED=1`. Эндпоинт: `POST /mcp` (заголовок
`Authorization: Bearer <key>`).

## 4. Основные инструменты

| Инструмент | Назначение |
|-----------|------------|
| `etn.networks.list` | список доступных сетей |
| `etn.thoughts.search` | полнотекстовый поиск |
| `etn.thoughts.query` | структурная выборка по критериям: тип, поддерево, актуальность, ключевые слова, свойства, даты |
| `etn.thoughts.get` / `neighbors` | чтение мысли (с `meta`: счётчики связей/вложений/хроники и превью постоянного комментария) и её окружения |
| `etn.thoughts.subgraph` | подграф радиуса N (контекст для генерации) |
| `etn.thoughts.path` | путь между мыслями |
| `etn.thoughts.find_duplicates` | **обязателен перед созданием** — поиск дубликатов |
| `etn.thoughts.create/update/delete` | изменение мыслей |
| `etn.links.create/delete` | связи |
| `etn.comments.upsert` | комментарии |
| `etn.properties.set` | значения свойств |
| `etn.export.subgraph` | подграф как Markdown-документ |

## 5. Важное правило: не плодить дубликаты

Перед `etn.thoughts.create` агент **обязан** вызывать
`etn.thoughts.find_duplicates` и переиспользовать существующую мысль при
совпадении имени/синонима.

## 6. Поведение

- Изменения агента проходят те же проверки прав и валидацию, что у людей.
- Участники сети видят изменения агента в реальном времени (WebSocket).
- Каждый изменяющий вызов фиксируется в аудите (`category=data`).
- Лимиты: `max_nodes_per_subgraph` (default 500), `max_writes_per_minute`
  (default 60) — настраиваются администратором.

## 7. Пример: собрать дайджест по теме

1. `etn.thoughts.search { query: "конкуренты", scope: "all" }`
2. `etn.thoughts.subgraph { seed_ids: [топ-5], radius: 2, include_comments: true }`
3. Сгенерировать дайджест в своей LLM.
4. Опционально: `etn.comments.upsert` — сохранить дайджест как хронологический
   комментарий у корневой мысли.
