# Руководство администратора ETN

## 1. Первый запуск

См. [install-server.md](install-server.md). После `etn init` у вас есть
пользователь-администратор и его первичный API-key.

## 2. Пользователи и ключи

Админ-панель → «Пользователи» (доступна только администратору):

- **Добавить пользователя** — username + отображаемое имя (+ опция «администратор»).
  При создании генерируется API-key — он показывается **один раз**. Скопируйте
  кнопкой и передайте пользователю по надёжному каналу.
- **Перевыпустить ключ** — старый ключ продолжает работать до отзыва; отзыв —
  отдельной операцией.
- **Отключить учётку** — пользователь и его ключи перестают действовать.
- **Удалить пользователя** — невозможно, если он владеет хотя бы одной
  мыслесетью (сначала передайте владение).

Ключ нельзя восстановить: хранится только хеш. Формат: `etn_<32 hex>`.

## 3. Мыслесети и доступ

- Пользователь создаёт мыслесеть → становится её **владельцем**.
- Владелец управляет участниками: «Участники сети» → добавить/исключить,
  передать владение.
- **Администратор** видит все сети («Администрирование → Сети»), может сменить
  владельца или удалить любую сеть. Чтение данных чужой сети администратору
  недоступно без участия в ней — это сознательное ограничение приватности.

## 4. Аудит

«Администрирование → Аудит» — журнал операций: входы/отказы auth, изменения
пользователей и ключей, создание/удаление сетей, членство, действия MCP-агентов.
Фильтры: пользователь, сеть, категория, период.

## 5. Резервное копирование и восстановление

- Остановите сервер (или выполните checkpoint) и скопируйте `ETN_DATA_DIR`
  целиком (`_system.db` + `networks/`).
- Для восстановления положите каталог на место и запустите сервер.
- Перенос отдельной сети: скопируйте каталог `networks/<uuid>/` и заведите
  запись в `_system.db` (таблицы `networks`, `network_members`).

## 6. Защита от перебора

Встроенная: 10 неудачных попыток с одного IP в минуту → 429 на 5 минут;
WebSocket — 5 неудачных подключений → бан. События фиксируются в аудите
(`category=auth`).

## 7. MCP-агенты

Включите `ETN_MCP_ENABLED=1` (или выделенный `ETN_MCP_PORT`) для удалённых
агентов; локальные агенты подключаются через `etn mcp --api-key …`. Для агента
рекомендуется отдельный ключ пользователя (при необходимости — read-only).
Подробнее: [mcp-clients.md](mcp-clients.md).
