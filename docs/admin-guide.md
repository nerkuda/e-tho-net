# Руководство администратора ETN

## 1. Первый запуск

См. [install-server.md](install-server.md). После `etn init` у вас есть
пользователь-администратор и его первичный API-key.

## 2. Пользователи и ключи

Админ-панель (меню пользователя → «Администрирование» → «Пользователи»,
доступна только администратору):

- **Добавить пользователя** — username + отображаемое имя (+ опция
  «администратор»). При создании генерируется API-key — он показывается
  **один раз**. Скопируйте кнопкой и передайте пользователю по надёжному
  каналу.
- **(Пере)генерировать ключ** — выпускает новый ключ; старый продолжает
  работать, пока не удалён из списка ключей пользователя (отзыв —
  `DELETE …/keys/{id}`; активные подключения с ключом закрываются).
- **Список ключей пользователя** — только префиксы (полный ключ не хранится).
- **Отключить учётку** — пользователь и его ключи перестают действовать.
- **Удалить пользователя** — невозможно, если он владеет хотя бы одной
  мыслесетью (сначала передайте владение).

Ключ нельзя восстановить: хранится только хеш. Формат: `etn_<32 hex>`.

### 2.1. Ключи для агентов и лимиты записи

Пользователь может выпускать себе дополнительные ключи и сам — REST-ом
(`POST /api/v1/me/keys`; отдельного экрана в клиенте нет). Параметры ключа:

- `label` — метка («desktop», «agent», …);
- `read_only: true` — ключ пропускает только чтение (REST и MCP);
- `max_writes_per_minute` — персональный лимит записи MCP для ключа
  (`null` — серверный дефолт, см. [mcp-clients.md](mcp-clients.md) §1);
  меняется позже через `PATCH /api/v1/me/keys/{id}`.

Для AI-агента рекомендуется отдельный ключ пользователя — при необходимости
  read-only и с собственным лимитом: bulk-импорт получит свой бюджет, не
  ослабляя глобальную защиту от runaway-агента.

## 3. Мыслесети и доступ

- Пользователь создаёт мыслесеть → становится её **владельцем**.
- Владелец управляет участниками (меню «Мыслесеть» → «Участники сети»):
  добавить/исключить, передать владение.
- **Администратор** видит все сети («Администрирование → Сети»), может сменить
  владельца или удалить любую сеть. Чтение данных чужой сети администратору
  недоступно без участия в ней — это сознательное ограничение приватности.

### 3.1. Слои изменений

В сети могут работать **слои** — временные ветки правок (см.
[user-guide-views.md](user-guide-views.md)). Администрирования слоёв нет —
слой создаёт и сливает сам участник. Оператору важно знать:

- при каждом слиянии автоматически создаётся **резервный служебный слой**
  (точка отката) — списки слоёв клиентов его не показывают, но строки этих
  слоёв физически живут в БД сети;
- событие `layer.merged` попадает в аудит (`category=data`);
- заброшенные слои видны по `last_activity_at` (REST `GET …/layers`).

## 4. Аудит

«Администрирование → Аудит» — журнал операций: входы/отказы auth, изменения
пользователей и ключей, создание/удаление сетей, членство, действия
MCP-агентов. Фильтры: пользователь, сеть, категория, период.

## 5. Резервное копирование и восстановление

- Остановите сервер (или выполните checkpoint) и скопируйте `ETN_DATA_DIR`
  целиком: `_system.db` + `networks/<uuid>/` — в каталоге сети лежат
  `data.db` (данные, включая теневые строки слоёв) и `attachments/`
  (загруженные файлы-вложения).
- Для восстановления положите каталог на место и запустите сервер. Миграции
  SQLite применяются автоматически при старте.
- **Перенос отдельной сети на другой сервер** — без доступа к файловой
  системе: экспорт `.etnx` в клиенте (панель выделения → «Действия» →
  «Экспорт» → zip-архив) и импорт на целевом сервере; повторный импорт
  идемпотентен. Альтернатива для оператора — скопировать каталог
  `networks/<uuid>/` и завести запись в `_system.db` (таблицы `networks`,
  `network_members`).

Подробнее о структуре каталога данных и обновлении —
[install-server.md](install-server.md) §7–8.

## 6. Защита от перебора

Встроенная: 10 неудачных попыток с одного IP в минуту → 429 на 5 минут;
WebSocket — 5 неудачных подключений → бан. События фиксируются в аудите
(`category=auth`).

## 7. MCP-агенты

Включите `ETN_MCP_ENABLED=1` (или выделенный `ETN_MCP_PORT`) для удалённых
агентов; локальные агенты подключаются через `etn mcp --api-key …`.
Полный список инструментов (чтение, запись, слои, корзина, дельта-фид
изменений) и правила для агентов — [mcp-clients.md](mcp-clients.md).

Глобальные лимиты MCP (`mcp.max_nodes_per_subgraph`,
`mcp.max_writes_per_minute`) хранятся в настройках `_system.db`; на уровне
ключа лимит записи переопределяется параметром ключа (§2.1).
