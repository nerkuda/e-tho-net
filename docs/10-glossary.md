# 10. Словарь терминов

> Расширен из исходного словаря замысла (`Мой аналог TheBrain.md`) инженерными
> терминами спецификаций. Перви́чные определения сохранены дословно по смыслу.

## Основные сущности

**ETN** — The Endless Thought Network. Название системы. Бесплатный self-hosted
аналог программы TheBrain.

**Thought Network / мыслесеть** — отдельная база данных для мыслей и связей
(физически — отдельный каталог `networks/<id>/` с `data.db`). У пользователя
может быть сколько угодно мыслесетей; каждую можно экспортировать/импортировать/
бэкапить и защищать паролем (последнее — будущее) независимо от других. В
терминологии кода — `network`.

**`.etnx`** — zip-архив переноса графа между мыслесетями (`02-data-model.md` §9,
фаза P). Содержит `manifest.json` со всеми сущностями выбранного подграфа и
опциональный каталог `attachments/` с бинарями. Версия формата хранится в
`manifest.version` (`ETNX_VERSION`).

**Мысль** — обособленная запись, описывающая информацию, слабо зависящую от
времени. Базовая сущность системы. В коде — `thought`.

Признаки:
- может быть актуальной или неактуальной;
- может иметь один тип;
- может иметь синонимы (для поиска и дедупликации);
- может иметь иконку, цвет/стиль;
- имеет заголовок (до 400 символов).

Особый подвид: **корневая мысль** (`is_root=1`) — автоматически создаваемая мысль
«HOME». Она же защищённая (`is_protected=1`): нельзя удалить, можно
переименовать/менять свойства.

**Тип мысли** (`thought_type`) — пользовательский тип, назначаемый мыслям.
Определяет внешний вид по умолчанию (цвет, шрифт, иконку) и набор свойств. По
умолчанию новые мысли не имеют типа. Одна мысль — один тип.

**Свойство типа** (`type_property`) — поле, доступное мыслям определённого типа.
Типы значений: `text`, `date`, `number`, `bool`, `thought_ref` (ссылка на другую
мысль, возможно с ограничением по типу).

**Связь мыслей** (`link`) — направленное отношение между двумя мыслями. Имеет
источник (`source_id`) и назначение (`target_id`), опционально тип. Связь бывает
актуальной/неактуальной. Петли (source=target) запрещены.

**Тип связи** (`link_type`) — пользовательский тип связи. Определяет цвет/стиль
линии и два направленных имени: `name_forward` (от источника к назначению) и
`name_reverse` (обратно). Именно эти имена отображаются как подпись на линии и
как заголовки групп в редакторе.

**Комментарий** (`comment`) — markdown-описание мысли или связи. Двух видов:
- **постоянный** (`kind=permanent`) — один на владельца; не зависит от даты.
- **хронологический** (`kind=chronological`) — много; имеет `valid_from`/`valid_to`
  (по умолчанию обе = сегодня).

**Вложение** (`attachment`) — ссылка на интернет-страницу или файл ОС. Имеет
заголовок и комментарий. На MVP файлы не загружаются на сервер (`kind=file`
хранит путь в ОС клиента).

**Автор** (`created_by`) — пользователь, создавший сущность (мысль, связь,
тип мыслей, тип связей, определение свойства, слой, постоянный или
хронологический комментарий, вложение). Служебная колонка таблицы,
заполняется автоматически при создании; **никогда не меняется** после
создания сущности. У объектов, существовавших до появления
авторства (до версии 0.7.1), автор = первый пользователь сервера.

**Редактор** (`updated_by`) — пользователь, последний раз изменивший
сущность. Служебная колонка таблицы, обновляется при каждой записи.
Пара полей «автор + дата создания» иммутабельна; пара «редактор + дата
изменения» обновляется на каждом коммите. У объектов, существовавших
до появления авторства, редактор = автор = первый пользователь
сервера.

**Дата создания** (`created_at`) и **дата изменения** (`updated_at`) —
служебные временные метки сущности. Хранятся в миллисекундах для
сортировки; пользователю показываются с точностью до секунды в его
часовом поясе.

## Роли

**Администратор системы** (`is_admin=1`) — глобальная роль. Управляет
пользователями и их ключами, любой сетью и её членством, может удалить любую
сеть, читать `audit_log`. Не обязан быть участником сети для управления её
членством, но для чтения данных сети требуется членство.

**Первый пользователь** (`is_first_user=1`) — создаётся командой `etn init`,
неудаляем, всегда `is_admin=1`. Root инсталляции.

**Владелец сети** (`role=owner` в `network_members`) — создатель сети (или тот,
кому передано владение). Полный доступ к данным сети + управление её членством.
Может удалить свою сеть.

**Участник сети** (`role=member`) — полный доступ к данным сети, без отличий от
владельца. Не управляет членством.

## Аутентификация

**API-key** — статичный bearer-токен формата `etn_<32 hex>`. Выдаётся
администратором или самим пользователем. Хранится на сервере только SHA-256
хешем; сам ключ восстановить нельзя. Один пользователь может иметь несколько
ключей (например, отдельный — для MCP-агента).

**Профиль сервера** (`server_profile`) — запись в локальном SQLite клиента с
параметрами подключения: URL сервера, зашифрованный API-key, user_id.

## Архитектурные термины

**Сервер** — Node.js-процесс: REST API, WebSocket-шлюз, MCP-сервер, доменный
слой, слой хранения. Self-hosted, в сети пользователя.

**Клиент** — десктоп-приложение на Electron. Онлайн-only.

**Доменный слой** (domain / core) — бизнес-логика над данными: правила создания/
удаления, валидация, контроль доступа, транзакции, генерация real-time событий.
Общий фасад для REST и MCP.

**`_system.db`** — общесерверная SQLite-БД: пользователи, ключи, реестр сетей,
членство, роли, серверные предпочтения, журнал аудита, буфер событий real-time.

**`data.db`** (на сеть) — SQLite-БД конкретной мыслесети: мысли, синонимы,
связи, типы, свойства, комментарии, вложения, FTS-индексы.

**Pub/sub по network_id** — in-memory `EventEmitter` на сервере, разводящий
real-time-события по подписчикам сети.

**Событие real-time** — JSON-сообщение по WebSocket: `{type, seq, ts, actor,
network_id, data, meta}`. `seq` монотонный, для пропуска/повторной доставки.

**MCP-сервер** — точка подключения внешних AI-агентов к данным ETN по протоколу
Model Context Protocol. Использует тот же доменный слой, что и REST.

## UI-термины

**Холст** — центральная часть GUI с четырьмя зонами: фокус (центр), источники
связей (верх-лево), родственники (верх-право), назначения связей (низ).

**Облачко** — визуальное представление мысли на холсте: иконка, заголовок,
строка индикаторов (постоянный комментарий, хронология, вложения), два эллипса.

**Эллипсы облачка** — индикаторы наличия входящих/исходящих связей (закрашены,
если есть) и одновременно точки drag для создания новых мыслей в соответствующем
направлении.

**Редактор элемента** — боковая/верхняя/нижняя панель с детальным содержимым
выбранной мысли или связи: шапка свойств + сворачиваемые группы (свойства,
вложения, постоянный/хронологический комментарии, связи, упоминания).

**Фокус** — мысль, выбранная в центре холста. Открывается в редакторе по
умолчанию. Запоминается сервером в `thought_views` (последний фокус пользователя
в сети).

**Строка поиска** — поле в toolbar. Активируется `Ctrl+F`, **восстанавливает**
предыдущий запрос (текст + опции + результаты).

**Панель выделения** — левая панель с множественным выбором мыслей для групповых
операций.

**Панель использования** (S13) — отдельная доковая панель слева (на месте панели
выделения или правее неё), открывается при заблокированном удалении. Показывает,
кто ссылается на мысль/связь через свойства и какие слои её удерживают, с
действиями («Очистить свойство», «Удалить слой»). Не путать с пассивной группой
«Использование» во вкладке «Связи» редактора — та же информация, но только для
просмотра, без действий (`08-ui-spec.md` §5a.3, §6.7).

**Корзина** (S13) — диалог со всеми мыслями и связями сети, помеченными на
удаление; открывается пунктом «Корзина» меню «Мыслесеть» (`08-ui-spec.md` §5a.4,
`03-server-api.md` §14b).

**Диалог добавления мыслей** — модальный диалог с живым поиском существующих
мыслей и режимом «одна/несколько». Цель — не дублировать мысли.

## Состояния

**Актуальность** (`active`) — признак мысли/связи. Если признак = false и у
пользователя выключено «показывать неактуальное», сущность скрыта.

**Версия** (`version`) — целое число, монотонно растёт при каждом изменении
сущности. Используется для optimistic concurrency (`If-Match`).

**Черновик** (`draft`) — несохранённое/несохранённое-из-за-обрыва изменение поля
сущности, лежащее в локальном SQLite клиента. Отправляется при восстановлении
связи.

**Конфликт** — ситуация, когда серверная версия сущности опережает клиентскую при
попытке изменения. Для **того же поля** → `409 VERSION_CONFLICT`. Для разных
полей — мирное слияние (last-write-wins per field). С появлением **захвата**
объекта (0.7.1) такие конфликты стали редкими: открытие редактора захватывает
объект, и запись через клиент/REST/MCP блокируется до конца редактирования.
Конфликт остаётся актуальным для сценариев «правка в обход клиента»
(скрипты, race-условия при сетевых сбоях).

**Пометка на удаление** (`marked_for_deletion`, S13) — намерение удалить мысль/
связь при первой возможности; не влияет на существование строки и обратима
(«Вернуть из корзины»). Не путать с **неактуальностью** (`active=false`) —
неактуальность про историю и не подразумевает будущего удаления; пометка на
удаление, наоборот, про мусор, который рано или поздно уберут физически
(`02-data-model.md` §3.1.2).

**Захват** (`lock`, 0.7.1) — мягкая серверная блокировка объекта при
редактировании. Участник, открывший редактор мысли/связи, диалог настроек,
диалог смены типа или диалог удаления, **захватывает** объект за собой;
любая запись этого объекта другими участниками (через клиент, REST и MCP)
отклоняется до завершения редактирования. Чтение при захвате не
блокируется. Снимается автоматически при закрытии редактора, разрыве
WebSocket клиента, рестарте сервера; вручную — командой
«Снять все блокировки» в диалоге «Участники мыслесети» (доступна любому
участнику сети), через REST `…/locks/release_all`, MCP `etn.locks.*`.

**Журнал активности** (`activity_log`, 0.7.1) — таблица сетевых событий
(создание/изменение/удаление/пометка/восстановление мыслей, связей,
типов, свойств, слоёв, комментариев, вложений). Источник рабочего стола
«События». Поля записи: `id`, `user_id` (кто), `action` (что
сделал — `created`/`updated`/`deleted`/`trashed`/`restored`/…),
`entity_type` (`thought`/`link`/`thought_type`/`link_type`/`property`/
`layer`/`comment`/`attachment`), `entity_id` (id сущности, пока она
жива), `entity_title` (краткое описание-снимок, хранится вместо
`entity_id` для удалённых сущностей), `layer_id` (где произошло),
`occurred_at_ms` (когда). **Автоматической ретенции нет**: история
растёт неограниченно, пока её не уменьшат свёрткой или обрезкой.

**Свёртка** (`rollup`, 0.7.1) — операция обслуживания журнала активности
по дате D: для каждой ключевой сущности (мысль, связь со всеми её
свойствами и постоянным комментарием, хроно-комментарий, вложение, тип
мыслей/связей, свойство, слой) из периода до D остаются **только
запись создания и запись последнего изменения** в этом периоде; по
удалённой сущности — единственная запись удаления. Промежуточные
правки удаляются. Свёртка **необратима**. При слиянии слоя в основу
выполняется автоматически.

**Обрезка** (`truncate`, 0.7.1) — операция обслуживания журнала
активности по дате D: все записи до D удаляются **полностью**, включая
создания и удаления. После обрезки за этот период ничего нет.
Обрезка **необратима**.

**Удерживающие ссылки** (S13) — то, что блокирует физическое удаление
(«очистку корзины») помеченной мысли/связи: использование в свойствах
(`thought_ref`) других мыслей и удерживающие теневые строки в слоях изменений
(появляются с версии 0.5.2, [13-layers.md](13-layers.md)). Проверяются
эндпоинтом `deletion-check` (`03-server-api.md` §6.5a).

## Прочее

**Дедупликация мыслей** — проверка при добавлении: живой поиск по `title` и
`synonyms`, предложение использовать существующую мысль вместо создания новой.

**Упоминания** (`mentions`) — мысли и связи, в текстах (комментариях) которых
встречается название или синоним заданной мысли. Реализовано через FTS-поиск по
title+синонимам.

**Серверные предпочтения** (`user_preferences`, в `_system.db`) — настройки
пользователя в сети, влияющие на выборку данных (например, `show_inactive`).

**Локальные UI-state** (`ui_state`, в SQLite клиента) — настройки визуала:
положение редактора, свёрнутые группы, сортировки зон, состояние поиска.

**`etn init`** — CLI-команда первичной инициализации сервера: создаёт `_system.db`
и первого пользователя-администратора, печатает первичный API-key.
