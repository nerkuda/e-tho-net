# Руководство пользователя ETN. Часть 1: основы и карта мыслей

ETN — «цифровой мозг»: граф связанных записей (мыслей) с комментариями,
вложениями и совместной работой в реальном времени.

Руководство состоит из трёх частей:

- **Часть 1 (этот файл)** — базовые понятия, окно программы, карта мыслей,
  поиск, история, закреплённые мысли и совместная работа (авторство,
  захват объектов, лента «События»).
- [Часть 2: редактор, типы, удаление](user-guide-editing.md) — редактор
  мысли/связи, комментарии и wiki-ссылки, типы, корзина.
- [Часть 3: обзоры, слои, обмен](user-guide-views.md) — рабочие столы
  «Структуры», «Хроника» и «События», слои изменений, экспорт/импорт,
  настройки.

Установка: [сервер](install-server.md), [клиент](install-client.md).
Подключение AI-агентов: [mcp-clients.md](mcp-clients.md).

## 1. Базовые понятия

- **Мыслесеть** — отдельная база мыслей и связей (аналог «мозга» в TheBrain).
  В одном окне можно открыть несколько сетей — каждая в своей вкладке (табе).
- **Мысль** — запись: люди, организации, идеи, темы, гипотезы… Всё, что вы
  хотите связать.
- **Связь** — направленное отношение между мыслями («состоит из» → «входит в
  состав»). Имеет имена для обоих направлений.
- **Тип** — шаблон для мыслей и связей: внешний вид (иконка, цвет, стиль) и
  набор свойств. Типы образуют иерархию с наследованием (часть 2, раздел 5).
- **Холст** — экран с мыслью в фокусе и её окружением.
- **Фокус** — мысль в центре холста.
- **Рабочий стол** — режим просмотра сети: **Карта мыслей** (холст),
  **Структуры мыслей** (отбор по критериям + дерево), **Хроника**
  (хронологические комментарии) — часть 3.
- **Слой изменений** — «прозрачная плёнка» поверх сети: правки в слое не видны
  остальным, пока слой не слит в основу (часть 3, раздел 5).
- **Корзина** — двухфазное удаление: пометить сейчас, удалить или вернуть
  позже (часть 2, раздел 6).
- **Закреплённая мысль** — мысль, вынесенная на верхнюю строку приложения для
  быстрого перехода (раздел 9).

## 2. Окно программы

### 2.1. Табы

Вверху окна — лента вкладок: каждая открыта отдельная мыслесеть со своим
контекстом (фокус, вид, слой, фильтры). Одна сеть может быть открыта в
нескольких табах — состояния независимы.

- **«+»** — открыть экран списка сетей (выбрать существующую или создать
  новую).
- Табы перетаскиваются для изменения порядка; не вместившиеся — в списке
  `▾ N`.
- `*` в заголовке таба — пришли изменения по этой сети (не от вас); снимается
  при активации таба.
- Сеть без доступа (например, вас исключили) — блеклый таб; активация
  показывает заглушку «Нет доступа к сети».
- Закрытие последнего таба возвращает на экран списка сетей.

### 2.2. Верхняя строка и панель инструментов

Слева направо:

- **`[👤 Пользователь ▾]`** — «Открыть сеть», «Создать сеть»,
  «Администрирование» (только для администратора; см.
  [admin-guide.md](admin-guide.md)), «О программе» (версия, сервер, ссылки),
  «Отключиться».
- **Табы** (см. выше).
- **`[🌐 Мыслесеть ▾]`** — команды текущей сети: «Участники сети» (владелец),
  «Выйти из сети», «Типы мыслей», «Типы связей», «Корзина (N)», «Настройки
  мыслесети».
- **`[▤ Основа ▾]`** — меню слоёв изменений: заголовок меню — имя текущего
  слоя; список слоёв, создание, отличия, слияние, удаление (часть 3,
  раздел 4).
- **Переключатель рабочих столов** — «Карта мыслей» / «Структуры мыслей» /
  «Хроника» / «События» (часть 3).
- **Панель закреплённых мыслей** — во всю свободную ширину (раздел 9).
- **`[☰ Вид]`** — «Показать/Скрыть редактор», «Все настройки» (единый диалог
  настроек — часть 3, раздел 6).

### 2.3. Статус-бар (нижняя строка)

- Индикатор соединения: 🟢 подключено, 🟡 переподключение, 🔴 нет связи.
- Индикатор масштаба карты.
- Область сообщений о событиях (ширину можно тянуть разделителем).
- История посещения мыслей: облачка последних открытых мыслей + полный
  список в меню `▾` (раздел 8).

## 3. Рабочие столы

Три кнопки-иконки переключают рабочие столы (панель редактора, выделение и
статус-бар остаются общими):

- **Карта мыслей** — холст с фокусом (этот файл, разделы 4–7).
- **Структуры мыслей** — отбор мыслей по критериям (ключевые слова с `*` и
  `-`, типы, свойства, типы связей, автор/редактор) и дерево результатов —
  [часть 3, раздел 1](user-guide-views.md).
- **Хроника** — таблица всех хронологических комментариев с привязками к
  мыслям и связям, с колонками «Автор» и «Редактор» —
  [часть 3, раздел 2](user-guide-views.md).
- **События** — лента сетевых событий «кто что сделал»: создано,
  изменено, удалено, помечено в корзину и т.п.; фильтры по периоду,
  участнику и типу сущности — [часть 3, раздел 3](user-guide-views.md)
  и подробности о захвате/авторстве — [раздел 12 ниже](#12-совместная-работа).

## 4. Карта мыслей

Холст делится на зоны:

| Зона | Что показывает |
|------|----------------|
| Центр | мысль в фокусе |
| Верх слева | источники связей (родители) |
| Верх справа | родственные мысли (те же родители) |
| Низ | назначения связей (дети) |

- **Клик по мысли** → открывает её в редакторе (ореол вокруг облачка).
- **Двойной клик по мысли** → она становится фокусом.
- **Двойной клик по пустому месту зоны** «Верх слева»/«Низ» открывает диалог
  добавления родительской/дочерней мысли (к фокусу). В зоне «Верх справа»
  добавления нет: у фокуса может быть несколько родителей.
- **Прокрутка** в зоне — вертикальная; на полосе виден диапазон `12–36`.
- **Меню зоны:** правый клик по зоне → «Добавить мысль» (для «Верх слева» и
  «Низ» — как клик по пустому месту) и сортировка (алфавит, дата создания,
  дата просмотра, ручной).
- **Раскладка в зоне** — построчно (row-major): первая мысль в левом-верхнем
  углу, последняя — в правом-нижнем.
- **Индикаторы облачка:** 📝 — есть постоянный комментарий, 📅 — есть
  хронологические записи, 📎 — есть вложения; значок корзины и бледность —
  помечена на удаление; пунктирная рамка с бейджем слоя — мысль перекрыта
  текущим слоем. Наведение с `Ctrl` показывает содержимое индикаторов без
  открытия редактора (раздел 6).
- **Связь:** клик по линии открывает связь в редакторе; hover эллипса
  подсвечивает все его связи.

### 4.1. Перетаскивание мыслей

- **Обычное перетаскивание** облачка на другую мысль создаёт связь (на
  верхний эллипс — A→Б, на тело — Б→A), в соседнюю зону — перемещает мысль
  между родителями и детьми фокуса.
- **`Ctrl`+перетаскивание** на мысль — сделать её единственным родителем
  перетаскиваемой (не копия).
- **`Ctrl`+`Shift`+перетаскивание** (при «ручном» порядке) — поставить перед
  мыслью: место вставки показывается зазором, облачка раздвигаются и после
  броска плавно переезжают.
- **Эллипсы** облачка: потянуть за **верхний эллипс** — создать родителя,
  за **нижний** — создать ребёнка (открывается диалог добавления).

### 4.2. Ручной порядок в зоне

При сортировке «ручной» порядок задаётся перетаскиванием с зажатыми
`Ctrl`+`Shift` (раздел 4.1) или клавишами `Ctrl`+`Shift`+`↑/↓`. Направление
всегда «сверху вниз по порядку зоны». В правом нижнем углу облачка выводится
порядковый номер (1-based), обновляется при изменениях состава зоны; новые
мысли номер не получают — до явного переставления.

### 4.3. Клавиатурная навигация по карте

Пока фокус клавиатуры на холсте (клик по нему):

- **Стрелки** — двигают курсорную рамку (пунктир) к ближайшему облачку в
  направлении стрелки; зона при необходимости прокручивается.
- **`Tab` / `Shift+Tab`** — как стрелки `→` / `←`.
- **`Home` / `End`** — первое/последнее облачко зоны (с фокуса — край первой
  / последней непустой зоны).
- **`Enter`** — открыть мысль курсора в редакторе.
- **`Ctrl+Enter`** — перевести мысль курсора в фокус.
- **`Ctrl+Shift+←` / `Ctrl+Shift+→`** — переместить мысль курсора в ручном
  порядке (только зоны «верх-лево» и «низ» при сортировке «ручной»).
- **`Escape`** — снять рамку курсора.

## 5. Добавление мыслей

1. Правый клик по мысли → «Добавить вниз/вверх/налево» — или потяните за
   **верхний эллипс** (создать родителя) / **нижний эллипс** (создать ребёнка)
   облачка — или дважды кликните по пустому месту зоны «Верх слева»
   (родитель) / «Низ» (ребёнок) — или правый клик по этим зонам →
   «Добавить мысль».
2. В диалоге начните вводить название — ETN **ищет существующие мысли** (по
   имени и синонимам), чтобы не плодить дубликаты. Выберите найденную или
   создайте новую. UUID в поле ввода ищет мысль по ID напрямую.
3. Синонимы вводятся через `|`: `Иванов Иван | Ваня, Иваныч`.
   В синониме можно использовать подстановки `*` — «любое количество любых
   символов в пределах одного слова»: синоним `Игорян*` найдёт мысль при вводе
   `Игорянский`, а `Петров* Игор*` — при вводе `Петрова Игоря` (но не
   `Петрович передал Игорю`).
4. Для нескольких мыслей: включите режим «несколько», вводите по одной (Enter),
   в конце `Ctrl+Enter`. Можно вставить многострочный текст — каждая строка
   станет мыслью. `Ctrl+Shift+Enter` — вставить всё и сразу открыть первую из
   добавленных мыслей в фокусе.
5. **Быстрое создание типа:** если в поле типа совпадений нет, список
   предлагает «Создать новый „…“» — откроется диалог создания типа с
   предзаполненным именем (часть 2, раздел 5).
6. Перетаскивание ссылки/файла из браузера в верх-лево или низ холста создаёт
   мысль с вложением; файл при этом загружается на сервер (часть 2,
   раздел 3).

## 6. Предпросмотр содержимого (Ctrl+наведение)

Наведение курсора с зажатым `Ctrl` — на индикаторы 📝/📅/📎 облачка или
подсказки связи — раскрывает содержимое во всплывающем окне рядом, без
открытия редактора:

- 📝 — постоянный комментарий;
- 📅 — список хроно-записей (заголовок, даты, краткое начало; новые сверху);
- 📎 — список вложений;
- **ссылки в комментариях**: на мысль — её постоянный комментарий, на мысль из
  другой мыслесети — имя сети, на файл — содержимое (картинка или текст),
  прочие URL — полный адрес;
- **эллипсы облачка** — списки входящих/исходящих связей; клик по мысли в
  списке открывает её в редакторе, двойной — переводит в фокус.

В окно можно перевести курсор (не закрывается 0,3 с после ухода), содержимое
прокручивается, предпросмотры вкладываются друг в друга до 5 уровней. Каждое
окно закрывается само, когда курсор уходит из его границ; `Esc` закрывает
самое верхнее. Работает на всех экранах и во всех списках: карта, структуры,
хроника, поиск, история, закрепления, панель выделения, вкладка «Связи».

## 7. Поиск

`Ctrl+F` — строка поиска на карте мыслей (под верхней строкой программы);
восстанавливает предыдущий запрос. Результаты по группам: имена / тексты /
связи / хронология. UUID-запрос ищет мысль по ID напрямую.

Шестерёнка — фильтры: поиск только в подчинённых мыслях, типы мыслей/связей,
показывать неактуальное, показывать помеченные на удаление (по умолчанию
помеченные скрыты и в поиске, и в «Структурах»).

## 8. История посещения мыслей

Единая история для всех рабочих столов (карта, структуры, хроника):
записывается каждое открытие мысли в редакторе. В статус-баре — облачка
последних мыслей; меню `▾` — полный список (глубина 50). Клик возвращает к
прежней мысли. Меню «Журнал» → «История» — та же история в виде списка.

## 9. Закреплённые мысли

На верхней строке приложения, справа от кнопок рабочих столов, — панель
закреплённых мыслей: чипы с иконками в одну строку; не поместившиеся — в
списке `▾ N`.

- **Закрепить/открепить** — правый клик по мысли в любом месте (холст,
  структуры, история, выделение) → «Закрепить мысль»/«Открепить мысль».
  Можно просто перетащить мысль на панель — панель подсветится рамкой, а
  вертикальная метка покажет место вставки; перетаскивание между чипами
  меняет порядок. Вынос чипа на холст не открепляет мысль.
- **Переход** — клик по чипу: на карте мыслей — фокус и редактор, в
  структурах — мысль открывается в редакторе (и подсвечивается, если есть
  в результатах отбора).
- **Лимит** — не более 20 закреплённых; сверх лимита программа попросит
  сначала открепить лишние.
- Закреплённые хранятся на сервере — на всех ваших компьютерах список один.
  Неактуальные мысли скрываются/показываются вместе с настройкой видимости
  (часть 3, раздел 6).

## 10. Копирование и вставка мыслей

- **`Ctrl+C`** — копирует одну мысль: под курсорной рамкой на карте, а без
  рамки — открытую в редакторе. Панель выделения на `Ctrl+C` не влияет.
  Если в этот момент выделен текст (просмотр комментария) — копируется текст.
- **«Скопировать мысли»** (меню «Действия» панели выделения) — копирует
  несколько мыслей вместе со связями между ними.
- **`Ctrl+V`** на карте — вставка под мыслью курсорной рамки (или фокуса):
  создаётся копия с новым `id`; связи внутри скопированного набора
  сохраняются, родителем становится цель — только у «корня» подграфа.
- **Между сетями**: копирование работает и через табы в одно окно, и в
  разные окна. Типы и свойства-ссылки резолвятся в сети-получателе по `id`,
  затем по имени; не найденное сбрасывается. Wiki-ссылки автоматически
  переписываются в кросс-сетевую форму `[[n:<сеть>#<id>]]`.
- В системный буфер при копировании попадает только текст wiki-ссылок
  (`[[#<id>]]`) — содержимое мыслей наружу не утекает; когда системный буфер
  перезаписан другой программой, вставка из ETN больше не срабатывает.
- `Ctrl+V` в поле ввода диалога добавления: UUID → поиск и связь; строка
  `Имя | синонимы` → новая мысль; многострочный текст → по мысли на строку.

## 11. Горячие клавиши

| Клавиша | Действие |
|---------|----------|
| `Ctrl+F` | поиск (на карте мыслей) |
| `Ctrl+клик` | добавить/убрать мысль из выделения |
| `Ctrl+клик` по эллипсу | выделить всех родителей/детей |
| `Ctrl+наведение` | предпросмотр содержимого (раздел 6) |
| `Ctrl+C` / `Ctrl+V` | копировать/вставить мысль (раздел 10) |
| `Enter` | на карте — открыть мысль курсора в редакторе |
| `Ctrl+Enter` | на карте — фокус на мысль курсора; в диалогах — подтвердить; в «Хронике» — применить отбор |
| Стрелки, `Home`/`End`, `Tab` | навигация по карте (раздел 4.3) и таблицам |
| `Ctrl+Shift+↑/↓`, `Ctrl+Shift+←/→` | ручной порядок в зоне (раздел 4.2) |
| `Ctrl+колесо` над markdown-полем | масштаб документов |
| `Escape` | закрыть верхний диалог / снять выделение / снять рамку курсора |

## 12. Совместная работа

В ETN над одной мыслесетью работают несколько человек и AI-агентов
одновременно. Версия **0.7.1** добавила три связанных механизма, которые
делают совместную работу осмысленной: **авторство** (видно, кто создал и
кто последний менял), **захват объектов** (защита от перезаписи), и
**ленту «События»** (видно, кто что делал). Этот раздел — главный
справочник по ним.

### 12.1. Авторство

У каждой мысли, связи, типа мыслей, типа связей, определения свойства,
слоя, постоянного и хронологического комментария и вложения ETN хранит
четыре служебных поля:

- **Автор** — пользователь, создавший сущность (никогда не меняется).
- **Редактор** — пользователь, последний раз изменивший сущность.
- **Дата создания** — когда сущность появилась.
- **Дата изменения** — когда сущность правили последний раз.

Время хранится в миллисекундах, показывается с точностью до секунды в
вашем часовом поясе. Авторство и редакторство есть у **любой**
сущности — независимо от её типа.

**Где это видно:**

- **Вкладка «Метаданные»** в редакторе мысли/связи и в диалогах
  редактирования типов мыслей/связей и определений свойств — отдельная
  вкладка, всегда последняя. Помимо автора, редактора и дат там же
  показан **id сущности** (кнопка «Копировать ID»). Подробнее —
  [часть 2, раздел 1](user-guide-editing.md).
- **Колонки «Автор» и «Редактор»** в таблицах рабочих столов «Хроника» и
  «События». Подробнее —
  [часть 3, разделы 2 и 3](user-guide-views.md).
- **Фильтры «Автор» / «Редактор»** в панели поиска карты мыслей, в
  отборах «Структур мыслей» и «Хроники» — выпадающий список участников
  сети (см. ниже).

> У объектов, созданных до версии 0.7.1, автор и редактор одинаковы и
> равны первому пользователю сервера — это сознательный backfill, чтобы
> «неизвестных авторов» в системе не было.

### 12.2. Захват объектов

Когда вы открываете редактор мысли, диалог её настроек, диалог смены
типа или диалог удаления — ETN **захватывает** объект за вами. Пока вы
редактируете, никто другой **не сможет записать этот объект**: ни через
другой клиент, ни через REST, ни через MCP. Чтение при этом не
блокируется никогда — все по-прежнему видят текущее состояние.

**Что блокируется:** любая запись в этот объект — `update`,
`upsert_bundle`, смена типа, удаление, изменение свойств, постоянного
комментария, изменение активности. Запись вернётся ошибкой
`409 LOCK_HELD` с указанием, кто сейчас держит захват.

**Как выглядит у соседа:** в редакторе у соседа на шапке объекта
появляется значок **🔒** и подсказка с именем текущего редактора. В
статус-баре — уведомление «Объект редактируется таким-то». Сосед по-
прежнему может открыть объект в режиме чтения, перейти по ссылкам и
отменить своё редактирование — но сохранить свои изменения не даст.

**Когда захват снимается автоматически:**

- вы закрыли редактор или диалог (кнопка «Отмена», `Esc`, клик мимо);
- вы сохранили изменения — захват снимается сразу после записи;
- **разрыв WebSocket** между клиентом и сервером — сервер сбрасывает
  все захваты отвалившегося клиента и шлёт участникам событие
  real-time;
- **рестарт сервера** — сбрасываются вообще все захваты (в памяти
  процесса их нет, и при старте никто не числится редактирующим).

**Ручной сброс — «Снять все блокировки»:** если участник отошёл от
компьютера, не закрыв редактор, и его WebSocket ещё держится — любой
другой участник сети может снять его блокировки:

- Меню `[🌐 Мыслесеть ▾]` → «Участники мыслесети» → строка участника →
  «Снять все блокировки».
- Команда отправит всем участникам событие real-time, и значок 🔒
  исчезнет.

> В AI-агенте та же операция доступна через MCP `etn.locks.release_all`
> (см. [mcp-clients.md](mcp-clients.md) §4).

#### Короткий сценарий

> Вы с коллегой правите одну мысль. Вы открыли редактор — у коллеги на
> облачке появился 🔒. Коллега не может сохранить свои правки и видит
> «объект редактируется вами». Вы сохранили — 🔒 исчез, коллега теперь
> может открыть редактор сам.

### 12.3. Вкладка «Метаданные»

Во всех редакторах (мысль, связь) и диалогах редактирования типов мыслей
и связей, а также определений свойств, появилась вкладка **«Метаданные»**
— обычно последняя. Она показывает:

- **id сущности** с кнопкой «Копировать ID» (в шапке редактора раньше
  был виден короткий id — теперь он переехал сюда);
- **Автор** — пользователь, создавший объект;
- **Редактор** — пользователь, последний менявший объект;
- **Дата создания** и **Дата изменения** в формате `ГГГГ-ММ-ДД ЧЧ:ММ:СС`
  в часовом поясе клиента.

Эти поля служебные и не правятся напрямую — они обновляются системой
при операциях записи. Если объект редактируется другим участником,
вкладка покажет значок 🔒 и имя текущего редактора.

### 12.4. Вид «События»

Новый рабочий стол **«События»** — лента «кто что сделал» в сети.
Источник — таблица `activity_log` сервера. Здесь видны все значимые
действия участников: создано, изменено, удалено, восстановлено,
помечено в корзину, снято с корзины…

**Панель отбора** (сверху):

- **Период** — «с / по» с точностью до секунды; удобно сузить ленту до
  нужного дня/часа.
- **Участник** — выпадающий список участников сети; пусто = «все».
- **Тип сущности** — мысль, связь, тип мыслей, тип связей, свойство,
  слой, комментарий, вложение; пусто = «все».
- «Применить» (`Ctrl+Enter`), «Очистить отбор», «Сохранить отбор» /
  «Удалить отбор» — сохранённые отборы, как в «Хронике» и «Структурах».

**Таблица**: колонки «Когда» | «Кто» | «Действие» | «Что» | «Где».
Навигация стрелками, `Enter` открывает сущность в редакторе (если она
ещё жива) или показывает карточку удалённой сущности по её краткому
описанию. Пагинация по 50 строк.

**Удалённые сущности** в ленте не «исчезают»: вместо ссылки на объект —
его краткое описание-снимок вида «мысль без типа, „Название“» или
«связь A → B». Снимок хранится прямо в записи активности — поэтому
история остаётся читаемой и после удаления.

> Меток чтения/просмотра в «Событиях» нет — это поток действий, а не
> лента новостей.

### 12.5. Свёртка и обрезка журнала активности

Журнал активности `activity_log` **не имеет автоматической ретенции** —
он растёт неограниченно, пока вы не управляете его размером вручную.
Это сознательное решение: история ценна, и её нельзя потерять по
таймеру. Размер управляется двумя операциями обслуживания, доступными
через меню **«Журнал»** рабочего стола «События» (то же — REST
`/activity/rollup`, `/activity/truncate`, MCP `etn.activity.*`).

> Обе операции **необратимы**. Перед запуском сервер попросит подтвердить
> дату «до которой» и покажет оценку числа затронутых записей.

**Свёртка** (rollup, «Свернуть до даты»): по каждой ключевой сущности
(мысли, связи с их свойствами и комментариями, хроно-комментарии,
вложения, типы мыслей/связей, свойства, слои) из всего периода до даты
D остаются **только запись создания и запись последнего изменения в
периоде**; по удалённой сущности — единственная запись удаления («что,
кто, когда»). Все промежуточные правки исчезают. Получается компактная
история «кто что сделал», без шума.

**Обрезка** (truncate, «Обрезать до даты»): все записи до даты D
удаляются **полностью**, включая создания и удаления. После обрезки в
«Событиях» за этот период просто ничего нет.

**Когда что использовать:**

- свёртка — когда хочется сохранить итог по сущностям, но «замести
  мусор» промежуточных правок;
- обрезка — когда старый период больше не интересует в принципе и
  нужно уменьшить размер БД.

> При **слиянии слоя** в основу свёртка выполняется автоматически: по
> каждой затронутой сущности в основе появляется ровно одна итоговая
> запись с автором и временем исходного итогового события слоя;
> детальные события слоя удаляются вместе со слоем. Удаление слоя без
> слияния удаляет его события так же — без свёртки.

### 12.6. Фильтры «Автор» и «Редактор»

В трёх местах можно быстро отобрать объекты по тому, кто их создал или
кто их последний раз менял:

- **Панель поиска карты мыслей** (`Ctrl+F`) — в шестерёнке фильтров
  поле «Автор» / «Редактор»: выпадающий список участников сети; пусто
  = «не фильтровать».
- **«Структуры мыслей»** — в панели отбора среди прочих фильтров.
- **«Хроника»** — в панели отбора среди прочих фильтров.

Фильтры действуют в комбинации с другими: например, «все мысли,
созданные Алисой за последний месяц, типа „проект“» — это ключевые
слова + Автор + период + тип мысли.

### 12.7. Запрет удаления пользователя-автора

Если у пользователя есть хотя бы одна сущность, где он указан как автор
или редактор, **физическое удаление этого пользователя невозможно**.
Администратор получит ошибку `422 VALIDATION_ERROR` со списком
блокирующих сущностей.

Порядок действий администратора:

1. Проверить список блокирующих сущностей.
2. Решить судьбу авторства (как правило — передать другому пользователю
   через прямые правки нужных колонок в БД или через массовый
   `etn.usage_clear` / `etn.thoughts.update` с явным указанием нового
   автора; штатного UI-переноса авторства нет — это редкая операция).
3. Повторить удаление.

Пометка на удаление пользователя (отзыв всех ключей, лишение членства в
сетях) — **доступна**, как и раньше. Это полезно, если нужно «вывести
из оборота» пользователя, не теряя историю авторства.

Подробности и сама команда удаления — [admin-guide.md](admin-guide.md) §2.
